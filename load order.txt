STILL WATERS — MASTER LOAD ORDER (ALL SUBSYSTEMS)
================================================================================

Subsystems covered:
  - js/core/*                 (constants, utilities, state, UI primitives)
  - js/core/rank/*            (rank subsystem)
  - js/modules/names/*        (name subsystem)
  - js/character/*            (character, family, children, mortality)
  - js/location/*             (location)
  - js/selectors/*            (selectors)
  - js/settlement/*           (settlement)
  - js/systems/roles/*        (role subsystem)
  - js/systems/government/*   (government)
  - js/religion/*             (religion)
  - js/culture/*              (culture)
  - js/skill/*                (skill taxonomy)
  - js/households/*, js/industry/*, js/crime/*, js/education/*,
    js/events/*, js/social/*, js/relationships/*  (only where another
    subsystem requires them)

Notation:

  file.js
      a script load.
  call()
      a function invocation (not a script load).
  <- AFTER: file.js            (HARD)
      mandatory load-time dependency: this file's guard throws if
      file.js is not already loaded.
  <- after: file.js            (call-time)
      strong recommendation: the file loads without it, but a
      function throws or degrades when it is missing.
  <- after: file.js            (soft)
      optional dependency with a documented fallback.
  OPTIONAL block
      may be skipped if the corresponding features are not used.
  [UNVERIFIED]
      referenced but not in the supplied batch; confirm exports.
  [NOT PROVIDED]
      referenced by a header or REQUIRED list but not in the supplied
      files.
  [LOAD-ORDER-CRITICAL]
      a specific ordering constraint whose violation produces
      non-obvious failure (e.g. stack overflow, silent clobbering,
      double aliasing).

Reading rule: never reorder two lines within a block unless the
block says "order within this block is unimportant". Every
"<- AFTER: (HARD)" note is mandatory. Every "<- after: (call-time)"
is a strong recommendation for a functioning page.

settlement blocks because:

BLOCK 49 — KNOWN HAZARDS (CROSS-SUBSYSTEM)
==============================================================================

  1.  getCurrentYear vs getCurrentYearSafe. Name, Rank, Role,
      Culture, Religion, Settlement, Character, Location all use
      getCurrentYear. Only Government uses getCurrentYearSafe.

  2.  window.PlaceQueries is [UNVERIFIED]. Three consumers:
      settlement, government's PlaceQueries presence check, and
      culture. Culture's LOAD-TIME guards are the strictest.

  3.  js/core/names.js vs js/modules/names/name-system.js
      potential alias collision.
      js/core/names.js is the CORE names module (getRandomNameFromCountry,
      getRandomSurnameFromCountry, etc. at the core level).
      js/modules/names/name-system.js is the NAME SUBSYSTEM
      compatibility shim that aliases the same names to NameQueries
      functions. If both load, the LATER one wins. Verify the
      load order and the alias winner before deploying. See the
      name subsystem doc PART 7 §3.

  4.  role-system.js [LOAD-ORDER-CRITICAL] after role-queries.js.
      role-queries.js captures window.getRoles at load time. If
      role-system.js loads FIRST, calls to getRoles recurse to
      stack overflow.

  5.  name-queries.js is NOT stack-overflow-sensitive to
      name-system.js load order. Unlike role-queries.js, it does
      not capture the shim-aliased names. It uses
      window.getNameLists and window.pickRandom directly, which
      the shim does NOT alias.

  6.  Rank subsystem internal hazards. See BLOCK 18 notes and
      rank-doc-companion PART 7. Top items: modals-rank.js inline
      styles; hierarchy data-depth CSS rules must ship;
      getNextRankNumber 3-arg signature; rank-bootstrap
      REQUIRED vs OPTIONAL split; death / delete cascade calls
      RankIssues.handleCharacterDeath / removeAllReferencesTo
      DIRECTLY.

  7.  Role subsystem internal hazards. See BLOCK 19 notes. Top
      items: role-system.js [LOAD-ORDER-CRITICAL]; read aliases
      return CLONES (one-shot console.warn on first
      window.getAllRoles); window.getRoleById reconciliation
      (aliased to RoleState.getRole = clones); RoleState.reset()
      only clears ephemeral UI; NameState.reload does NOT mark
      dirty; modals-roles.js projection contract.

  8.  Name subsystem internal hazards. See BLOCK 17 notes. Top
      items: NameCommands.recordSurnameChange DOES NOT SAVE —
      caller must persist once; modals-name.js uses its local
      _renderError (5-sec auto-clear) not _showToast;
      modals-name.js requires a `.modal-body` element for
      in-place refresh; NamesState.clearAllCaches() must be
      called on masterData reload; getCurrentYearSafe NOT used
      by name-commands.js (only getCurrentYear).

  9.  Culture subsystem internal hazards. See BLOCK 22 notes and
      culture-docs PART 7. Top items: window.PlaceQueries
      provider [UNVERIFIED]; window.Culture is created by
      init(), not at script load; CultureBootstrap auto-init
      catches throw; culture-modals.js onConfirm uses
      document.getElementById not root.querySelector (stacked
      modals collide).

  10. Character-creation persistence contract.
      NameCommands.recordSurnameChange no longer saves. If
      character-creation-commands.js was relying on the OLD
      auto-save, character creation now persists ZERO times.
      Verify character-creation-commands.js explicitly calls
      NameCommands.persist() at the end of its batch. This is
      the single integration point outside the name module that
      the save-contract change can break.

  11. Children birth persistence contract.
      Same as HAZARD 10. The newborn surname write
      (recordBirthSurname / recordSurnameChange) no longer
      auto-saves. children-commands.js must persist once at the
      end of the birth batch, or the caller must.

  12. Cross-domain state modules. household-state.js,
      role-state.js (from js/roles/), ranks/rank-state.js (from
      js/ranks/), names/name-state.js (from js/names/),
      core/state/location-ui-state.js are only required by
      state.js, not by any of the character / location /
      settlement / government / religion / rank / culture / role

      - SettlementCommandCommit throws on persist failure.

      - RankCommands.persist returns { success, reason? } and
