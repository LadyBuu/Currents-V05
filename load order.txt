STILL WATERS — MASTER LOAD ORDER (ALL SUBSYSTEMS)
================================================================================

Subsystems covered:
  - js/core/*                (constants, utilities, state, UI primitives)
  - js/core/rank/*           (rank subsystem)
  - js/character/*           (character, family, children, mortality)
  - js/location/*            (location)
  - js/selectors/*           (selectors)
  - js/settlement/*          (settlement)
  - js/systems/government/*  (government)
  - js/religion/*            (religion)
  - js/households/*, js/industry/*, js/roles/*, js/crime/*,
    js/culture/*, js/education/*, js/events/*, js/relationships/*,
    js/social/*   (only where another subsystem requires them)

Notation:

  file.js
      a script load.
  call()
      a function invocation (not a script load).
  <- AFTER: file.js            (HARD)
      mandatory load-time dependency: this file's guard throws if
      file.js is not already loaded.
  <- after: file.js            (call-time)
      strong recommendation: the file loads without it, but a
      function throws or degrades when it is missing. Order to
      avoid first-use failures.
  <- after: file.js            (soft)
      optional dependency with a documented fallback. Ordering is
      optional but recommended.
  OPTIONAL block
      may be skipped if the corresponding features are not used.
  [UNVERIFIED]
      referenced but not in the supplied batch; confirm exports.
  [NOT PROVIDED]
      referenced by a header or REQUIRED list but not in the
      supplied files.

Reading rule: never reorder two lines within a block unless the
block says "order within this block is unimportant". Every
"<- AFTER: (HARD)" note is mandatory. Every "<- after: (call-time)"
is a strong recommendation for a functioning page.

location, and UI blocks because:

BLOCK 45 — KNOWN HAZARDS (CROSS-SUBSYSTEM)
==============================================================================

  1.  getCurrentYear vs getCurrentYearSafe.
      Core, character, location, settlement, religion, RANK:
      getCurrentYear.
      Government: getCurrentYearSafe (deprecated alias).
      Do not unify without updating every Government call site
      and government-docs.txt §18.

  2.  window.PlaceQueries.
      Referenced by the settlement subsystem; [UNVERIFIED]
      provider. Religion and Government use LocationQueries /
      accessors.getPlaceById instead. If PlaceQueries is absent,
      the settlement factory, settlement view models, and
      settlement modals throw on first call.

  3.  IndustryQueries and RoleQueries are hard load-time
      dependencies of government-queries.js. [UNVERIFIED] —
      confirm their prerequisites and that they load before
      government-queries.js.

  4.  Rank subsystem internal hazards.
      The rank subsystem has its own KNOWN HAZARDS list; see
      rank-doc.md §17 and the rank-doc-companion (this document's
      companion rank subsystem doc, PART 7). The top items:
        - modals-rank.js inline styles (deferred)
        - hierarchy data-depth CSS rules must ship with
          rank-ui-list.js
        - getNextRankNumber 3-arg signature (5-arg callers are
          latent bugs)
        - rank-bootstrap.js REQUIRED vs OPTIONAL split: RomanceQueries
          is OPTIONAL, FamilyQueries is REQUIRED
        - the character death / delete cascade calls
          RankIssues.handleCharacterDeath and
          RankIssues.removeAllReferencesTo DIRECTLY (typeof-guarded)

  5.  Cross-domain state modules.
      js/households/household-state.js, js/roles/role-state.js,
      js/ranks/rank-state.js (NOT js/core/rank/rank-state.js),
      js/names/name-state.js, js/core/state/location-ui-state.js
      are only required by state.js, not by any of the character /
      location / settlement / government / religion / rank
      modules in this batch. Load them only if the state facade
      is used.

  6.  Government uses getCurrentYearSafe.
      Religion, settlement, character, location, RANK use
      getCurrentYear. Do not add getCurrentYearSafe calls to any
      non-Government module.

  7.  Deprecated government files.
      government-system.js, government-assignment.js,
      government-laws.js must not be loaded.

  8.  LocationCommands throw/boolean contract.
      GovernmentCommands._wrapLocationResult handles both.

  9.  Persistence divergence.
      SettlementCommandCommit throws on persist failure.
      GovernmentCommands.persist returns { success: false } but
      does not throw.
      ReligionCommands.persist returns { success, reason? } (does
      not throw).
      RankCommands.persist returns { success, reason? } using
      Pattern A (reads getLastSaveError().message on false; does
      not throw).
      Do not unify without updating every caller's
      error-handling.

  10. Year-transition integration.
      settlement-annual-processor.js must load BEFORE
      character-lifecycle.js so advanceMortality's settlement
      step actually runs. rank-issues.js must load BEFORE
      character-lifecycle.js so handleCharacterDeath is callable.
      Both constraints are satisfied by the documented order
      (BLOCK 16 and BLOCK 23 precede BLOCK 34).

  11. window.PlaceQueries and window.LocationQueries.
      Government uses LocationQueries.getPlaceSummary;
      Settlement uses window.PlaceQueries (or the LocationQueries
      adapter). Both surfaces must exist.

  12. Family queries load before modals-char-selector.js and
      selector-base.js at call time.

  13. relationship-queries.js (RomanceQueries provider) load
      before modals-char-selector.js and selector-base.js
      (call-time, soft). Also before rank-queries.js,
      rank-assignment.js, rank-issues.js (call-time, soft — the
      rank subsystem degrades gracefully without it per its
      OPTIONAL contract).

  14. religion-queries.js load before settlement-religion-queries.js
      and settlement-crime-queries.js (call-time, soft).

  15. culture-queries.js load before location-commands.js,
      location-view-models.js, character-generator.js
      (call-time, soft).

  16. education-queries.js load before settlement-education-queries.js
      (call-time, optional).

  17. LAW ENUM SOURCE.
      religion-commands.js and religion-validation.js read the
      canonical namespaced source (SettlementLawDefinitions.*,
      CrimeConstants.CRIME_TYPES). They do NOT read flat
      window.LAW_* globals. Missing source → "enum not loaded" in
      validation, not "invalid value".

  18. MODAL CLOSE CONTRACT (religion).
      modals-religion.js's onConfirm handlers RETURN the boolean
      from _handleCommandResult. Do not call closeTopModal() from
      within the success path — that caused a double-close.

  19. CALLBACK ORDERING (religion).
      onSuccess fires BEFORE the modal closes.

  20. Character projections.
      religion-queries.js returns character-domain projections,
      not live records. rank-queries.js likewise reads character
      projections via CharacterState.getCharacter. Do not mutate
      either.

  21. getFollowers returns [] for unknown religion id, not null.
      Only getReligion(id) returns null for unknown id.

  22. _resolveCurrentLocationId.
      religion-queries.js prefers
      LocationQueries.getCurrentLocationId (semantic). Falls back
      to CharacterQueries.getCurrentLocationId (raw field) for
      bare harnesses.

  23. isCulturallyCompatible / isReligiouslyPermitted stubs.
      Both fail closed (false with a reason). Do not treat the
      boolean as definitive.

  24. Religion bootstrap warn-only.
      CharacterQueries and PlaceQueries are WARN-ONLY for
      religion-bootstrap.js.

  25. Government-law formatter duplication.
      js/systems/government/settlement-law-formatters.js and
      js/religion/religion-format.js each have their own law label
      tables. Canonical source is SettlementLawDefinitions.

  26. Modal navigation setTimeout(100) in modals-religion.js.
      Documented deferral for the details modal's navigation
      buttons.

  27. Character religion writes.
      All religion writes to character.religionId /
      character.religionHistory route through
      CharacterCommands.setReligion.

  28. Children-commands + religion-inheritance integration.
      children-commands.js calls religion inheritance via
      CharacterCommands.assignCharacterReligion (or via
      religion-commands.js at call time). Must not write
      character.religionId directly.

  29. window.Religion.modals may be null if modals-religion.js
      loads AFTER religion-bootstrap.js. Load modals before
      bootstrap, or reach window.ReligionModals directly.

  30. Rank modal callback API.
      Every callback (onMount, onOpen, onConfirm, onCancel)
      receives the DOM element as its only argument — NOT a
      { element } handle. Read inputs via
      root.querySelector('#id'), never document.getElementById.

  31. Rank persist pattern.
      RankCommands.persist() uses Pattern A. Pattern C (discard
      the boolean return, report success) is banned. This is the
      same rule documented in stillwaters-docs.txt §3.1 for all
      domains.

  32. rankCollapsedGroups is session state.
      RankState.rankCollapsedGroups and RankState.reset are facade
      compatibility surfaces, not persisted state. Do not add
      persistence without changing the state contract.

  33. rank-bootstrap.js auto-init.
      init() runs at load. If masterData.data is not yet present,
      it hydrates against empty collections and completes. A
      subsequent explicit RankBootstrap.init() call is a no-op.
      Do not assume a page that loads rank-bootstrap.js without
      initializeStorage() will hydrate from the persisted data.

  34. No listener registry for death / delete hooks.
      CharacterLifecycle.killCharacter calls
      RankIssues.handleCharacterDeath DIRECTLY.
      CharacterDeletionCommands.deleteCharacter calls
      RankIssues.removeAllReferencesTo DIRECTLY. There is no
      registerLifecycleHook mechanism. Callers that skip these
      calls leave a dead character's deprecate-on-death ranks
      un-deprecated and a deleted character's inheritedFrom
      pointers dangling.
