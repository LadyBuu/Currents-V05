Notation:

  file.js
      a script load.
  call()
      a function invocation (not a script load).
  <- AFTER: file.js            (HARD)
      mandatory load-time dependency: this file's guard throws if
      file.js is not already loaded.
  <- after: file.js            (call-time)
      strong recommendation: the file loads without it, but a
      function throws or degrades when it is missing. Order to
      avoid first-use failures.
  <- after: file.js            (soft)
      optional dependency with a documented fallback. Ordering is
      optional but recommended.
  OPTIONAL block
      may be skipped if the corresponding features are not used.
  [UNVERIFIED]
      referenced but not in the supplied batch; confirm exports.
  [NOT PROVIDED]
      referenced by a header or REQUIRED list but not in the
      supplied files.

BLOCK 0 — STYLESHEETS (load before any page script)
==============================================================================

Every HTML page that renders domain UI MUST link these stylesheets,
in this order, before any <script> tag that touches the DOM.

  css/themes.css
    (defines :root defaults, all named themes, art direction)

  css/common.css
    <- AFTER: css/themes.css                  (HARD — every
                                                colour, font,
                                                radius, and shadow
                                                declaration is a
                                                var(--token) that
                                                themes.css
                                                defines)

  css/<page>.css
    <- AFTER: css/themes.css                  (HARD — same reason)
    <- AFTER: css/common.css                  (soft — for the
                                                shared structural
                                                classes:
                                                .empty-state,
                                                .location-tree-badge,
                                                .btn)

  Notes:
    - themes.css MUST be first. Without it, common.css and every
      domain CSS file render with UNSET tokens: transparent
      backgrounds, no borders, inherited (i.e. browser-default)
      fonts. The symptom looks like "no CSS at all" but every
      rule in common.css and the domain CSS is loading; they are
      simply resolving to unset values.
    - This is the single most common "the CSS isn't working"
      cause and it is not a domain-specific rule. It applies to
      index.html, DataManager.html, LocationManager.html,
      GovernmentManager.html, SettlementManager.html,
      ReligionManager.html, CultureManager.html,
      HouseholdManager.html, RoleManager.html, CharacterManager.html,
      every legacy *_v0*.html, every test page under js/testing/,
      and any future page.
    - index.html uses  themes.css → nexus.css  (nexus.css is
      self-contained and does not depend on common.css).
    - DataManager.html uses  themes.css → common.css →
      data-manager.css.  data-manager.css owns ONLY the app shell
      (.data-manager-app, .topbar, .panel-tabs, .tab-content,
      .tab-pane). Each tab module injects its own structural CSS
      at load (.ltm-* for location types, .gtm-* for government
      types, .rtm-* for ranks). common.css supplies .empty-state,
      .location-tree-badge, .btn.
    - No domain CSS file defines colour, font, radius, or shadow
      literals. Every visual value comes from themes.css tokens.

BLOCK 16 — RANK SUBSYSTEM (js/ranks/)
==============================================================================

This block is placed BEFORE the religion, settlement, government,
location, and UI blocks because:

  - CharacterLifecycle.killCharacter dispatches
    RankIssues.handleCharacterDeath at CALL TIME (typeof-guarded,
    DIRECT call, no listener registry).
  - CharacterDeletionCommands.deleteCharacter dispatches
    RankIssues.removeAllReferencesTo at CALL TIME (typeof-guarded,
    DIRECT call).
  - role-queries.js reads rank fields via accessors.getRankById at
    CALL TIME (role is loaded in BLOCK 35).
  - religion-queries.js and religion-commands.js do not read rank,
    but the settlement and government blocks read RoleQueries at
    CALL TIME, and RoleQueries reads RankSummary via accessors.
  - Under the documented full-app order the character subsystem
    loads BEFORE rank, so rank is placed immediately after the
    character block to close the call-time cycle.

BLOCK 45 — KNOWN HAZARDS (CROSS-SUBSYSTEM)

  1.  getCurrentYear vs getCurrentYearSafe.

      getCurrentYear.
      Government: getCurrentYearSafe (deprecated alias).
      Do not unify without updating every Government call site
      and government-docs.txt §18.

  2.  window.PlaceQueries.
      Referenced by the settlement subsystem; [UNVERIFIED]
      provider. Religion and Government use LocationQueries /
      accessors.getPlaceById instead. If PlaceQueries is absent,
      the settlement factory, settlement view models, and
      settlement modals throw on first call.

  3.  IndustryQueries and RoleQueries are hard load-time
      dependencies of government-queries.js. [UNVERIFIED] —
      confirm their prerequisites and that they load before
      government-queries.js.

  4.  Rank subsystem internal hazards.
      The rank subsystem has its own KNOWN HAZARDS list; see
      rank-doc.md §17 and the rank-doc-companion (this document's
      companion rank subsystem doc, PART 7). The top items:
        - modals-rank.js inline styles (deferred)
        - hierarchy data-depth CSS rules must ship with
          rank-ui-list.js
        - getNextRankNumber 3-arg signature (5-arg callers are
          latent bugs)
        - rank-bootstrap.js REQUIRED vs OPTIONAL split: RomanceQueries
          is OPTIONAL, FamilyQueries is REQUIRED
        - the character death / delete cascade calls
          RankIssues.handleCharacterDeath and
          RankIssues.removeAllReferencesTo DIRECTLY (typeof-guarded)

  5.  Cross-domain state modules.
      js/households/household-state.js, js/roles/role-state.js,
      js/ranks/rank-state.js (the state-facade variant, NOT the
      canonical js/ranks/rank-state.js from BLOCK 16),
      js/names/name-state.js, js/core/state/location-ui-state.js
      are only required by state.js, not by any of the character /
      location / settlement / government / religion / rank
      modules in this batch. Load them only if the state facade
      is used.

  6.  Government uses getCurrentYearSafe.
      Religion, settlement, character, location, RANK use
      getCurrentYear. Do not add getCurrentYearSafe calls to any
      non-Government module.

  7.  Deprecated government files.
      government-system.js, government-assignment.js,
      government-laws.js must not be loaded.

  8.  LocationCommands throw/boolean contract.
      GovernmentCommands._wrapLocationResult handles both.

  9.  Persistence divergence.
      SettlementCommandCommit throws on persist failure.
      GovernmentCommands.persist returns { success: false } but
      does not throw.
      ReligionCommands.persist returns { success, reason? } (does
      not throw).
      RankCommands.persist returns { success, reason? } using
      Pattern A (reads getLastSaveError().message on false; does
      not throw).
      Do not unify without updating every caller's
      error-handling.

  10. Year-transition integration.
      settlement-annual-processor.js must load BEFORE
      character-lifecycle.js so advanceMortality's settlement

      character-lifecycle.js so handleCharacterDeath is callable.

      (BLOCK 16 and BLOCK 23 precede BLOCK 34).

  23. isCulturallyCompatible / isReligiouslyPermitted stubs.
      Both fail closed (false with a reason). Do not treat the
      boolean as definitive.

  24. Religion bootstrap warn-only.
      CharacterQueries and PlaceQueries are WARN-ONLY for
      religion-bootstrap.js.

  25. Government-law formatter duplication.
      js/government/settlement-law-formatters.js and
      js/religion/religion-format.js each have their own law label
      tables. Canonical source is SettlementLawDefinitions.

  26. Modal navigation setTimeout(100) in modals-religion.js.
      Documented deferral for the details modal's navigation
      buttons.

  27. Character religion writes.
      All religion writes to character.religionId /
      character.religionHistory route through
      CharacterCommands.setReligion.

  28. Children-commands + religion-inheritance integration.
      children-commands.js calls religion inheritance via
      CharacterCommands.assignCharacterReligion (or via
      religion-commands.js at call time). Must not write
      character.religionId directly.

  29. window.Religion.modals may be null if modals-religion.js
      loads AFTER religion-bootstrap.js. Load modals before
      bootstrap, or reach window.ReligionModals directly.

  30. Rank modal callback API.
      Every callback (onMount, onOpen, onConfirm, onCancel)
      receives the DOM element as its only argument — NOT a
      { element } handle. Read inputs via
      root.querySelector('#id'), never document.getElementById.

  31. Rank persist pattern.
      RankCommands.persist() uses Pattern A. Pattern C (discard
      the boolean return, report success) is banned. This is the
      same rule documented in stillwaters-docs.txt §3.1 for all
      domains.

  32. rankCollapsedGroups is session state.
      RankState.rankCollapsedGroups and RankState.reset are facade
      compatibility surfaces, not persisted state. Do not add
      persistence without changing the state contract.

  33. rank-bootstrap.js auto-init.
      init() runs at load. If masterData.data is not yet present,
      it hydrates against empty collections and completes. A
      subsequent explicit RankBootstrap.init() call is a no-op.
      Do not assume a page that loads rank-bootstrap.js without
      initializeStorage() will hydrate from the persisted data.

  34. No listener registry for death / delete hooks.
      CharacterLifecycle.killCharacter calls
      RankIssues.handleCharacterDeath DIRECTLY.
      CharacterDeletionCommands.deleteCharacter calls
      RankIssues.removeAllReferencesTo DIRECTLY. There is no
      registerLifecycleHook mechanism. Callers that skip these
      calls leave a dead character's deprecate-on-death ranks
      un-deprecated and a deleted character's inheritedFrom
      pointers dangling.

  35. themes.css must load before common.css and every domain
      CSS file. Missing themes.css = unset tokens = transparent
      surfaces, no borders, default fonts. The symptom is "no
      CSS at all" but every rule is loading.
      Failure without it: every var(--token) declaration
      resolves to its fallback (none), which is unset.
      This is not a per-page rule; it applies to every page.

  36. responsive.js MUST load before collapsible.js.
      collapsible.js throws at load if
      RESPONSIVE_BREAKPOINTS.MOBILE is missing.
      The error reads "collapsible.js: responsive.js must load
      first (RESPONSIVE_BREAKPOINTS.MOBILE missing)".
      This is invariant 8 in BLOCK 44 restated as a hazard
      because the failure mode is a hard throw that kills the
      page.

  37. Character prerequisites must load before selectors,
      location, rank, or government.
      js/character/character-state.js,
      js/character/character-commands.js, and
      js/character/character-queries.js are HARD load-time
      dependencies of:
        - js/selectors/modals-char-selector.js
          (CharacterQueries.getCharacterSummary)
        - js/location/location-commands.js
          (CharacterCommands, CharacterQueries)
        - js/ranks/rank-queries.js
          (CharacterState)
        - js/ranks/rank-assignment.js
          (CharacterCommands.updateRankAssignment)
        - js/ranks/rank-commands.js
          (nine CharacterCommands rank-API methods)
        - js/ranks/rank-issues.js
          (CharacterState, CharacterCommands)
        - js/ranks/modals-rank.js
          (CharacterState)
      Failure without them: the dependent file throws at load
      with a named dependency message. The most common cascade
      is "modals-char-selector.js: character-queries.js must
      load first (CharacterQueries.getCharacterSummary
      missing)" — which is fixed by moving the character block
      before selectors, not by changing any selector file.

  38. js/selectors/modals-household-selector.js requires the
      full household domain (household-constants.js,
      household-rules.js, household-state.js,
      household-queries.js, household-commands.js) at load.
      It is NOT a universal selector. Pages that do not load
      the household stack must NOT include it. A page that
      needs it must load the full household block first.
      Failure without it: the file throws at load with
      "modals-household-selector: HouseholdQueries is
      required".

  39. Government requires four cross-domain modules at load:
      RoleQueries, SettlementQueries,
      SettlementProsperityQueries, IndustryQueries.
      government-queries.js throws at load if any one is
      missing. On a page that does not load the Settlement /
      Industry / Role stacks, the four namespaces must be
      stubbed BEFORE government-queries.js runs. The stub is:
        window.SettlementQueries           — getIndustryTaxRate,
                                              getGovernmentSalaryBudget
        window.SettlementProsperityQueries — getProsperityValue
        window.IndustryQueries             — getIndustryTaxRevenue,
                                              getIndustryEnterpriseStats
        window.RoleQueries                 — getRoleSummary,
                                              getRankSummary,
                                              getAllRankSummaries,
                                              getAllRoleSummaries
      Failure without the stub: government-queries.js throws at
      load ("government-queries.js requires RoleQueries"), which
      cascades to government-commands.js, government-economy.js,
      every modals-government-*.js, and the government-type
      manager tab.

  40. When the government block is loaded behind stubs, only
      Government Type CRUD is fully functional. Government
      departments, positions, assignments, salary flows, and
      justice/watch updates reach the stubs and will either
      render empty data or throw at call time. This is expected
      on a page that does not include the full Settlement /
      Industry / Role stacks.

  41. js/core/constants.js does NOT exist. The path is
      js/core/constants/constants.js. Any HTML referencing
      js/core/constants.js gets a 404 on every load.
      Failure without the correct path: window.LOCAL_STORAGE_KEYS,
      window.GENDER_VALUES, window.ATTRACTION_VALUES, and every
      other constant that lives in constants.js is undefined at
      the point where dependent modules read them.

  42. No file named js/core/query-helpers.js exists in the tree.
      If an HTML references it, that is a stale path. The
      helpers it used to provide (if any) are now spread across
      js/core/world.js, js/core/accessors.js, and the domain
      query modules.
