File: household-state.js

Purpose:
The single source of truth for all household data in the Still Waters system. This module manages:

    Loading and storing household data from masterData

    In-memory caching with efficient lookups

    Batch updates with change notifications

    UI state management (filters, selection, view mode)

    Subscriber notification system

Key Features:

    Single Source of Truth - All household data flows through this module

    Batch Updates - Changes are queued and processed in batches for performance

    Change Notifications - Subscribers are notified of all state changes

    Cache Management - Maps for O(1) lookups with automatic invalidation

    Recursion Guards - Prevents infinite loops in update/refresh cycles

    UI State Separation - UI state is separate from data state

    Error Handling - Graceful handling of missing data and invalid operations

Migration Notes:

    All modules should use HouseholdState.getHousehold() instead of window.getHousehold()

    All modules should use HouseholdState.getAllHouseholds() instead of window.getAllHouseholds()

    All modules should use HouseholdState.createHousehold() instead of window.createHousehold()

    All modules should use HouseholdState.updateHousehold() instead of window.updateHousehold()

    All modules should use HouseholdState.deleteHousehold() instead of window.deleteHousehold()

    All modules should use HouseholdState.subscribe() to listen for changes

    The householdListUI.js should use HouseholdState.getUIState() and HouseholdState.setUIState() for filters

Backward Compatibility:
The module still exports to window so existing code that uses window.getHousehold() etc. will continue to work, but should be migrated to use HouseholdState directly for consistency.

File: household-commands.js

Purpose:
All write operations for household management. This module handles:

    Adding, removing, and updating household members

    Transferring members between households

    Managing household heads (setting, removing, succession)

    Managing departments (create, update, delete, set head)

    Recording household changes in character history

    Repairing broken data consistency

Key Features:

    Single Entry Point - All write operations go through this module

    Validation - All operations validate input before execution

    History Recording - All changes are recorded in character history

    Activity Logging - All changes are logged in household activity logs

    Event Logging - All changes trigger system events

    Error Handling - Graceful error handling with rollback support

    Recursion Guards - Prevents infinite loops during operations

    Cache Invalidation - Automatically invalidates caches after changes

Migration Notes:

    Replace window.addHouseholdMember() with HouseholdCommands.addMember()

    Replace window.removeHouseholdMember() with HouseholdCommands.removeMember()

    Replace window.setHouseholdHead() with HouseholdCommands.setHead()

    Replace window.createDepartment() with HouseholdCommands.addDepartment()

    Replace window.deleteDepartment() with HouseholdCommands.removeDepartment()

    Replace window.recordHouseholdChange() with HouseholdCommands.recordHistory()

Return Values:

All commands return a standardized result object:
javascript

{
    success: true,          // or false
    reason: '...',          // only on failure
    // Operation-specific data
    member: {...},
    household: {...},
    character: {...}
}

Recursion Safety:

    _processingCommand guard prevents re-entry during command execution

    _recordingHistory guard prevents history recording recursion

    All operations are atomic (success/fail as a unit)
