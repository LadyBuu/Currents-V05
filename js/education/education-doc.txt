================================================================================
PART 1 — FILE INVENTORY AND LAYERS
================================================================================

The education subsystem follows a strict layered chain:

  CONSTANTS (leaf; pure vocabulary + static config)
    js/systems/education/education-constants.js

  RULES (pure policy; depends on constants at load)
    js/systems/education/education-rules.js

  STATE (owns canonical institutions + indexes + persistence sync +
         cross-tab reload)
    js/systems/education/education-state.js

  LEARNING (proficiency / literacy / education level reads; hydration
            helper routed through CharacterCommands)
    js/systems/education/education-learning.js

  HISTORY (append-only event ledger on each institution)
    js/systems/education/education-history.js

  QUERIES (read-only; composes State + Learning + History +
           accessors + world + role / religion / settlement
           readers)
    js/systems/education/education-queries.js

  COMMANDS (writes; the only saveMasterData site)
    js/systems/education/education-commands.js

  ANNUAL (pipeline orchestrator; sequence, not mutations)
    js/systems/education/education-annual.js

  UI LIST (DOM rendering; consumes Queries + History)
    js/systems/education/education-ui-list.js

  MODALS (DOM + commands; batch persist per successful action)
    js/systems/education/modals-education.js

      - PERSISTENCE: persist() is called once at the end of the
        pipeline, and its boolean return is inspected.

================================================================================
PART 7 — KNOWN HAZARDS
================================================================================

 1.  hydrateFromMasterData is EXPLICIT.
     EducationState does not hydrate on module load. Every read
     and every mutation primitive calls _assertHydrated() and
     throws if hydration has not run. Bootstrap must call
     hydrateFromMasterData([...]) once after masterData loads,
     before any education read or write. This is the single most
     common integration mistake.

 2.  Cross-tab reload does NOT mark data dirty.
     education-state.js's masterDataUpdated handler uses an
     internal _rehydrateFromMasterData that drops duplicate ids
     and logs (does NOT throw), writes
     masterData.data.educationalInstitutions (no-op for content
     but ensures the in-memory array matches the masterData
     reference), invalidates the accessor cache, and does NOT
     call markDataDirty. The prior revision went through
     hydrateFromMasterData (via the generic load path) which threw
     on duplicates and always marked dirty. Do not "simplify" by
     routing reload through the public API.

 3.  EducationState writes masterData on every local mutation.
     Then EducationCommands.persist() flushes. The prior revision
     had the state NOT write masterData — that is the
     silent-loss-on-reload bug the current implementation closes.
     Do not move the sync into persist(); it belongs at the
     memory-write boundary.

 4.  persist() returns a BOOLEAN, not { success, reason }.
     Unlike rank / religion / role / name (which return
     { success, reason? }), education-commands.js::persist()
     returns the raw boolean from saveMasterData(). On failure,
     getLastSaveError() is read inside persist() and logged via
     console.error, but NOT returned. Callers that want the
     underlying reason must call getLastSaveError() themselves
     after a false return. modals-education.js's
     _persistAndWarn() documents this by returning false on a
     false return and surfacing a warning toast. This is a
     documented divergence — see HAZARDS §9 (persistence
     divergence across domains).

 5.  Event ID prefix must not contain underscores.
     education-history.js uses 'eduevt' (no underscore). ids.js's
     grammar for prefixes is [a-z][a-z0-9]*; an underscore makes
     generateId return null. addEvent throws on a null/non-string
     id. Prior revisions used 'edu_evt' and silently stored null
     ids on every event.

 6.  addEvent takes an institution ID, not a record.
     Passing a cloned institution record (e.g. from
     EducationState.getInstitution) writes to the clone and
     silently loses the event. addEvent throws on non-string
     input. Recorders in education-history.js pass an id to
     addEvent, and are called BEFORE the last _updateInstitution
     in their command.

 7.  Character mutation ownership.
     Character-owned education fields (education,
     educationHistory, subjectProgress, isLiterate) are written
     only via CharacterCommands. The generic
     updateCharacterFields refuses them. Education code that
     writes character.* directly is a bug.

 8.  window.getLocationPopulationCount [UNVERIFIED].
     education-queries.js requires this function for its health,
     recommendation, and density queries. It is NOT exported by
     world.js. The module throws when it is absent. Returning 0
     would hide the missing primitive. Do not add a fallback. Add
     the function to world.js (or a dedicated population module)
     before calling these queries. See education-doc.txt §10.

 9.  Persistence divergence across domains.
       - SettlementCommandCommit throws on persist failure.
       - GovernmentCommands.persist returns { success: false }
         but does not throw (does not read getLastSaveError).
       - ReligionCommands.persist returns { success, reason? }
         and DOES read getLastSaveError.
       - RankCommands.persist returns { success, reason? } and
         DOES read getLastSaveError.
       - RoleCommands.persist returns { success, reason? } and
         DOES read getLastSaveError (typeof-guarded).
       - CultureCommands.persist returns { success, reason? }
         but does NOT read getLastSaveError.
       - NameCommands.persist returns { success, reason? } and
         DOES read getLastSaveError (typeof-guarded).
       - EducationCommands.persist returns BOOLEAN and reads
         getLastSaveError (typeof-guarded) to log, NOT to return.
     Do not unify without updating every caller's
     error-handling.

 10. Role skill authority.
     character.professions[].skillLevel is canonical.
     character.subjectProgress['role_<id>'].level is educational
     progress and may legitimately differ. Education reports
     progression; Role writes it. Do not conflate the two values.
     See education-doc.txt §9.

 11. ROLE_CATEGORIES divergence.
     education-constants.js defines role categories that are
     intended to agree with the role domain's category vocabulary.
     If they diverge, education-constants.js's ROLE_CATEGORIES
     should be removed and RoleState should provide categories.
     This is a documented deferral in education-doc.txt §10, not
     a live bug.

 12. Graduation grants a role at skillLevel 100.
     That is a placeholder pending the qualification model. Not a
     bug. Changing it requires deciding what a qualification is,
     what a graduate is qualified for, and how role eligibility
     reads a qualification. See education-doc.txt §10.

 13. advanceLearning's role skill progression requires the
     character to hold the role.
     RoleCommands.recordCharacterSkillProgress refuses to create
     a profession record. If the character does not hold the
     role, advanceLearning returns _ok(...) with roleSkillError.
     Education does not assign the role. This is deliberate — see
     education-doc.txt §10.

 14. Student detail modal action bindings close-then-reopen.
     openInstitutionDetailsModal's onMount binds each action to
     close the current modal and open the target. On success of
     the target modal, the details modal is re-opened. No
     setTimeout; no stale binding. Modals that open the
     details modal from inside another modal are unaffected.

 15. Enrollment transaction order.
     The household debit runs AFTER the character-side enrollment
     write. If the character-side write fails, the household is
     never debited. If the household debit fails after the
     character-side write succeeds, the character-side enrollment
     is rolled back via recordEducationWithdrawal and the roster
     entry is removed. This closes the "Household wealth
     rollback" deferral in education-doc.txt §10. Do not
     reorder without re-auditing rollback.

 16. deleteInstitution orphan sweep.
     Runs regardless of the cascade flag, via
     CharacterCommands.removeEducationRecord. Best-effort;
     individual failures are logged; the delete still succeeds.
     Result envelope exposes orphanSweepAttempted and
     orphanSweepSucceeded. If removeEducationRecord is not
     available, the sweep is skipped with a single console.warn.

 17. Inline styles in education-ui-list.js and
     modals-education.js.
     CSS class extraction is a documented deferral (see
     education-doc.txt §10). Do not assume either file is
     CSS-only.

 18. modals-education.js uses onMount, not setTimeout.
     The prior revision used _processingModal + setTimeout(100),
     which had two failure modes (a fast close left a pending
     timeout; a throw before the flag cleared left the guard
     stuck). onMount runs synchronously during openModal, so
     both failures are impossible. Do not reintroduce a
     setTimeout-based guard.

 19. advanceLearning's STUDENT_BECAME_LITERATE emission guards
     against a missing HISTORY_EVENT_TYPES.
     If HISTORY_EVENT_TYPES is missing (a load-order regression),
     the event is skipped with a console.warn — the literacy flag
     write still succeeds. Prior revisions accessed the constant
     inline, so a missing HISTORY_EVENT_TYPES would throw a
     TypeError after the skill write had already happened.

 20. Curriculum proficiency cap during graduation.
     graduateStudent caps every curriculum item's proficiency at
     100, iterating item by item. If a mid-loop call throws, the
     loop logs and CONTINUES (the item failure does not abort
     the rest). The graduation record is written before the cap
     loop. Known partial-failure mode; a batch
     updateSubjectProgress command would fix it. Deferred.

 21. Tuition history deduplication.
     updateInstitution's tuitionPerYear branch and updateTuition's
     customTuition branch both append to tuitionHistory. Both skip
     the push when the current year already has an entry with the
     same newAmount. The modal calls both in sequence for one user
     save; the dedup makes the pair produce exactly one entry per
     distinct change. Do not remove the dedup without changing the
     modal.

 22. education-annual.js processedStudentCount BEHAVIOUR CHANGE.
     The count now includes students evaluated for graduation
     readiness who did not gain skill and were not ready. This is
     a higher number than prior revisions. Tests that asserted a
     specific value will need updating. No other field on the
     result envelope changes shape.

 23. education-annual.js success vs status.
     success is BOOLEAN (true iff no fatal errors); status is the
     legacy string ('completed' / 'completed_with_errors' /
     'partial' / 'failed'). New code should prefer success plus
     the individual step-result fields. Do not rely on status
     alone — it does not distinguish fatal from non-fatal.

 24. Auto-graduation skips multi-role institutions.
     When options.autoGraduate is true, the pipeline graduates
     students ready for graduation AND whose institution teaches
     at most one role. Multi-role institutions require the
     caller to choose a role. This is deliberate — the
     graduation-granting command requires role selection.

 25. getStudentsReadyForGraduation (queries) reads via
     EducationState.getInstitution (clone), not
     _getInstitutionCanonical.
     The clone is deep enough for the student records the
     function reads. Do not "fix" by using the internal accessor;
     that is commands-only.

 26. education-learning.js's read accessors fall back to the
     projection with a ONE-SHOT console.warn.
     If CharacterCommands.getSubjectProgress /
     getSubjectProgressAll are absent, the module logs once per
     process (not per call) and reads off the projection. This
     preserves prior behaviour and makes the gap visible. If
     character-commands.js later gains the accessors, the
     fallback becomes unreachable and can be deleted.

 27. Local escapeHtml fallback.
     education-ui-list.js and modals-education.js define a local
     escapeHtml fallback when window.escapeHtml is absent. This
     is a defensiveness pattern that predates the formatting.js
     hard dependency in the other subsystems. Do not assume these
     two education files are consistent with rank / role /
     religion, which require escapeHtml at load. If the tree
     tightens this, both files need updating in one pass.

 28. modals-education.js uses three confirmDialog call sites.
     Each calls _confirmDialog (which prefers window.confirmDialog
     and falls back to window.confirm). Do not add a direct
     window.confirm call; the fallback path is documented for
     absence of modals-core.js.

 29. selector integration is OPTIONAL for modals-education.js.
     openCharacterSelector and openHouseholdSelector are soft —
     missing -> toast and return. Only the create/ownership
     modals need them. A page that only uses enrollment,
     graduation, and curriculum editing does not need the
     selectors loaded.

 30. education-annual.js fails loudly when SettlementState is
     missing.
     The budget step is meaningless without
     SettlementState.getEducationBudget, so it is a hard
     requirement, not an optional one. Do not soften it to a
     warning; a page that runs the annual pipeline without
     settlement would silently under-process budgets.
