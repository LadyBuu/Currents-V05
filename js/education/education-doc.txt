# EDUCATION SYSTEM - DOCUMENTATION

## Overview

The Education System manages educational institutions, enrolment, teaching
staff, curriculum, learning progression, tuition, ownership, finance, and
historical records. It is one of the layered domain subsystems alongside
Apprenticeship, Professional, Relationship, Settlement, Religion, and Household.

Design principles:

- Layered: constants → rules → state → queries/commands → annual → UI.
- Single source of truth: `education-state.js` owns canonical institution records.
- Projections: queries return frozen projections, never live records.
- Transaction boundary: commands mutate; the caller persists once.
- Fail loud: missing dependencies throw; they do not return empty values.
- Append-only history: education events are never edited or deleted.
- Cross-domain via commands: education calls Role, Household, Settlement, and
  Religion commands for cross-domain effects; it does not touch their state.

## Module responsibilities

### education-constants.js

Vocabulary and configuration only. No logic.

Exports on `window`:

    EDUCATION_LEVELS        Literacy-based education tiers.
    SUBJECTS                Canonical subject registry.
    INSTITUTION_TYPES       Seven institution tiers, size/prestige-based.
    OWNERSHIP_TYPES         public | private | religious.
    SCHOOL_TIERS            Exclusive reputation bands (half-open).
    ROLE_CATEGORIES         Role category vocabulary (for specialization).
    TUITION_DEFAULTS        Tuition tuning parameters.
    TUITION_TYPE_MULTIPLIERS Per-type tuition multipliers.
    HISTORY_EVENT_TYPES     Closed vocabulary for history events.

Conventions:

- `education-constants.js` is the only source for these values. No other module
  may define fallback copies.
- `INSTITUTION_TYPES[*].baseTuition` is canonical. There is no separate
  `DEFAULT_TUITION_BY_TYPE`.
- `SCHOOL_TIERS` boundaries are half-open `[min, max)`. A reputation of 40 is
  `lower_middle`, not `poor`.
- `HISTORY_EVENT_TYPES` is closed. The history module rejects unknown types.

### education-rules.js

Pure policy. No state, no I/O, no mutation. Every function accepts facts and
returns a decision.

Key functions:

    getEducationLevelForLiteracy(literacy)     Highest level whose threshold is met.
    isLiterateAtLevel(literacy)                literacy >= LITERACY_THRESHOLD (30).
    calculateLearningResult(current, delta)    Validated, clamped proficiency.
    isGraduationEligible({...})                Single canonical graduation check.
    progressKeyFor(curriculumItem)             `role_<id>` or `<id>`.

`isGraduationEligible` is the only implementation of graduation readiness. It
takes `{ yearsEnrolled, requiredYears, curriculum, proficiencyByKey }` and
returns `{ eligible, missing, reason }`.

### education-state.js

Canonical institution records, indexes, subscriptions, UI state, hydration.

Public API:

    subscribe(callback)                        Subscribe to state events.
    getAllInstitutions()                       Cloned records (defensive).
    getInstitution(id)                         Cloned record or null.
    getInstitutionsByLocation(locationId)      Cloned records.
    getInstitutionsByType(typeId)              Cloned records.
    getInstitutionsByOwnershipType(type)       Cloned records.
    getInstitutionsByReligion(religionId)      Cloned records.
    getUIState()                               Frozen snapshot.
    updateUIState(partial)                     Merge top-level fields.
    hydrateFromMasterData(list)                Replace state from raw data.
    migrateInstitution(raw)                    Normalize a raw record.
    isHydrated()                               Whether hydration has run.

Internal API (for Commands only, prefixed `_`):

    _getInstitutionCanonical(id)               Live canonical record.
    _getAllInstitutionsCanonical()             Live array.
    _addInstitution(inst)                      Add and reindex. No save.
    _updateInstitution(id, patch)              Patch and reindex. No save.
    _removeInstitution(id)                     Remove and reindex. No save.
    _indexesRebuild()                          Rebuild indexes manually.

Rules:

- State does not persist. Callers call `EducationCommands.persist()`.
- State does not interpret domain fields. No `religionId → isReligiousSchool`
  inference, no `specializationCategory → isSpecialized` inference.
- Reads return clones. Mutating a clone has no effect on canonical state.
- Subscriptions are queued, not recursive. Nested mutations dispatch after the
  outer notification finishes; events are never dropped.

### education-learning.js

Proficiency, literacy, and education level reads. Hydration helper.

Public API:

    ensureCharacterEducationRecord(character)  Initialize education fields.
    getProficiency(characterId, item)          Subject proficiency 0-100.
    getSubjectProficiency(characterId, id)     By subject id or `role_<id>`.
    getCharacterProficiencies(characterId)     All proficiency records.
    getEducationLevel(characterId)             Level object from constants.
    isLiterate(characterId)                    Literacy threshold predicate.

Rules:

- `subjectProgress.literacy.level` is canonical for literacy.
  `character.isLiterate` is a materialized milestone maintained by
  `EducationCommands.advanceLearning` and is not consulted by reads.
- Reads do not mutate. `ensureCharacterEducationRecord` is explicit; it is
  never called by a read.

### education-commands.js

All write operations. Every command:

    1. Validates input and dependencies.
    2. Reads canonical state via `_getInstitutionCanonical`.
    3. Applies mutations via `_addInstitution` / `_updateInstitution` /
       `_removeInstitution` and cross-domain commands.
    4. Emits history events via `EducationHistory`.
    5. Returns a structured result.

Commands do not persist. The caller calls `EducationCommands.persist()` once
after a batch. Commands do not toast. The caller surfaces notifications.

Institution CRUD:

    createInstitution(options)           Single object. Legacy positional also accepted.
    createReligiousSchool(religionId, name, locationId, options)
    updateInstitution(id, updates)
    deleteInstitution(id, cascade)
    updateReputation(id, delta)

Teachers:

    hireTeacher(institutionId, teacherId, subjectId)
    fireTeacher(institutionId, teacherId, reason)

Students:

    enrollStudent(institutionId, studentId, startYear)
    graduateStudent(institutionId, studentId, graduationYear, selectedRoleId)
    withdrawStudent(institutionId, studentId, reason)

Learning:

    advanceLearning(characterId, curriculumItem, progress)

Headmaster:

    setHeadmaster(institutionId, characterId, title, startYear)
    endHeadmasterTerm(institutionId, endYear, reason)

Tuition:

    calculateTuition(institutionId, year)
    updateTuition(institutionId, newTuition, reason)
    updateTuitionWaiver(institutionId, waiveTuition, reason)
    getTuitionHistory(institutionId, limit)

Ownership:

    setSchoolOwnership(institutionId, ownershipType, ownerId, ownerType)
    setSchoolOwner(institutionId, ownerId, ownerType)

Finance:

    calculatePublicSchoolFunding(institutionId, year)
    applyGovernmentFunding(institutionId, year)
    calculatePrivateSchoolProfit(institutionId, year)
    processPrivateSchoolProfit(institutionId, year)
    processAllSchoolFinances(year)

Settlement:

    receiveSettlementBudget(locationId, amount, year)
    getSettlementFundingSummary(locationId, year)

Demolition:

    demolishInstitution(id, reason, year, options)
    rebuildInstitution(id, rebuildYear, options)
    getDemolishedInstitutions(options)
    getInstitutionDemolitionStats(locationId)

Persistence:

    persist()                            Save current state. Caller-owned.

Result shape:

    { success: true, ...command-specific fields }
    { success: false, reason: string, ...contextual fields }

Command semantics:

- `createInstitution` accepts a single options object. Legacy positional
  `(name, typeId, locationId, options)` is detected and normalized.
- `enrollStudent` deducts tuition from the student's household if the
  institution is private and tuition is non-zero. Household wealth is read via
  `HouseholdEconomy`. If the household cannot afford tuition, enrollment fails.
- `graduateStudent` delegates graduation eligibility to
  `EducationRules.isGraduationEligible` via `getStudentsReadyForGraduation`.
  Grants role on graduation if the institution teaches roles. Multi-role
  institutions require `selectedRoleId`.
- `advanceLearning` writes to `character.subjectProgress` and syncs
  `character.professions` via Role commands. Emits `student_became_literate`
  when literacy threshold is crossed.
- `applyGovernmentFunding` and `processPrivateSchoolProfit` are the write paths
  for public and private finance respectively. `processAllSchoolFinances` runs
  both in one pass and returns a summary.
- `receiveSettlementBudget` distributes a settlement's education budget equally
  among its institutions.
- `demolishInstitution` and `rebuildInstitution` are the only paths that set
  `status` to `demolished` and back. Both preserve religion fields.

### education-annual.js

Annual pipeline orchestrator. Owns sequence, not mutation.

    processAnnualEducation(year, options)       Full pipeline.
    processAnnualInstitution(id, year, options) Single-institution pipeline.
    getStudentsReadyForGraduation(id, year)     Delegates to EducationQueries.

Pipeline order (frozen):

    1. Learning advancement for every enrolled student.
    2. Graduation readiness evaluation (recorded, not committed).
    3. Settlement education budget allocation (before finance).
    4. School finances (public funding, private profit).
    5. Persist once.

Options:

    autoGraduate     If true, auto-graduates students when the institution
                     teaches at most one role. Multi-role institutions require
                     explicit selection and are skipped.
    processFinances  Default true. Runs step 4.
    processBudgets   Default true. Runs step 3.
    persist          Default true. Runs step 5.

Result envelope:

    {
      year, status,
      processedStudentCount,
      skillGains[], withdrawals[], readyForGraduation[], graduations[],
      finances, budgetProcessing,
      errors[]
    }

`status` is `completed`, `completed_with_errors`, or `partial`.

The annual pipeline saves once via `EducationCommands.persist()`. It never
toasts. It never mutates state directly.

Append-only event ledger embedded on each institution as `institution.history`.

Public API:

    getInstitutionHistory(id, options)           Frozen event copies.
    getInstitutionHistoryStats(id)               Event type counts.
    getTeacherEmploymentHistory(characterId)     Hiring + departure events.

Recorders (call these from Commands; they call `addEvent` internally):

    recordTeacherDeparted(instId, teacherId, year, reason, notes)
    recordStudentEnrolled(instId, studentId, year, notes)
    recordStudentGraduated(instId, studentId, year, notes)
    recordStudentWithdrew(instId, studentId, year, reason, notes)
    recordHeadmasterAppointed(instId, characterId, title, year, notes)
    recordHeadmasterEnded(instId, characterId, year, reason, notes)

    recordInstitutionMoved(instId, oldLocName, newLocName, year, reason)
    recordReputationChanged(instId, oldRep, newRep, year, reason)

Event shape:

    { id, type, year, entityId, entityName, details, reason,
      previousValue, newValue, metadata, timestamp }

Rules:

- Events are frozen on read.
- Events are never edited or deleted. Corrections are new events.
- `type` must be in `HISTORY_EVENT_TYPES`. Unknown types throw.
- `metadata` is a structured object, not a JSON string.
- Sort order is `(year desc, timestamp desc, id desc)`. Deterministic for
  same-year events.
- History does not persist. The enclosing Command's caller saves.
- Formatted HTML is not produced here. Rendering is `education-ui-list.js`.

## Cross-domain integration

Education reads and writes through other domains via their commands. It does
not touch their state directly.

Role:

- `RoleCommands.assignRoleToCharacter(cid, rid, opts)` — used by graduation.
- `RoleCommands.updateProfessionSkill(cid, rid, level)` — used by
  `advanceLearning` for role-type curriculum items.
- `RoleState.getRole(id)`, `RoleState.getAllRoles()` — for specialization and
  category lookups.

Household:

- `HouseholdEconomy.getHouseholdWealth(hid)`, `updateHouseholdWealth(...)`,
  `trackTuitionExpense(...)` — for private tuition payment on enrolment.

Settlement:

- `SettlementState.getEducationBudget(locId)` — the annual budget source.
- `SettlementCommands.updateWealth(locId, delta, reason)` — debited when a
  public school receives funding.

Religion:

- `ReligionState.getReligion(id)`, `ReligionState.getAllReligions()` — for
  religious school affiliation and ownership.

Character:

- `getCharacterById`, `getCharacters`, `calculateAge` — read access.
- Education writes only to `character.subjectProgress`, `character.isLiterate`,
  `character.education`, and `character.educationHistory`. Profession records
  are written via Role commands.

## Persistence

Every mutation path leads to `EducationCommands.persist()`, which calls
`saveMasterData()` exactly once. Commands do not save individually.

Callers that mutate:

- `education-annual.js` persists once at the end of the annual pipeline.
- `modals-education.js` persists once per successful modal submission.
- External orchestrators persist once after their batch.

State hydration is explicit:

    EducationState.hydrateFromMasterData(
        window.masterData?.data?.educationalInstitutions || []
    );

Called once at app bootstrap before any query or command runs.

## Integration with Apprenticeship

Education and Apprenticeship share the profession record as the canonical
store for role skill.

- Education writes role skill via `RoleCommands.updateProfessionSkill`.
- Apprenticeship writes role skill via `RoleCommands.setSkillLevel`.
- Education reads school proficiency from `character.subjectProgress`. This is
  the curriculum mirror, not the canonical profession skill.
- Apprenticeship reads role skill from `character.professions`. This is
  canonical.
- Graduation grants role skill to `professions` via `assignRoleToCharacter`.

A character who has both school and apprenticeship training will have two
numbers: the school curriculum proficiency in `subjectProgress`, and the
professional skill in `professions`. They are not the same value and should
not be treated as such.

The canonical rule: **`professions[i].skillLevel` is the source of truth for
competence. `subjectProgress` is a curriculum progress log.**

## Testing and verification checklist

Load:

- `education-constants.js` loads without `window.masterData` present.
- Each subsequent module loads after its dependencies.
- `education-system.js` throws clearly if a canonical module is missing.

Hydration:

- `hydrateFromMasterData([])` leaves state empty but valid.
- `hydrateFromMasterData([raw])` normalizes missing fields.
- `migrateInstitution(null)` returns null.
- `migrateInstitution({})` returns null (no id).

Reads:

- `getInstitution(id)` returns a clone; mutating the clone has no effect.
- `getInstitutionDetails(id)` returns frozen projections.
- `getInstitutions()` filters without crashing on missing reputation.
- `getReligiousInstitutions()` uses `isReligiousSchool === true`.
- `getStudentsReadyForGraduation()` delegates to the rules.

Writes:

- `createInstitution({...})` returns `{ success: true, institutionId }`.
- `createInstitution(name, typeId, locId, opts)` legacy form works.
- Private institution without owner fails with `Private institutions require
  an ownerId`.
- Public institution with a religion is allowed and remains `public`.
- Religious ownership without a religion fails.
- `enrollStudent` on private school with insufficient household wealth fails.
- `graduateStudent` with multiple taught roles and no `selectedRoleId` returns
  `availableRoles`.
- `advanceLearning` crossing the literacy threshold emits
  `student_became_literate`.
- `demolishInstitution` records `institution_demolished`. `rebuildInstitution`
  records `institution_rebuilt`.

Annual:

- `processAnnualEducation` runs the full pipeline.
- With `autoGraduate: false`, students appear in `readyForGraduation`.
- With `autoGraduate: true` and a single taught role, students graduate.
- With `autoGraduate: true` and multiple taught roles, students are skipped
  and remain in `readyForGraduation`.
- Settlement budgets allocate before finance.
- One save occurs at the end.
