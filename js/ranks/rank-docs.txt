# Rank System Documentation

## Overview

The Rank System is a modular, clean-architecture implementation for managing hierarchical titles, ranks, and inheritance in the Still Waters world simulation. It provides complete CRUD operations, assignment logic, numbering systems, surname rules, and spouse inheritance.

---

## File Reference

### 1. rank-constants.js

**Purpose:** Centralized constants for rank levels, symbols, and default structures.

**Exports:**
| Constant | Type | Description |
|----------|------|-------------|
| `RANK_LEVELS` | Object | Level definitions with name, icon, description |
| `AVAILABLE_SYMBOLS` | Array | Allowed rank symbols for UI selection |
| `DEFAULT_RANK` | Object | Default rank structure template |

**RANK_LEVELS Structure:**
```javascript
RANK_LEVELS = {
    1: { name: "Sovereign", icon: "◉", description: "Highest level - Rulers, monarchs, emperors" },
    2: { name: "High Noble", icon: "◧", description: "Dukes, princes, high lords" },
    3: { name: "Noble", icon: "◈", description: "Counts, earls, barons" },
    4: { name: "Gentry", icon: "⟡", description: "Knights, esquires, landed gentry" },
    5: { name: "Commoner", icon: "⌂", description: "Merchants, artisans, peasants" }
}
```

### 2. rank-state.js

**Purpose:** Single source of truth for ALL rank data with caching and notifications.

**Exports:**

| Function | Description |
|----------|-------------|
| `RankState.getRank(id)` | Get rank by ID |
| `RankState.getAllRanks()` | Get all ranks |
| `RankState.getRanksByPriority(priority)` | Get ranks by priority level |
| `RankState.getRankHierarchy()` | Get hierarchical rank structure |
| `RankState.getInheritanceRules()` | Get all inheritance rules |
| `RankState.getInheritanceRulesForRank(rankId)` | Get rules for a rank |
| `RankState.getRankCount()` | Get total rank count |
| `RankState.addRank(rankData)` | Add a new rank |
| `RankState.updateRank(rankId, updates)` | Update a rank |
| `RankState.deleteRank(rankId)` | Delete a rank |
| `RankState.addInheritanceRule(parentRankId, childRankId, minChildAge, order)` | Add inheritance rule |
| `RankState.removeInheritanceRule(parentRankId, ruleIndex)` | Remove inheritance rule |
| `RankState.subscribe(callback)` | Subscribe to state changes |
| `RankState.invalidateCache()` | Clear all caches |

**Rank Data Structure:**
```javascript
{
    id: "rank_1234567890_abc123",
    name: "Duke of Example",
    priority: 2,                // 1-5 (Sovereign to Commoner)
    numbered: true,
    numberingType: 'reign',     // 'reign' or 'birth'
    numberingPrefix: '',        // e.g., "Prince "
    numberingSuffix: '',        // e.g., " of England"
    symbol: "◧",
    genderRestriction: 'either', // 'either', 'male', 'female'
    locationTypeId: null,
    deprecateOnDeath: false,
    spouseInheritance: null,    // Rank ID that spouse inherits
    allowsMultipleSpouses: false,
    parentRankId: null,         // Parent rank in hierarchy
    customSurnameRule: false,
    surnameConnector: 'of',     // 'of', 'from', 'van', 'de' (free text)
    surnamePrefix: '',          // 'Mac', 'Fitz'
    surnameSuffix: '',          // 'son', 'dottir'
    createdAt: 1234567890,
    updatedAt: 1234567890
}
```

### 5. rank-assignment.js

**Purpose:** Complex business logic for rank assignment and numbering.

**Exports:**

| Function | Description |
|----------|-------------|
| `RankAssignment.assignRankToCharacter(characterId, rankId, options)` | Assign rank |
| `RankAssignment.deprecateRankAssignment(characterId, rankId)` | Deprecate rank |
| `RankAssignment.getNextRankNumber(rankId, characterId, characterName, gender)` | Get next number |
| `RankAssignment.renumberRankHolders(rankId)` | Renumber holders |
| `RankAssignment.fixAllNumberingForCharacter(characterId)` | Fix numbering for character |
| `RankAssignment.toOrdinal(n)` | Convert to ordinal (1st, 2nd, 3rd...) |
| `RankAssignment.toRoman(n)` | Convert to Roman numeral (I, II, III...) |
| `RankAssignment.generateSurnameFromRankRule(character, context)` | Generate surname from rule |
| `RankAssignment.updateRankSurnameRule(rankId, ruleSettings)` | Update surname rule |
| `RankAssignment.checkAndSpouseInheritance()` | Check spouse inheritance |
| `RankAssignment.applySpouseInheritanceFixes(fixes)` | Apply spouse inheritance fixes |

**Numbering Types:**
- `'reign'`: Numbered by reign (e.g., Henry I, Henry II, Henry III)
- `'birth'`: Numbered by birth order (e.g., 1st Duke, 2nd Duke, 3rd Duke)

**Surname Rule Context:**
```javascript
var context = {
    locationName: "Patagonia"  // The location name used in surname generation
};

// With connector "of", prefix "Mac", suffix "son":
// Result: "Macof Patagoniason" → "Macof Patagoniason"
// With connector "of" only:
// Result: "of Patagonia"
```

## Integration with Existing Systems

### Accessors Integration

The Rank System uses accessors.js for character lookups:
```javascript
// Inside rank-queries.js
function _getCharacters() {
    return typeof window.getCharacters === 'function' ? window.getCharacters() : [];
}

function _getCharacterById(id) {
    return typeof window.getCharacterById === 'function' ? window.getCharacterById(id) : null;
}
```

### Storage Integration

All rank data is stored in `masterData.data.ranks`:
```javascript
// In rank-state.js
window.masterData.data.ranks = _state.ranks.all;
window.masterData.data.rankInheritanceRules = _state.inheritanceRules;
_saveMasterData();
```

### Character Integration

Ranks are assigned to characters via `character.rankAssignments`:
```javascript
character.rankAssignments = [
    {
        rankId: 'rank_123',
        customTitle: null,
        number: { rawNumber: 1, display: 'I', type: 'roman' },
        isActive: true,
        isDeprecated: false,
        assignedYear: 1250,
        notes: 'Inherited from father'
    }
];
character.activeRankId = 'rank_123';  // Currently active rank
```

## Example Workflows

### 1. Creating a New Rank

```javascript
var result = RankCommands.createRank({
    name: 'Duke of Example',
    priority: 2,
    symbol: '◧',
    numbered: true,
    numberingType: 'reign',
    genderRestriction: 'either',
    customSurnameRule: true,
    surnameConnector: 'of'
});

if (result.success) {
    console.log('Rank created:', result.data);
} else {
    console.error('Failed:', result.error);
}
```

### 2. Assigning a Rank to a Character

```javascript
var result = RankCommands.assignRankToCharacter('char_123', 'rank_456', {
    notes: 'Appointed by king',
    assignedYear: 1250
});

if (result.success) {
    console.log('Rank assigned:', result.data.assignment);
}
```

### 3. Getting Rank Holder Statistics

```javascript
var stats = RankQueries.getRankHolderStats('rank_456');
console.log('Total holders:', stats.total);
console.log('Living:', stats.living);
console.log('Male:', stats.male);
console.log('Female:', stats.female);
```

### 4. Checking for Spouse Inheritance

```javascript
var fixes = RankAssignment.checkAndSpouseInheritance();
if (fixes.success && fixes.fixes.length > 0) {
    console.log('Found', fixes.fixes.length, 'spouse inheritance issues');
    
    var applied = RankAssignment.applySpouseInheritanceFixes(fixes.fixes);
    console.log('Applied', applied.applied, 'fixes');
}
```

### 5. Rebuilding All Rank Numbering

```javascript
var result = RankCommands.rebuildAllRankNumbering();
console.log('Fixed', result.totalFixed, 'numbering issues');
```

## Best Practices

1. **Always use RankCommands for writes** - Never modify rank data directly
2. **Always use RankQueries for reads** - Leverages caching for performance
3. **Subscribe to state changes** - Use `RankState.subscribe()` for reactive UI updates
4. **Validate before deletion** - Check for holders before deleting a rank
5. **Use bulk operations for multiple assignments** - More efficient than individual calls
6. **Handle errors properly** - All commands return `{ success, data, error }`

---

## Error Handling

All commands return a consistent result object:

```javascript
{
    success: true/false,
    data: { /* result data */ },  // Only if success
    error: 'Error message'         // Only if failure
}
```

**Common Errors:**
- `'Rank not found'` - Invalid rank ID
- `'Character not found'` - Invalid character ID
- `'Gender restriction does not match'` - Gender mismatch
- `'Character already has this rank'` - Duplicate assignment
- `'Cannot delete rank with X active holder(s)'` - Rank in use

## Example Workflows

### 1. Creating a New Rank

```javascript
var result = RankCommands.createRank({
    name: 'Duke of Example',
    priority: 2,
    symbol: '◧',
    numbered: true,
    numberingType: 'reign',
    genderRestriction: 'either',
    customSurnameRule: true,
    surnameConnector: 'of'
});

if (result.success) {
    console.log('Rank created:', result.data);
} else {
    console.error('Failed:', result.error);
}
```

### 2. Assigning a Rank to a Character

```javascript
var result = RankCommands.assignRankToCharacter('char_123', 'rank_456', {

});

if (result.success) {
    console.log('Rank assigned:', result.data.assignment);
}
```

```javascript
var stats = RankQueries.getRankHolderStats('rank_456');
console.log('Total holders:', stats.total);
```

```javascript
var fixes = RankAssignment.checkAndSpouseInheritance();
```

```javascript
var result = RankCommands.rebuildAllRankNumbering();
```

## Best Practices

1. **Always use RankCommands for writes** - Never modify rank data directly
2. **Always use RankQueries for reads** - Leverages caching for performance
3. **Subscribe to state changes** - Use `RankState.subscribe()` for reactive UI updates
4. **Validate before deletion** - Check for holders before deleting a rank
5. **Use bulk operations for multiple assignments** - More efficient than individual calls
6. **Handle errors properly** - All commands return `{ success, data, error }`

---

## Error Handling

All commands return a consistent result object:

```javascript
{
    success: true/false,
    data: { /* result data */ },  // Only if success
    error: 'Error message'         // Only if failure
}
```

**Common Errors:**
- `'Rank not found'` - Invalid rank ID
- `'Character not found'` - Invalid character ID
- `'Gender restriction does not match'` - Gender mismatch
- `'Character already has this rank'` - Duplicate assignment
- `'Cannot delete rank with X active holder(s)'` - Rank in use
