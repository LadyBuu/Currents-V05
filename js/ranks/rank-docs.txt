================================================================================
PART 1 — FILE INVENTORY AND LAYERS
================================================================================

The rank subsystem follows the same strict layer chain as the reference
subsystems (location, settlement, government, religion):

  CONSTANTS (no deps)
    js/core/rank/rank-constants.js

  RULES (pure policy; depends on constants at call time)
    js/core/rank/rank-rules.js

  STATE (owns canonical catalogue + derived indexes)
    js/core/rank/rank-state.js

  QUERIES (read-only; composes State + CharacterState + FamilyQueries +
           RomanceQueries)
    js/core/rank/rank-queries.js

  ASSIGNMENT (numbering arithmetic + spouse-inheritance detection;
              pure except for CharacterCommands writes)
    js/core/rank/rank-assignment.js

  COMMANDS (writes via State primitives + CharacterCommands; the only
            saveMasterData site)
    js/core/rank/rank-commands.js

  ISSUES (detection + fix closures; annual pipeline; death hook;
          hard-delete cleanup)
    js/core/rank/rank-issues.js

  UI LIST (DOM rendering; consumes queries)
    js/core/rank/rank-ui-list.js

  MODALS (DOM + commands; one persist per successful action)
    js/core/rank/modals-rank.js

  BOOTSTRAP (load-time verification + hydration + namespace)
    js/core/rank/rank-bootstrap.js

PART 2 — DEPENDENCIES

Terminology:
  REQUIRED (load-time)  — a module-level guard throws if the
                          dependency is missing when this file loads.
  REQUIRED (call-time)  — a function throws/refuses if the dependency
                          is missing when invoked; the module loads
                          without it.
  OPTIONAL              — the module checks and falls back.

Cross-domain references are labeled with their subsystem:
  [core]        js/core/...

2.1 CONSTANTS — rank-constants.js
--------------------------------------------------------------------------------

  js/core/rank/rank-constants.js
    Owns: window.RANK_LEVELS, window.AVAILABLE_SYMBOLS,
          window.DEFAULT_RANK, window.INHERITANCE_SOURCE,
          window.NUMBERING_TYPE, window.NUMBERING_GROUP,
          window.RankConstants (container).
    Load-time dependencies: NONE. Pure vocabulary + internal
      consistency check at load (_validate()).
    Call-time dependencies:  NONE.
    Consumed by (load-time):
      [load] rank-rules.js        (RANK_LEVELS, AVAILABLE_SYMBOLS,
                                   INHERITANCE_SOURCE, NUMBERING_GROUP,
                                   DEFAULT_RANK — read via window.*
                                   at call time inside rank-rules.js)
      [load] rank-queries.js      (RANK_LEVELS, AVAILABLE_SYMBOLS —
                                   both are HARD LOAD-TIME GUARDS;
                                   missing -> throw)
      [load] modals-rank.js       (RANK_LEVELS, AVAILABLE_SYMBOLS,
                                   DEFAULT_RANK, NUMBERING_TYPE,
                                   NUMBERING_GROUP, INHERITANCE_SOURCE —
                                   all in the REQUIRED block; missing
                                   -> throw)
      [load] rank-bootstrap.js    (RANK_LEVELS verified in
                                   REQUIRED_GLOBALS; missing -> init()
                                   throws)
    Notes:
      - RANK_LEVELS entries carry only { name, description }. No
        icon field. Level icons come from icons.js via
        window.getRankLevelIcon(priority). RankQueries
        .getRankLevelIcon routes to it.
      - The module runs a load-time _validate() check that throws if:
          * any priority key is not an integer in 1..10
          * any level has no name or description
          * AVAILABLE_SYMBOLS is empty, contains duplicates, or
            contains any code point in the emoji ranges (regional
            indicators, emoticons, transport/map symbols, skin tone
            modifiers, ZWJ, VS16, etc.)
          * NUMBERING_TYPE / NUMBERING_GROUP / INHERITANCE_SOURCE
            do not match the expected sets
          * DEFAULT_RANK is incoherent (inheritanceSource not 'none',
            sourceRankId not null, parentRankId not null, symbol not
            in AVAILABLE_SYMBOLS, priority out of range)
      - spouseInheritance on DEFAULT_RANK is legacy (null by
        default). New ranks use inheritanceSource + sourceRankId.

2.3 STATE — rank-state.js
--------------------------------------------------------------------------------

  js/core/rank/rank-state.js
    Owns: window.RankState (collision guard: __owner ===
      'core/rank/rank-state.js'; another module claiming the name
      throws).
    Load-time dependencies: NONE at parse. No load-time guard against
      window.masterData or window.markDataDirty; both are checked at
      hydrate/mutation time.
    Call-time dependencies (all via window.X):
      window.masterData              [core] via storage.js — read on
                                     hydrate; write target for the
                                     in-memory sync
      window.markDataDirty           [core] via storage.js — called by
                                     every mutation primitive
      window.invalidateAccessorCaches [core] via accessors.js —
                                     typeof-guarded; called at every
                                     mutation and at hydration
      window.RankRules.applyDefaults [core] via rank-rules.js —
                                     production path of _normaliseRank;
                                     fallback is _normaliseRankFallback
      window.addEventListener       browser — listens for
                                     masterDataUpdated for cross-tab
                                     reload
    Consumed by:
      [load] rank-queries.js     (every read: getRank, getAllRanks,
                                  getRanksByPriority, getRankHierarchy,
                                  getRankCount, getInheritanceRules,
                                  getInheritanceRulesForRank,
                                  hydrateFromMasterData, isHydrated)
      [load] rank-assignment.js  (getRank, getAllRanks, getAllRanks
                                  for enumeration)
      [load] rank-commands.js    (getRank, getAllRanks, getAllRanks,
                                  _addRank, _updateRank, _removeRank,
                                  _addInheritanceRule,
                                  _removeInheritanceRule,
                                  _setInheritanceRules,
                                  _getRankCanonical not called here)
      [load] rank-issues.js      (getRank)
      [load] rank-ui-list.js     (imported as RS for surface presence;
                                  the actual read path goes through
                                  RankQueries)
      [load] rank-bootstrap.js   (hydrateFromMasterData,
                                  getRankCount, validateIntegrity,
                                  isHydrated)
    Notes:
      - ACCESSOR CACHE CONTRACT — THREE BOUNDARIES:
          1. Mutation boundary: every mutation primitive calls
             _syncToMasterData, which calls _invalidateAccessorCaches
             (typeof-guarded) then _markDataDirty.
          2. Hydration boundary: hydrateFromMasterData calls
             _invalidateAccessorCaches at the end, because the cache
             mirrors masterData.data.ranks which was just replaced.
          3. Cross-tab reload: storage.js invalidates BEFORE
             dispatching masterDataUpdated (see stillwaters-docs.txt
             §3.1). RankState's own masterDataUpdated handler calls
             hydrateFromMasterData, which invalidates again —
             redundant but harmless.
      - PUBLIC READS RETURN CLONES. The clone helper copies arrays
        by slice and plain objects by Object.assign; nested arrays of
        objects on rank records are rare and none currently exist
        on the canonical shape. getRankHierarchy builds each node's
        children array fresh on every call, so a caller that mutates
        a returned node does not corrupt the catalogue.
      - CANONICAL ACCESS is _getRankCanonical / _getAllRanksCanonical,
        reserved for RankCommands. No other caller may use them.
      - hydrateFromMasterData THROWS on:
          * missing masterData
          * non-array ranks
          * non-plain-object inheritanceRules (null/undefined is OK
            and coerced to {})
          * duplicate rank ids
          * a rank record with no id
        It does NOT throw on semantic incoherence
        (sourceRankId w/ inheritanceSource 'none'); that is preserved
        and reported by validateIntegrity.
      - validateIntegrity is GRAPH CONSISTENCY only. Semantic
        incoherence is not flagged here; it is flagged by
        RankRules.validate.
      - Facade compatibility surface: rankCollapsedGroups (get/set)
        and reset(). Backed by an internal _rankCollapsedGroups map
        that is session-only, not persisted, not notified.

          renderRankCard / renderRankStatistics
                                          -> string | null
        (HTML on success; null when the rank is missing or the
        container is invalid. The card and stats renderers accept
        an optional container; when omitted they return HTML, when
        provided they write it and return it. Both return null on
        failure.)
      - DELEGATED CLICK HANDLING: one click listener per container,
        tracked via a WeakMap. On re-render, the previous listener
        is removed before installing a fresh one. No stacking.
      - CONTAINER REGISTRY: registerContainer(id, kind, options)
        registers a container for refreshAll(). Kinds: 'list',
        'hierarchy', 'tree', 'selector', 'card', 'stats'.
        refreshAll() prunes containers whose elements are no longer
        in the document.
      - DEFAULT ACTION MAP: 'details' and 'edit' open the
        corresponding RankModals function when present. 'select'
        is a no-op (callers override it).

Each invariant names the failure mode it prevents.

     ("RANK_LEVELS missing"); modals-rank.js throws at load

     throws ("RANK_LEVELS required").

     RankRules.applyDefaults / formatNumber / classifyNumberingGroup

================================================================================
PART 7 — KNOWN HAZARDS
================================================================================

 1.  getCurrentYear vs getCurrentYearSafe.
     Rank uses getCurrentYear throughout. Government uses
     getCurrentYearSafe (deprecated alias). Do not substitute.
     rank-bootstrap.js verifies getCurrentYear and does not verify
     the alias.

 2.  RANK_LEVELS vs getRankLevelIcon split.
     RANK_LEVELS entries carry only { name, description }. Icons
     come from icons.js via window.getRankLevelIcon(priority).
     RankQueries.getRankLevelIcon delegates to it. There is no
     icon field on RANK_LEVELS entries. Do not reintroduce a glyph
     field; the SVG is icons.js-owned.

 3.  Hierarchy CSS contract.
     rank-ui-list.js::_renderHierarchyNode emits
     data-depth="N" on .rank-hierarchy-node and relies on CSS for
     the pixel values. Without the following rules the hierarchy
     renders flat:

       .rank-hierarchy-node[data-depth="0"] { padding-left: 0; }
       .rank-hierarchy-node[data-depth="1"] { padding-left: 20px; }
       .rank-hierarchy-node[data-depth="2"] { padding-left: 40px; }
       .rank-hierarchy-node[data-depth="3"] { padding-left: 60px; }
       .rank-hierarchy-node[data-depth="4"] { padding-left: 80px; }

     If deeper hierarchies are needed, use a CSS variable approach
     (rank-doc.md §13 documents the calc(var(--rank-depth, 0) * 20px)
     form) or extend the rules.

 4.  modals-rank.js inline styles.
     The modals use inline style attributes for layout. This is a
     documented deferral. Do not assume the modals are CSS-only. See
     rank-doc.md §17 and the file's own header INLINE STYLES
     section.

 5.  Modal callback API.
     Every callback (onMount, onOpen, onConfirm, onCancel) receives
     the modal DOM element as its ONLY argument. Do NOT read
     `modal.element` — that is the old handle shape and was the
     Phase 8.1 fix. The DOM element is the root for
     root.querySelector scoped reads.

 6.  Modal input reads.
     Every input is read via root.querySelector('#id'), NOT
     document.getElementById. The latter collides when two rank
     modals are open simultaneously. Two open create-rank modals
     would otherwise both read the first modal's inputs.

 7.  options shadowing in modals-rank.js.
     openAssignRankModal's onConfirm declared `var options = {...}`
     in a previous revision, shadowing the function parameter. The
     phase 8 fix renamed the local to `assignOptions`. Do not
     reintroduce a local named `options` inside a callback that
     also reads the outer `options` parameter.

 8.  RankCommands.persist — Pattern A.
     persist() inspects the boolean return from saveMasterData()
     and, on false, reads getLastSaveError().message for the
     actual failure reason. It does NOT assume saveMasterData()
     throws. Pattern C (discard the return, report success) must
     not be reintroduced.

 9.  One persist per batch.
     Every mutation in the rank domain goes through
     RankState._syncToMasterData -> markDataDirty. The explicit
     flush is RankCommands.persist(). Batch callers (annual
     pipeline, modals, external orchestrators) call persist() once
     per batch. Adding a second persist() inside a command body
     would produce two saveMasterData calls for a single logical
     mutation.

 10. Accessor cache staleness.
     rank-state.js invalidates the accessor cache on every
     mutation and on hydration. If a caller writes to
     masterData.data.ranks directly (bypassing RankState), the
     cache goes stale silently. Do not write to
     masterData.data.ranks outside RankState's mutation
     primitives.

 11. FamilyQueries required vs RomanceQueries optional.
     FamilyQueries.getParents is REQUIRED at bootstrap time
     (parent inheritance is a first-class feature). RomanceQueries
     is OPTIONAL (spouse inheritance is a rank configuration, not
     a core feature). Do not promote RomanceQueries to required
     without updating rank-doc.md §16 and the corresponding
     rank-bootstrap.js classification.

 12. Spouse inheritance scan duplication.
     RankIssues._checkSpouseInheritance and
     RankAssignment.checkAndFixSpouseInheritance scan the same
     condition but return different shapes (RankIssue with fix
     closure vs fix-data records). They are intentionally not
     consolidated. See rank-doc.md §17. Do not "simplify" by
     collapsing one into the other; that would either introduce a
     RankCommands -> RankIssues dependency or duplicate the
     classification logic.

 13. Delegated helpers are canonical.
     RankQueries.getParentIds, RankQueries.getChildIds, and
     RankAssignment.getHolderGroupKey are the SINGLE
     implementations. rank-assignment.js and rank-issues.js
     delegate. Do not reintroduce inline normalisers in those two
     files; drift would cause "predict what renumber will produce"
     and "produce it" to disagree.

 14. numberingGroup 'source' requires inheritanceSource !== 'none'.
     RankRules.validate rejects a numbered rank with group 'source'
     and no inheritance source. RankRules.canAssignRank rejects an
     assignment to such a rank. The check exists in both places
     because a rank can become incoherent through a patch that
     bypasses canAssignRank.

 15. Death hook dispatch is direct.
     CharacterLifecycle.killCharacter must call
     RankIssues.handleCharacterDeath directly.
     CharacterDeletionCommands.deleteCharacter must call
     RankIssues.removeAllReferencesTo directly. There is no
     listener registry and no registerLifecycleHook mechanism.
     Callers that skip these calls leave a dead character's
     deprecate-on-death ranks un-deprecated and a deleted
     character's inheritedFrom pointers dangling.

 16. deprecateRanksOnDeath does not persist.
     The death cascade's orchestrator (usually
     CharacterLifecycle.advanceMortality) persists once at the end
     of the cascade. RankCommands.deprecateRanksOnDeath mutates
     state and renumbers but does not call saveMasterData.

 17. removeAllReferencesTo does not persist.
     Same story as (16). CharacterDeletionCommands is the
     orchestrator; it persists once after every cleanup step.

 18. rankCollapsedGroups is session state, not persisted.
     RankState.rankCollapsedGroups and RankState.reset are facade
     compatibility surfaces backed by an internal map. They are
     not in masterData and not in localStorage. Do not add
     persistence to them without changing the state contract.

 19. hydrateFromMasterData does NOT call markDataDirty.
     Hydration is a read from storage, not a mutation. It reflects
     the normalised catalogue back into masterData.data.ranks but
     does NOT mark dirty. A reload path that relies on the
     normalisation to be persisted must call markDataDirty
     explicitly, or call RankCommands.persist after a mutating
     operation.

 20. validateIntegrity is not policy validation.
     validateIntegrity checks graph consistency (id presence,
     duplicate ids, priority range, parent / source reference
     resolution, self-parent, self-source, inheritance rule
     references). It does NOT check semantic incoherence
     (sourceRankId with inheritanceSource 'none',
     numbered+group 'source' with no source, empty surname rule
     with customSurnameRule true). Semantic incoherence is
     preserved by _normaliseRank and flagged by
     RankRules.validate. Do not add policy checks to
     validateIntegrity.

 21. Modals are presentation.
     modals-rank.js does not write masterData directly. Every
     write goes through RankCommands. The modal calls persist()
     exactly once per successful write. The death hook is not a
     modal concern.

 22. Inline character picker.
     openAssignRankModal uses a local picker. There is no
     dependency on modals-char-selector.js. Do not reintroduce a
     dependency on a character selector modal; the inline picker
     is the documented design.

 23. DEFAULT_SYMBOL is derived from window.DEFAULT_RANK.symbol.
     modals-rank.js derives DEFAULT_SYMBOL at load. The prior
     hardcoded '⟡' is removed. A change to DEFAULT_RANK.symbol
     in rank-constants.js propagates to the modals without a code
     change.

 24. Priority fallback removed.
     _buildPriorityOptions reads priority keys directly from
     window.RANK_LEVELS. The prior [1, 2, 3, 4, 5] fallback is
     removed; RANK_LEVELS is required at load. Do not reintroduce
     a hardcoded fallback.

 25. Enum dropdowns read from constants.
     _buildNumberingTypeOptions, _buildNumberingGroupOptions, and
     _buildInheritanceSourceOptions read window.NUMBERING_TYPE,
     window.NUMBERING_GROUP, and window.INHERITANCE_SOURCE. The
     fallback default-value objects in those builders are
     defensive; the production path uses the constants. Do not
     hardcode the enum literals in the option lists.

 26. Return-value contract of rank-ui-list.js.
     renderRankList / renderRankHierarchy / renderRankTree /
     renderRankSelector return boolean. renderRankCard /
     renderRankStatistics return string | null. The Phase 7 fix
     normalized renderRankStatistics; do not reintroduce the old
     false | string | true shape.

 27. Delegated click handling.
     rank-ui-list.js tracks one click listener per container in
     a WeakMap. On re-render, the previous listener is removed
     before installing a fresh one. Do not switch to a
     document-level delegated handler or to a per-row
     addEventListener; both regress the refresh cost and the
     listener-stacking guarantee.

 28. rank-docs.txt is obsolete.
     The rank subsystem's own narrative doc is rank-doc.md (the
     v3.1 replacement). The older rank-docs.txt describes the
     pre-refactor state and should not be cited. This document
     (this file) is the dependency-and-load-order companion to
     rank-doc.md and follows the same Phase 0-9 code deliveries.
