# Still Waters — Character Subsystem Documentation

**Version 2.0**

**Covers:** character, family, children, mortality, UI state

**Status:** character subsystem complete. Relationships and professional domains not yet rebuilt.

---

## 1. System Overview

The character subsystem manages:

- Canonical character records
- Biological, legal, and social parentage
- Kinship classification
- Pregnancy, birth, surrogacy, and adoption metadata
- Death, murder, and execution
- Population, family, children, and mortality statistics
- Panel UI state persistence
- UI modals for character CRUD, family view, death, birth, surrogacy, and adoption

Five architectural rules govern the whole system:

1. **One owner per concept.** Character record → `CharacterState`. Parent edges → `FamilyState`. Pregnancy, surrogacy, adoption records → `ChildrenState`. Death fields → on the character record, written only by `CharacterCommands.markDeceased`.

2. **Rules are pure.** `-rules.js` modules contain no I/O, no randomness, no mutation, no state access.

3. **Reads and writes are separate.** `-queries.js` reads, `-commands.js` writes. A query never mutates.

4. **Dependencies fail loudly.** Missing modules throw at load. Missing data returns null or []. Invalid input throws.

5. **Randomness is injected.** No rules module generates random numbers. Rolls are passed in by the caller.

## 4. Module Reference

### 4.1 `character-state.js`

**Owns:** canonical runtime character collection.

**Provides:** derived indexes, subscriptions, cache rebuild, low-level character-owned mutation primitives, internal live-reference access for authorized code.

**Public reads** (projections only): `getAllCharacters`, `getTotalCharacterCount`, `getCharacter`, `getCharacterId`, `hasCharacter`, `getCharactersByCurrentLocation`, `getCharactersByBirthplace`, `getCharactersByHousehold`, `getCharactersByStatus`, `getLivingCharacters`, `getDeceasedCharacters`, `getCharactersByGender`, `getCharactersByProfession`, `getCharactersByRank`, `getCharactersByBirthDecade`, `getCharactersByReligion`, `getCharactersByCulture`, `searchByName`.

**Public writes:** `updateCharacter`, `updateCharacters`, `applyDomainFieldPatch`, `addCharacter`, `addCharacters`, `removeCharacter`, `removeCharacters`.

**Internal:** `_getLiveCharacterForMutation(id)` — reserved for `CharacterCommands`, `FamilyCommands`, `ChildrenCommands`, `CharacterLifecycle`.

**Events:** dispatches `characterChanged`; listens for `characterChanged` and `masterDataUpdated`.

**Persistence:** `markDataDirty`.

---

### 4.2 `character-factory.js`

**Owns:** canonical character record construction.

**Public:** `buildCharacter(data, options)` → `{ success, data?, reason? }`.

`options.currentYear` is required when `data.birthYear` is omitted. Domain-owned fields are always constructed in their neutral empty state and never accepted from the caller: `professions`, `rankAssignments`, `relationships`, `friends`, `apprentices`. Parent fields are not part of the record.

---

### 4.3 `character-commands.js`

**Owns:** character-owned mutations.

**Field updates:** `updateCharacterFields(id, patch)`, `updateCharactersFields(changes)`, `updateCharacter` (alias).

`updateCharacterFields` refuses fields owned by other domains: `professions`, `rankAssignments`, `relationships`, `friends`, `apprenticeshipDetails`, `apprentices`, `isDeleted`, `deletedAt`.

**Death:** `markDeceased(id, deathData)` — the single canonical writer of `isDeceased` and associated fields. Validated through `MortalityRules.validateDeath`. Dispatches no family cleanup; the caller does (`CharacterLifecycle.killCharacter`).

**Professions:** `getProfession`, `getProfessions`, `addProfession`, `updateProfession`, `removeProfession`, `removeProfessionFromAll`, `replaceProfessions`, `setPrimaryProfession`, `clearPrimaryProfession`.

**Surname:** `recordCharacterSurnameChange`, `revertCharacterSurnameChange`.

**Religion:** `assignCharacterReligion`, `removeCharacterReligion` (delegate to `ReligionCommands`).

---

### 4.4 `character-queries.js`

**Owns:** semantic character reads.

**Search and lookup:** `searchCharacters`, `readCharactersByName`, `getAllCharacters`, `getCharacter`, `getCharacterDisplayName`, `getCurrentLocationId`, `getCharactersInLocations`.

**Age:** `getCharactersByAgeRange(minAge, maxAge, includeDeceased)`.

**Projections:** `getCharacterSummary`, `getCharacterFacts`, `getAllCharacterFacts`, `getCharacterIdentityFacts`.

**Family delegates:** `getCharacterChildren`, `getCharacterParents`, `getCharacterSiblings`, `getCharacterGrandparents`, `getCharacterGrandchildren`, `getCharacterKinship`, `getCharacterKinshipCloseness`.

**Profession delegates:** `getCharacterProfessions`, `getPrimaryProfession`.

---

### 4.5 `character-creation-commands.js`

**Owns:** creation boundary.

**Public:** `createCharacter`, `createCharacterFromData`, `createRandomCharacter`, `bulkCreateCharacters`.

Creation sequence: build → `CharacterState.addCharacter` → `FamilyCommands.setParent` for `options.parents` → `ReligionCommands.assignReligionToCharacter` (non-fatal). Rollback on family or religion failure.

Parent edges are passed as `options.parents`: an array of `{ parentId, parentRole?, parentType? }`.

---

### 4.6 `character-deletion-commands.js`

**Owns:** deletion boundary.

**Public:** `deleteCharacter`, `softDeleteCharacter`, `restoreSoftDeletedCharacter`, `purgeSoftDeletedCharacters`, `bulkDeleteCharacters`, `getSoftDeletedCharacters`.

Hard delete dispatches cleanup to: `FamilyCommands`, `ChildrenCommands`, `RelationshipCommands`, `HouseholdCommands`, `WorldCommands`, `RankCommands`, `ApprenticeshipCommands` — each called only if the module and method exist.

---

### 4.7 `character-generator.js`

**Owns:** random character data proposals.

**Public:** `generateRandomCharacterData(options)`. Produces character-owned input fields only. Nothing about family, relationships, or domain records.

---

### 4.8 `character-statistics.js`

**Owns:** population aggregation.

**Public:** `getCharacterStatistics`, `getAgeDistribution`, `getGenderDistribution`, `getHouseholdDistribution`, `getProfessionDistribution`, `getRankDistribution`, `getReligionDistribution`, `getCultureDistribution`, `getLiteracyStatistics(predicate)`.

---

### 4.9 `character-lifecycle.js`

**Owns:** age classification, time progression, death commands, lifespan estimation.

**Age classification:** `getLifeStage`, `getLifeStageName`, `getAgeGroup`, `getAllAgeGroups`, `getAgeGroupIndex`, `isElderly`, `groupCharactersByAgeGroup`.

**Time:** `advanceMortality(yearsAdvanced, options)`. Evaluates per year. Falls back to `MortalityRules.getDefaultMortalityRate(age)` when `getMortalityRate` is not supplied. Falls back to `MortalityRules.pickRandomCause` when `chooseDeathCause` is not supplied.

**Death:** `killCharacter(id, deathData)`, `killCharacterRandomCause(id, options)`, `triggerNaturalDeath(id, options)`, `triggerAccidentalDeath(id, options)`.

**Lifespan:** `predictLifespan`, `getExpectedRemainingYears`. Deterministic.

### 4.12 `family-rules.js`

**Owns:** parentage policy, kinship policy, cycle policy, adoption validation.

**Vocabulary:** parent types `biological | legal | social`; parent roles `father | mother | parent`; sibling types `full | half | step | adoptive`; kinship types `self`, `parent`, `child`, `sibling`, `grandparent`, `grandchild`, `great_grandparent`, `great_grandchild`, `aunt_uncle`, `niece_nephew`, `cousin`, `unrelated`.

## 6. Ownership Map

| Concept | Owner | Readers |
|---|---|---|
| Character record | `CharacterState` | `CharacterQueries` (projections) |
| Death fields on the record | `CharacterCommands.markDeceased` | `MortalityQueries`, `CharacterQueries` |
| Parent-child edges | `FamilyState` | `FamilyQueries` |
| Parentage meaning | `FamilyRules` | `FamilyCommands`, `FamilyQueries` |
| Kinship classification | `FamilyRules` | `FamilyQueries` |
| Pregnancy records | `ChildrenState` | `ChildrenQueries` |
| Surrogacy arrangements | `ChildrenState` | `ChildrenQueries` |
| Adoption metadata | `ChildrenState` | `ChildrenQueries` |
| Fertility and pregnancy policy | `ChildrenRules` | `ChildrenCommands` |
| Mortality policy | `MortalityRules` | `CharacterLifecycle`, `MortalityQueries` |
| Panel UI state | `UIState` | panels |

Only `CharacterCommands`, `CharacterCreationCommands`, `CharacterDeletionCommands`, and `CharacterLifecycle` write to character state. `FamilyCommands` writes parent-child edges. `ChildrenCommands` writes pregnancy, surrogacy, and adoption records, and reaches into character state only through `CharacterCreationCommands` and `CharacterCommands`.

## 7. Semantic Contracts

**Reads** return fresh projections. Callers cannot mutate state through a returned object.

**Return values:**

- Singular: `T | null`
- Collections: `T[]`
- Commands: `{ success, reason?, ... }`
- Rules: `{ valid, errors?, value? }`

**Missing data:** `null` or `[]`. Invalid explicit input: `throw`. Year 0 is preserved.

**Randomness:** no rules module draws random numbers.

**Persistence:** state modules write to `masterData`, then `markDataDirty`. Only storage flushes.

**Events:** `characterChanged`, `familyChanged`, `childrenChanged`, `masterDataUpdated`.

---

## 8. Deletion and Lifecycle Semantics

**Soft delete:** sets `isDeleted` and `deletedAt`. Orthogonal to death. Hidden from normal queries.

**Hard delete:** removes the record, then dispatches cross-domain cleanup.

**Restore:** clears `isDeleted`, `deletedAt`.

**Purge:** hard-deletes every soft-deleted character.

**Death via `CharacterLifecycle.killCharacter`:** validates through `MortalityRules`, calls `CharacterCommands.markDeceased`, dispatches `FamilyCommands.handleCharacterDeath`.

**Death via `CharacterCommands.markDeceased`:** validates through `MortalityRules`, writes the record, does not dispatch family cleanup. Reserved for cases where the death is part of a wider transaction, e.g. maternal death inside `ChildrenCommands.recordPregnancyAttempt`.

**Childbed fever:** not offered by the general death modal. Recorded through the pregnancy attempt transaction. Death modal routes to `openPregnancyAttemptModal` with death flow hints.

## 9. What Was Removed

### Relationship domain

Files: `relationship-state.js`, `relationship-queries.js`, `relationship-commands.js`, `relationship-rules.js`, `relationship-types.js`, `relationship-ui-metadata.js`, `relationships-bootstrap.js`, `relationship-docs.txt`, `relationship-finder-queries.js`, `relationship-finder.js`, `modals-relationship.js`, `modals-family.js`, `modals-friendship.js`, `romance-*`, `friendship-*`, `jealousy-*`, `affair-*`, `matchmaking-*`, `professional-*`.

Capabilities removed: romance, friendship, rivalry, enmity, jealousy, affairs, matchmaking, professional relationships, relationship finder.

### Mortality legacy

Files: `mortality-state.js`, `mortality-commands.js` (old), `mortality-queries.js` (old), `mortality-docs.txt`.

Behavior removed: direct death-field writes outside `markDeceased`; `1250` year fallback; `deathCause || 'Unknown'` coercion; `_processing` recursion guards.

### Children legacy

Files: `children-state.js` (old), `children-commands.js` (old), `children-queries.js` (old), `children-lifecycle.js`, `pregnancy-service.js`, `surrogacy-service.js`, `adoption-service.js`, `modals-adoption.js`, `modals-birth.js`, `modals-surrogacy.js`, `children-docs.txt`.

Behavior removed: parallel parent-setting, parallel family queries, `_processing` guards.

### Legitimacy

Deliberately removed. `canLegitimize`, `legitimizeChild`, `openLegitimizationModal`, and the character fields `isLegitimate`, `legitimization`, `legitimizedYear`, `inheritanceRights` are not present as policy. `isLegitimate` exists as a character field but no command writes it.

### Other

Silent childbirth age correction: removed. Murder/execution auto-consequence: removed.

## 10. What Is Not Implemented

### Requires new domains

- Relationship domain (romance, friendship, rivalry, jealousy, affairs, matchmaking, professional relationships)
- Succession and inheritance
- Justice (auto-execution of murderers)
- Education (literacy, enrollment, graduation)
- Groups (dropped by decision unless requested)
- Legitimacy (dropped by decision)

### Small additions when required
