## 1. System Overview

The character subsystem manages:

- The canonical character record and its lifecycle
- Family relationships (biological, legal, social parentage)
- Kinship classification
- Mortality (death, murder, execution)
- Children (birth, pregnancy, surrogacy, adoption metadata)
- Population, family, mortality, and children statistics
- UI modals for all of the above

The system is designed around four fixed principles:

1. **One canonical owner per concept.** Character data lives in `CharacterState`. Parent-child edges live in `FamilyState`. Pregnancy, surrogacy, and adoption metadata live in `ChildrenState`. Death fields live on the character record. Nothing is duplicated.

2. **Rules are pure.** Modules whose names end in `-rules.js` contain no I/O, no randomness, no mutation, no state access. They receive facts and return decisions.

3. **Reads and writes are separate.** Modules whose names end in `-queries.js` only read. Modules whose names end in `-commands.js` only write. A query never mutates. A command never computes a projection for presentation.

4. **Dependencies fail loudly.** Missing modules throw at load. Missing data returns `null` or `[]`. Invalid input throws. Nothing is fabricated.

---

## 2. Architectural Principles

### 2.1 Ownership

Every field on the character record is owned by exactly one module. The owner is the only module that may write it. Other modules may read it through the canonical read surface.

### 2.2 Composition over duplication

If a module needs information owned by another module, it calls the owner's query function. It does not reimplement the logic.

### 2.3 Injected randomness

No rules module generates random numbers. All randomness is drawn by the caller and passed in as a roll or a collection of rolls. This makes rules deterministic and testable.

### 2.4 Transactional writes

A single logical mutation has a single transaction owner. In practice this means:

- One command call → one persistence commit → one event.
- Multi-step operations (birth + parent edges + religion inheritance + pregnancy record) validate everything before any write, and roll back on failure.

### 2.5 No fallbacks

A missing dependency is a broken application, not a feature to degrade around. `_requireDependencies` at the top of every module throws when required modules are absent.

### 2.6 No fabricated data

- Missing character → `null`.
- Missing collection → `[]`.
- Invalid explicit input → `throw`.
- Year 0 is preserved.
- Empty strings and `0` are legitimate values.

| `getLivingCharacters()` | Array |

| `getCharactersByRank(rankId)` | Array |

| `getCharactersByReligion(religionId)` | Array |
| `getCharactersByCulture(cultureId)` | Array |

**Public write primitives:**

| Function | Effect |
|---|---|
| `updateCharacter(id, patch)` | Character-owned field patch. Shallow merge. |

**Internal:**

- `_getLiveCharacterForMutation(id)` — returns the live canonical object. Reserved for `CharacterCommands`, `FamilyCommands`, `ChildrenCommands`, and `CharacterLifecycle`.

**Events:**

- Dispatches `characterChanged` with `{ action, characterIds }` on every write.
- Listens for `characterChanged` and `masterDataUpdated`.

**Persistence:** Calls `window.markDataDirty()`. Never calls `saveMasterData`. Storage decides when to flush.

## 7. Character Factory

**File:** `js/character/character-factory.js`

**Ownership:** Construction of the canonical character record.

**Public API:**

```
buildCharacter(data, options) → { success, data?, reason? }
```

**Input validation:**

- `name` is required, trimmed, ≤ 100 chars.
- `gender` ∈ `male | female | unknown`.
- `attraction` ∈ `both | men | women | neither | unknown`.
- `surnameSource` ∈ `country | cultural | inherited | custom | none`.
- Year fields validated through `isValidYear`.
- Unknown input fields are ignored.

**Cross-field invariants:**

- A deceased character must have a `deathYear`.
- A living character must not have a `deathYear`.
- `deathYear` must not be before `birthYear`.

**Options:**

- `options.currentYear` is required when `data.birthYear` is omitted.

**Defaults:**

- `birthYear` defaults to `options.currentYear`.
- `surnameSource` defaults to `custom`.
- `gender` defaults to `unknown`.
- `attraction` defaults to `both`.
- `isLegitimate` defaults to `true`.

**Domain-owned fields constructed empty:**

`professions`, `rankAssignments`, `relationships`, `friends`, `apprentices`.

**Removed fields (not part of the record):**

`motherId`, `fatherId`, `children`, `adoptedParents`, `adoptedChildren`.

Parent edges are established after creation through `FamilyCommands.setParent`.

## 10. Character Creation Commands

**File:** `js/character/character-creation-commands.js`

**Ownership:** Creation boundary.

**Public API:**

| Function | Purpose |
|---|---|
| `createCharacter(data, options)` | Build, insert, establish family and religion edges. |
| `createCharacterFromData(built)` | Insert an already-built record. |
| `createRandomCharacter(options)` | Generate, build, insert. |
| `bulkCreateCharacters(array, options)` | Batch variant. |

**Composition:**

1. `buildCharacter(data, { currentYear })`
2. `CharacterState.addCharacter(built)`
3. `FamilyCommands.setParent` for every parent in `options.parents`
4. `ReligionCommands.assignReligionToCharacter` if applicable (non-fatal)

**Parent edges:**

Parents are passed as `options.parents`, an array of `{ parentId, parentRole?, parentType? }`. Defaults: `parentType = 'biological'`, `parentRole` inferred from gender.

**Rollback:** if family or religion establishment fails, the character is removed from `CharacterState` and the operation returns a structured failure.

## 12. Character Generator

**File:** `js/character/character-generator.js`

**Ownership:** Random character data proposals.

**Public API:**

```
generateRandomCharacterData(options) → { success, data?, reason? }
```

**Options:**

`gender`, `age`, `countryId`, `religionId`, `assignProfession`.

**Output:** character-owned input fields only. No parent edges, no family, no relationship records. The caller passes the proposal to `CharacterCreationCommands.createCharacter`.

**Age bands:** explicit `{ min, max, weight }`. No shared boundaries.

**Profession `startYear`:** placed within `[birthYear + MIN_PROFESSION_AGE, currentYear]`.

## 18. Family State

**File:** `js/character/family-state.js`

**Ownership:** Canonical parent-child edge collection.

**Storage key:** `masterData.data.parentChildEdges`.

**Edge shape:**

```
{
    id:          string,          unique
    parentId:    string,          character id
    childId:     string,          character id
    parentType:  'biological' | 'legal' | 'social',
    parentRole:  'father' | 'mother' | 'parent',
    startYear:   number | null,
    endYear:     number | null,
    status:      'ongoing' | 'ended',
    notes:       string,
    createdAt:   number,
    updatedAt:   number
}
```

**Indexes:** by id, by parent, by child, by pair.

**Public API:**

| Function | Purpose |
|---|---|
| `isInitialized()` | Boolean. |
| `snapshot()` | Deep copy of every edge. |
| `replaceAll(edges)` | Replace the collection. |
| `getEdgeCopy(id)` | Single projection. |
| `idsForParent(parentId)` | Edge ids. |
| `idsForChild(childId)` | Edge ids. |

## 38. Semantic Contracts

### Projections

Public reads return fresh objects. Callers cannot mutate state by holding a returned projection.

### Return values

- Singular lookups: `T | null`
- Collections: `T[]`
- Commands: `{ success: boolean, reason?: string, ... }`
- Rules: `{ valid: boolean, errors?: string[], value?: T }`

### Missing data

- Missing character → `null` or `[]`
- Missing collection → `[]`
- Invalid explicit input → `throw`
- Year 0 is preserved.

### Randomness

Every rules module is deterministic. Randomness is drawn by the caller and passed as a roll.

### Persistence

`CharacterState`, `FamilyState`, and `ChildrenState` call `window.markDataDirty()` after writing to `masterData`. They do not call `saveMasterData`. Storage decides when to flush.

### Events

- `characterChanged` — `{ action, characterIds }`
- `familyChanged` — `{ action, characterIds }`
- `childrenChanged` — `{ action, characterIds }`
- `masterDataUpdated` — reload signal

---

## 39. Deletion and Lifecycle Semantics

### Soft delete

Orthogonal to life/death. Sets `isDeleted` and `deletedAt`. Nothing else changes. Soft-deleted characters are hidden from normal queries but remain in the collection.

### Hard delete

Removes the record from the collection, then dispatches cleanup to every domain that owns a reference. Failures in cleanup are recorded but do not block removal.

### Restore

Clears `isDeleted` and `deletedAt`. The character becomes visible again.

### Purge

Hard-deletes every soft-deleted character.

### Death

Two paths:

1. **Through `CharacterLifecycle.killCharacter`** — validates through `MortalityRules`, calls `CharacterCommands.markDeceased`, dispatches `FamilyCommands.handleCharacterDeath`.
2. **Through `CharacterCommands.markDeceased`** — validates through `MortalityRules`, writes the record, does **not** dispatch family cleanup. Reserved for cases where the death is part of a wider transaction (`ChildrenCommands.recordPregnancyAttempt` for maternal death).

### Maternal death

Childbed fever is not offered in the general death modal. It is recorded as part of a pregnancy attempt. The transaction is one command: `ChildrenCommands.recordPregnancyAttempt`. That command records the birth and calls `CharacterCommands.markDeceased` for the mother, in that order.

### Relationship domain

`relationship-state.js`, `relationship-queries.js`, `relationship-commands.js`, `relationship-rules.js`, `relationship-types.js`, `relationship-ui-metadata.js`, `relationships-bootstrap.js`, `relationship-docs.txt`, `relationship-finder-queries.js`, `relationship-finder.js`, `modals-relationship.js`, `modals-family.js`, `modals-friendship.js`, `romance-rules.js`, `romance-queries.js`, `romance-commands.js`, `friendship-rules.js`, `friendship-queries.js`, `friendship-commands.js`, `jealousy-rules.js`, `jealousy-queries.js`, `jealousy-commands.js`, `affair-rules.js`, `affair-queries.js`, `affair-commands.js`, `matchmaking-rules.js`, `matchmaking-queries.js`, `professional-rules.js`, `professional-queries.js`, `professional-commands.js`.

Removed capabilities: romance, friendship, rivalry, enmity, jealousy, affairs, matchmaking, professional relationships (apprenticeship, employment, guild membership), the relationship finder.

### Mortality legacy

`mortality-state.js`, `mortality-commands.js` (old), `mortality-queries.js` (old), `mortality-docs.txt`.

Removed behavior: direct mutation of death fields outside `markDeceased`; `1250` year fallback; `deathCause || 'Unknown'` coercion; `_processing` recursion guards.

### Children legacy

`children-state.js` (old), `children-commands.js` (old), `children-queries.js` (old), `children-lifecycle.js`, `pregnancy-service.js`, `surrogacy-service.js`, `adoption-service.js`, `modals-adoption.js`, `modals-birth.js`, `modals-surrogacy.js`, `children-docs.txt`.

Removed behavior: parallel parent-setting logic, parallel family queries, `_processing` guards.

### Legitimacy

Deliberately removed. `canLegitimize`, `legitimizeChild`, `openLegitimizationModal`, and the character fields `isLegitimate`, `legitimization`, `legitimizedYear`, `inheritanceRights` are not in the current system. If legitimacy is reintroduced, it needs its own state decision and its own rules module.

### Silent childbirth age correction

Removed. A death year chosen by the user is not silently rewritten.

### Murder / execution auto-consequence

Removed. Killing the murderer after a murder is not implemented.

## 41. What Was Not Implemented

Capabilities that existed in the pre-refactor code (or were documented) and are not present in the current system.

### Character

- `CharacterState.getCharactersByAgeRange` — **now implemented** in `character-queries.js`.
- `CharacterState.invalidateCache` — replaced by `refresh()`.
- `CharacterQueries.getMasterCharacters`, `getCharactersByProfessionSkill` — need a professional domain.
- `CharacterQueries.getCharactersByEducationStatus`, `getCharactersNotInEducation` — need an education domain.
- `CharacterQueries.getCharacterSpouses`, `getCurrentSpouse`, `getCharacterRelationshipDescription` — need a relationship domain.
- `CharacterQueries.getCharacterConsanguinityDegree` — replaced by numeric kinship closeness.
- `CharacterLifecycle.getPrimaryHeir`, `getPotentialHeirs`, `hasPendingInheritance`, `processHouseholdInheritance`, `processAllPendingInheritance` — need a succession domain.
- `CharacterCommands.updateDeathData` — no post-death edit command. If death data needs correction, `updateCharacterFields` accepts it without mortality validation. A dedicated command would be safer.

### Family

- Wrappers for cousins, aunts/uncles, nieces/nephews — **now implemented** in `family-queries.js`.
- Numeric kinship closeness — **now implemented**.
- Legitimization — deleted by decision.

### Children

- `calculateExpectedChildren`, `getExpectedRemainingChildren`, `calculateChildSpacing` — **now implemented** in `children-rules.js`.
- `recordPregnancyAttempts` (batch) — **now implemented** in `children-commands.js`.
- `recordSwapSurrogacy` — **now implemented**.
- `updateAdoptionMetadata` — **now implemented**.
- Adoption search filters — **now implemented** in `modals-children-adoption.js`.
- Legitimization — deleted by decision.

### Mortality

- `killCharacterRandomCause`, `triggerNaturalDeath`, `triggerAccidentalDeath` — **now implemented** in `character-lifecycle.js`.
- `applyAgingMortality` — replaced by `advanceMortality` with a default rate table.
- `predictLifespan`, `getExpectedRemainingYears` — **now implemented**.
- Default cause catalogue and rate table — **now implemented** in `mortality-rules.js`.
- Auto-execution of murderers — deleted, needs a justice domain.

### UI state

- Persistent panel state — **now implemented** in `ui-state.js`.

### The remaining gaps

There are two categories of remaining gaps:

**Gaps that require a new domain:**

- **Succession / inheritance** — heir selection, household transfer on death, inheritance rights.
- **Legitimacy** — if reintroduced.
- **Justice** — auto-execution of murderers, judicial records.
- **Relationship domain** — romance, friendship, rivalry, jealousy, affairs, matchmaking, professional relationships.
- **Education domain** — literacy, enrollment, graduation.

**Gaps in the current modules that could be closed without a new domain:**

- `CharacterCommands.updateDeathData` — a validated post-death edit command.

None of these are needed for the character, family, children, and mortality subsystem to be complete. They are extensions.
