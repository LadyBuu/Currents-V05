## 1. Overview

The character subsystem manages:

- Canonical character records
- Biological, legal, and social parentage
- Kinship classification
- Pregnancy, birth, surrogacy, and adoption metadata
- Death, murder, and execution
- Education enrollment, graduation, withdrawal, and literacy
- Population, family, children, and mortality statistics
- Panel UI state persistence
- UI modals for character CRUD, family view, death, birth, surrogacy,
  adoption, and education
- Multi-year simulation clock coordination

Seven architectural rules govern the whole subsystem:

1. **One owner per concept.**
   Character record                → `CharacterState`.
   Parent edges                    → `FamilyState` (parentChildEdges).
   Pregnancy, surrogacy, adoption  → `ChildrenState`.
   Education containers            → `CharacterCommands` (education API).
   Death fields                    → on the character record, written
                                     only by `CharacterCommands.markDeceased`.

2. **Rules are pure.** `-rules.js` modules contain no I/O, no
   randomness, no mutation, no state access.

3. **Reads and writes are separate.** `-queries.js` reads, `-commands.js`
   writes. A query never mutates.

4. **Dependencies fail loudly.** Missing required modules throw at load.
   Missing optional dependencies either throw at call time or fail
   closed with a documented empty value. Missing data returns null or [].

5. **Randomness is injected.** No rules module generates random numbers.
   Rolls are passed in by the caller. Where a command genuinely needs a
   random draw, it goes through `randomness.js` (`window.random()`).
   `Math.random()` is forbidden everywhere.

6. **Multi-year simulation passes the simulated year.**
   `CharacterCommands.markDeceased` accepts `options.referenceYear` for
   this purpose. `CharacterLifecycle.advanceMortality` uses it on every
   simulated death and now also accepts `options.startYear` and returns
   `result.finalYear`. Any caller that writes a death year ahead of
   wall-clock must supply the reference year explicitly or validation
   will reject the death.

7. **No dead-schema reads.** The character record's parentage fields
   (`motherId`, `fatherId`, `children`, `adoptedParents`,
   `adoptedChildren`) were removed when parentage moved to
   `parentChildEdges`. The `relationships` array was removed when
   romantic links moved to the relationship domain. No module in the
   character subsystem — or in the household subsystem that reads from
   it — may read those fields.

## 2. File Manifest

### Character core

| File | Role |
|---|---|
| `character-state.js` | Canonical character collection and derived indexes. Owns all mutation primitives. Owns ephemeral UI state (facade compatibility). Projections deep-clone every embedded container. |
| `character-queries.js` | Semantic character-level reads (search, summary, facts, age-range, family delegates, profession delegates). Read side of `CharacterState`. |
| `character-commands.js` | Mutation boundary for character-owned fields. Traits, professions, rank assignments, education containers, literacy, surname history, religion orchestration, death transition. |
| `character-factory.js` | Canonical `buildCharacter` constructor. Validates, defaults, and assembles every character record. Also provides `validateBuiltCharacter` for the pre-built insertion path. |
| `character-generator.js` | Random character data generation. Produces the plain data object fed to `buildCharacter`. Does not construct entities. |
| `character-creation-commands.js` | Creation boundary. Routes every creation path through `buildCharacter` + `CharacterState.addCharacter`. Establishes family edges and religion after insertion. |
| `character-deletion-commands.js` | Deletion boundary. Soft delete, hard delete, purge, bulk. Dispatches cross-domain cleanup on hard delete. |
| `character-lifecycle.js` | Time progression and mortality orchestration. `advanceMortality`, `killCharacter`, `triggerNaturalDeath`, `triggerAccidentalDeath`. Age/life-stage classification. Cross-domain death dispatch. |

### Family

| File | Role |
|---|---|
| `family-rules.js` | Pure parentage and kinship policy. Validators. |
| `family-state.js` | Canonical `parentChildEdges` collection. Indexes by parent, child, and pair. |
| `family-queries.js` | Traversal and projection of parent-child edges. Kinship wrappers (`classifyKinship`, `getKinshipCloseness`). Ancestor provider for `FamilyRules` cycle detection. |
| `family-commands.js` | Mutation boundary for parent edges. `setParent`, `removeParent`, `createAdoption`, `removeAdoption`, `changeParentType`, `handleCharacterDeath`, `removeAllReferencesTo`. |
| `family-statistics.js` | Aggregate family counts for a character. Composition of `FamilyQueries` + `CharacterQueries`. |

### Children

| File | Role |
|---|---|
| `children-rules.js` | Pure pregnancy, surrogacy, and adoption policy. Fertility, conception, complication, reconciliation heuristics. |
| `children-state.js` | Canonical store for pregnancy records, surrogacy arrangements, adoption metadata. |
| `children-queries.js` | Read projections for pregnancies, surrogacy arrangements, adoptions. Composes `FamilyQueries` for parent resolution. |
| `children-commands.js` | Mutation boundary. `recordBirth`, `recordPregnancyAttempt`, `recordSurrogacyArrangement`, `recordAdoptionMetadata`, etc. Coordinates `CharacterCreationCommands` and `FamilyCommands`. |
| `children-generator.js` | Birth proposal generation. Does not construct children. |
| `children-statistics.js` | Aggregate pregnancy, surrogacy, adoption, and per-parent family statistics. |

### Mortality

| File | Role |
|---|---|
| `mortality-rules.js` | Pure death validation, cause catalogue, mortality-rate bands, deterministic cause picker. |
| `mortality-queries.js` | Read projections for death records, murders, executions. |
| `mortality-statistics.js` | Aggregate mortality analytics. |

### UI

| File | Role |
|---|---|
| `character-ui-list.js` | Renders character lists and cards. Delegated click handling. |
| `modals-character.js` | Character CRUD, details, family view. Edit-modal transaction contract (see §6). |
| `modals-children-adoption.js` | Adoption metadata modals. |
| `modals-children-birth.js` | Birth, pregnancy, batch birth modals. |
| `modals-children-surrogacy.js` | Surrogacy arrangement modals. |
| `modals-death.js` | Death, murder, execution modals. Childbed-fever routing. |

### Compatibility

| File | Role |
|---|---|
| `character-system.js` | One-way legacy aliases onto the canonical modules. Loads last. Throws if any canonical module is missing. |

subsystem must follow it. Deviating from it causes one of the
