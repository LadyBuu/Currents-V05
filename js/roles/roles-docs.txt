## 1. Overview

The role domain owns the **catalogue** of what a character can hold:
role records, categories, salary policy, literacy requirements, gender
restrictions, and the set of specializations a role offers.

It does not own:

- a character's profession record or skill level
  → `CharacterCommands`
- the apprenticeship that trains a character toward a role
  → `ApprenticeshipCommands`
- the relationship edge between master and apprentice
  → `ProfessionalCommands`
- the skill taxonomy
  → `SkillUtils`

The role catalogue answers "what does a Blacksmith role look like." It
does not answer "is Bruna a Blacksmith" or "is Bruna being trained by
João."

---

## 2. Files

| File | Purpose |
|------|---------|
| `role-constants.js` | Categories, salary policy, literacy vocabulary, teaching thresholds (mirrored from `SkillUtils`). Pure constants. |
| `role-rules.js` | Pure policy: specialization membership validation, and future role-domain validity rules. No state access. |
| `role-state.js` | The authoritative in-memory role collection. Derived indexes, subscriptions, persistence sync. |
| `role-queries.js` | Read-only projections: role collections, categories, character-role joins, statistics. |
| `role-commands.js` | Write operations: role CRUD, category management, specialization catalogue, character assignment, salary, literacy. |
| `role-system.js` | Compatibility shim. One-way aliases onto the canonical modules for legacy callers. |
| `role-ui-list.js` | UI: role list, role card, role detail panel, master-filter toggle. |
| `modals-roles.js` | UI: create/edit/delete role, assign role to character(s), edit skill, list roles, category manager. |
| `modals-role-select.js` | UI: reusable role picker for cross-system use. Read-only. |
