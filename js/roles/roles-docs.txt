# ROLE SYSTEM - COMPLETE DOCUMENTATION

## SYSTEM OVERVIEW

The Role System manages professions and occupations that characters can hold. Roles define what a character does, their skill level, specialization, salary, and literacy requirements. The system provides a complete CRUD interface with category management, role assignment, and skill tracking.

---

## DIRECTORY STRUCTURE

Based on your project structure, the Role System files are located at:

```
js/roles/
├── role-constants.js           # All constants (categories, thresholds, salary defaults)
├── role-state.js               # Single source of truth + cache + notifications
├── role-commands.js            # All write operations (CRUD, assignment, salary, literacy)
├── role-queries.js             # All read operations (search, filter, stats, categorization)
├── role-system.js              # Wrapper re-exporting all functions (backward compatibility)
├── role-ui-list.js             # UI list rendering (role list, detail panel, cards)
├── modals-roles.js             # UI modals (CRUD, assignment, category management)
├── modals-role-select.js       # Reusable role selector modals
└── roles-docs.txt              # This documentation
```

---

## RELATED FILES (Cross-System Dependencies)

```
js/core/
├── accessors.js                # getCharacterById, getCharacters, getRoleById
```

---

## KEY PRINCIPLES

| Principle | Description |
|-----------|-------------|
| **Single Source of Truth** | `role-state.js` holds all role data |
| **Command-Query Separation** | Commands (writes) vs Queries (reads) separated |
| **Separation of Concerns** | State, commands, queries, constants, UI all separate |
| **Recursion Guards** | All public functions protected from infinite loops |
| **Change Notifications** | Subscriptions for reactive updates |
| **No Emojis** | All icons from `icons.js` via `_getIcon()` |
| **No Direct masterData Access** | All access through the state layer |
