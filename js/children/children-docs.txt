## 1. SYSTEM OVERVIEW

The Children System manages all aspects of child-related data in the Still Waters simulation:

| Feature | Description |
|---------|-------------|
| **Birth** | Recording births, creating child characters, tracking pregnancy history |
| **Adoption** | Legal adoption, guardianship, foster care placement |
| **Surrogacy** | Traditional and gestational surrogacy, swap arrangements |
| **Pregnancy** | Fertility calculations, pregnancy simulation, complications |
| **Legitimization** | Declaring children legitimate heirs with inheritance rights |

**KEY PRINCIPLES:**
- Single Source of Truth (children-state.js)
- Command-Query Separation (commands vs queries)
- Separation of Concerns (state, commands, queries, lifecycle, UI)
- Recursion Guards on all public functions
- Change Notifications via subscriptions
- No direct masterData access outside state
- NO TRUST/LOYALTY systems

## 3. CHILDREN-STATE.JS - Single Source of Truth

**PURPOSE:** Manages the central state for all child-related data.

**DEPENDENCIES:**
- storage.js (masterData)
- accessors.js (getCharacters, getCharacterById)

**DATA STRUCTURES:**

```javascript
_state = {
    // Adoption records (childId -> array of adoption records)
    adoptionRecords: new Map(),
    
    // Pregnancy records (historical)
    pregnancyRecords: [],
    
    // Surrogacy records
    surrogacyRecords: [],
    
    // Cache
    cache: {
        adoptedChildren: new Map(),      // parentId -> [childId]
        adoptiveParents: new Map(),      // childId -> [parentId]
        childrenByParent: new Map(),     // parentId -> [childId]
        pregnanciesByMother: new Map(),  // motherId -> [pregnancy]
        surrogaciesByParent: new Map()   // parentId -> [surrogacy]
    },
    
    // Subscribers
    subscribers: [],
    _processingState: false,
    _initialized: false,
    lastUpdated: null
}
```

**FUNCTIONS:**

```javascript
// ---- Adoption ----
ChildrenState.getAdoptionRecords(childId)          // Array of adoption records
ChildrenState.getAdoptiveParents(childId)          // Array of { character, record }
ChildrenState.getAdoptedChildren(parentId)         // Array of child characters
ChildrenState.isAdopted(childId)                   // boolean

// ---- Pregnancy ----
ChildrenState.getPregnancyRecords(motherId)        // Array of pregnancy records

// ---- Surrogacy ----
ChildrenState.getSurrogacyRecords()                // Array of surrogacy records
ChildrenState.getSurrogacyRecordsForParent(parentId) // Array of surrogacy records

// ---- Children ----
ChildrenState.getChildren(parentId, includeAdopted) // { biological: [], adopted: [] }
ChildrenState.getTotalChildren(parentId, includeAdopted) // number

// ---- Subscriptions ----
ChildrenState.subscribe(callback)                  // Returns unsubscribe function

// ---- Cache ----
ChildrenState.invalidateCache()                    // Rebuilds all caches

// ---- Internal ----
ChildrenState._addAdoptionRecord(childId, adoption)
ChildrenState._removeAdoptionRecord(childId, parentId)
ChildrenState._addPregnancyRecord(record)
ChildrenState._addSurrogacyRecord(record)
ChildrenState._updateSurrogacyRecord(index, updates)
ChildrenState._loadData()
ChildrenState._rebuildCaches()
```

## 4. CHILDREN-COMMANDS.JS - Write Operations

**PURPOSE:** All write operations for children (birth, adoption, surrogacy, legitimization).

**DEPENDENCIES:**
- children-state.js (ChildrenState)
- character-commands.js (CharacterCommands)
- family-logic.js (FamilyLogic)
- accessors.js (getCharacterById, getCharacters)

**FUNCTIONS:**

```javascript
// ---- Birth ----
ChildrenCommands.recordBirth(mother, father, birthYear, options)
// options: { gender, isStillborn, name, surname, notes, birthplaceId, autoAssignHousehold }
// RETURNS: { success: boolean, child: Object, reason: string }

// ---- Adoption ----
ChildrenCommands.recordAdoption(parent, child, options)
// options: { year, type: 'legal'|'guardianship'|'foster', notes, parentType, partner }
// RETURNS: { success: boolean, child: Object, adoption: Object, reason: string }

// ---- Remove Adoption ----
ChildrenCommands.removeAdoption(parent, child, options)
// options: { endYear, reason, keepHistory }
// RETURNS: { success: boolean, reason: string }

// ---- Legitimize Child ----
ChildrenCommands.legitimizeChild(child, father, mother, options)
// options: { year, changeSurname: 'none'|'father'|'mother'|'hyphenated', 
//           inheritanceRights: 'full'|'limited'|'none', notes, autoAssignHousehold }
// RETURNS: { success: boolean, child: Object, year: number, inheritanceRights: string }

// ---- Surrogacy ----
ChildrenCommands.recordSurrogacy(intendedParent, surrogate, options)
// options: { childCount, birthYear, spermDonor, eggDonor, notes }
// RETURNS: { success: boolean, children: Array, surrogacyRecord: Object }

// ---- Update Surrogacy ----
ChildrenCommands.updateSurrogacyRecord(recordId, updates)
// updates: { status, actualBirthYear, childIds, notes }
// RETURNS: updated record or null
```

**LEGACY ALIASES:**
```javascript
window.generateNewborn = ChildrenCommands.recordBirth
window.createAdoption = ChildrenCommands.recordAdoption
window.removeAdoption = ChildrenCommands.removeAdoption
window.createSurrogacyArrangement = ChildrenCommands.recordSurrogacy
```

## 14. RECURSION GUARDS

All modules implement recursion guards to prevent infinite loops:

| Guard Name | Location | Purpose |
|------------|----------|---------|
| `_processingState` | children-state.js | Prevent state mutation re-entry |
| `_processing` | children-commands.js | Prevent command re-entry |
| `_processing` | children-queries.js | Prevent query re-entry |
| `_processing` | children-lifecycle.js | Prevent lifecycle operation re-entry |
| `_processing` | adoption-service.js | Prevent adoption operation re-entry |
| `_processing` | pregnancy-service.js | Prevent pregnancy operation re-entry |
| `_processing` | surrogacy-service.js | Prevent surrogacy operation re-entry |

**Pattern:**
```javascript
function someFunction() {
    if (_processing) {
        return { success: false, reason: 'Already processing' };
    }
    _processing = true;
    try {
        // ... function logic ...
    } finally {
        _processing = false;
    }
}
```

## 16. DATA SCHEMA

### Adoption Record Schema

```javascript
{
    parentId: string,           // Adoptive parent ID
    parentName: string,         // Adoptive parent name
    year: number,               // Year of adoption
    type: 'legal'|'guardianship'|'foster',  // Adoption type
    notes: string,              // Notes about the adoption
    status: 'active'|'ended'|'dissolved',   // Current status
    timestamp: number,          // Creation timestamp
    endedYear?: number,         // Year ended (if status is ended)
    endedReason?: string        // Reason ended (if status is ended)
}
```

### Pregnancy Record Schema

```javascript
{
    motherId: string,           // Mother character ID
    fatherId: string|null,      // Father character ID
    childIds: Array<string>,    // Child character IDs
    birthYear: number,          // Year of birth
    gender: string,             // 'male', 'female', or 'mixed'
    isMultiple: boolean,        // Multiple birth
    fetusCount: number,         // Number of fetuses
    hasComplications: boolean,  // Pregnancy complications
    maternalDeath: boolean,     // Maternal death occurred
    notes: string               // Notes about the pregnancy
}
```

### Surrogacy Record Schema

```javascript
{
    id: string,                 // Surrogacy record ID
    intendedParentId: string,   // Intended parent ID
    intendedPartnerId: string|null, // Intended partner ID
    surrogateId: string,        // Surrogate character ID
    spermDonorId: string|null,  // Sperm donor ID
    eggDonorId: string|null,    // Egg donor ID
    arrangementYear: number,    // Year arrangement made
    expectedBirthYear: number,  // Expected birth year
    actualBirthYear: number|null, // Actual birth year
    childIds: Array<string>,    // Child character IDs
    status: 'active'|'completed'|'cancelled', // Current status
    type: 'traditional'|'gestational', // Surrogacy type
    notes: string               // Notes about the arrangement
}
```

### Child Surrogacy Info Schema

```javascript
// Added to child character object when born via surrogacy
{
    surrogateId: string,        // Surrogate character ID
    intendedParentId: string,   // Intended parent ID
    intendedPartnerId: string|null, // Intended partner ID
    arrangementYear: number,    // Year arrangement made
    birthYear: number,          // Birth year
    type: 'traditional'|'gestational' // Surrogacy type
}
```
