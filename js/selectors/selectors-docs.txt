================================================================================
STILL WATERS — SELECTOR SUBSYSTEM DOCUMENTATION AND DEPENDENCIES
================================================================================

Scope of this document:
  - Every file in the selector subsystem that was provided:
      js/selectors/selector-base.js
      js/selectors/locationDropdown.js
      js/selectors/modals-char-selector.js
      js/selectors/modals-household-selector.js
  - Every core (js/core/) file the selector subsystem depends on,
    either at load time (module-level guards) or at call time
    (typeof-guarded lookups), and how each dependency is used.
  - Every cross-domain file the selector subsystem reaches into (via
    window.X lookups) and under what conditions.
  - The inconsistencies between the supplied files and the
    `selectors-docs.txt` reference document.

Cross-references:
  - stillwaters-docs.txt (core-level documentation and load order).
  - stillwaters-character-docs.txt.
  - stillwaters-location-docs.txt.
  - selectors-docs.txt (the reference doc; note that it is OUT OF
    SYNC with the code in several places — see Part 5).

PATHS NOTE:
  This document uses the paths shown in the repository tree. The
  selector files live at `js/selectors/`:
    js/selectors/selector-base.js
    js/selectors/locationDropdown.js
    js/selectors/modals-char-selector.js
    js/selectors/modals-household-selector.js
  The selectors-docs.txt document incorrectly describes a
  `js/core/query-helpers.js` file and a `js/core/selector-base.js`
  file. Neither exists in the tree. There is no `js/core/query-helpers.js`.
  The `selector-base.js` file is at `js/selectors/selector-base.js`.
  This document uses tree paths and flags the discrepancy in Part 5.

Anything not provable from the supplied files is marked [UNVERIFIED].


================================================================================
PART 1 — DEPENDENCIES
================================================================================

Terminology:
  REQUIRED (load-time)  — a module-level guard throws if the
                          dependency is missing when this file loads.
  REQUIRED (call-time)  — a function or method throws or refuses if
                          the dependency is missing when the function
                          is invoked; the module loads without it.
  OPTIONAL              — the module checks for the dependency and
                          falls back (usually skipping the feature)
                          when it is absent.

--------------------------------------------------------------------------------
1.1 SELECTOR-SUBSYSTEM FILES AND WHAT THEY EXPORT
--------------------------------------------------------------------------------

  js/selectors/selector-base.js
    Owns: window.SelectorBase (constructor), window.SelectorHelpers
          (helper object, also aliased as window._SelectorBaseHelpers),
          plus flat aliases getCharacterDisplayName,
          getCharacterInitials, isBloodRelativeBasic, isSpouseBasic,
          getGenderLabel, getGenderSymbol.
    Scope:
      - Base class for selector modals: open/close, listener
        registration and cleanup, debounce, toast, filter config
        normalization, pure filter predicates, display helpers.
      - All predicates and display helpers are pure; the class holds
        only per-instance state.
    Out of scope:
      - Concrete selector modals (modals-char-selector.js,
        modals-household-selector.js).
      - Family semantics (delegates to FamilyQueries).
      - Relationship semantics (delegates to RelationshipQueries).
      - Mutation (all reads).

  js/selectors/locationDropdown.js
    Owns: window.buildLocationDropdown,
          window.getLocationHierarchyDisplay,
          window.getLocationCountry,
          window.getLocationDistrict,
          window.getLocationTypeLabel.
    Scope:
      - Builds `<option>` markup for a location `<select>`.
      - Formats a place's hierarchy for display.
      - Resolves country/district ancestors (SUPERSET of world.js's
        same-named exports — accepts place OR id).
      - Returns the display name for a location type.
    Out of scope:
      - Hierarchy walks (delegated to world.js).
      - District and country resolution internals (delegated to
        world.js).
      - Formatting internals (delegated to formatting.js).
      - Mutation (all reads).

  js/selectors/modals-char-selector.js
    Owns: window.openCharacterSelector,
          window.closeCharacterSelector,
          window.FILTER_PRESETS,
          window._openCharacterSelector,
          window.openUnifiedCharacterSelector.
    Scope:
      - Character selector modal: build, filter, sort, render, pick.
      - Per-modal local state (`this._root`, `this._elements`).
    Out of scope:
      - Character mutation (CharacterCommands).
      - Family relationship resolution (FamilyQueries).
      - Relationship domain queries (RelationshipQueries).
      - Modal lifecycle (modals-core.js).
      - Rendering CSS (external stylesheet).

  js/selectors/modals-household-selector.js
    Owns: window.openHouseholdSelector.
    Scope:
      - Household selector modal: classify, filter, search, render,
        pick.
      - Uses SelectorHelpers.isBloodRelativeBasic to badge blood
        relatives of the anchor character (when `characterId` is
        supplied).
    Out of scope:
      - Household query layer (HouseholdQueries).
      - Family semantics (FamilyQueries).
      - Mutation (all reads).

PART 2 — ARCHITECTURE AND INTERFACE CONTRACTS
================================================================================

2.1 SELECTOR-BASE (window.SelectorBase + window.SelectorHelpers)
--------------------------------------------------------------------------------

  window.SelectorBase is a constructor. Subclasses call:

      SelectorBase.call(this, options);
      Subclass.prototype = Object.create(SelectorBase.prototype);
      Subclass.prototype.constructor = Subclass;

  The constructor guarantees (per the file):
    - this.options  — the caller's options object (never null)
    - this.state    — { filters, isOpen, onSelect, onCancel }
    - this._modal   — null until openModal() is called
    - this._listeners — array of tracked listener records

  The prototype provides:
    openModal(title, content, cancelText, onConfirmExtra, openOptions)
    close()
    escapeHtml(str)
    getIcon(name)
    getGenderSymbol(gender)
    isBloodRelative(aId, bId)
    isSpouse(aId, bId)
    debounce(fn, delay)
    showToast(message, type)
    _registerListener(el, eventType, handler)
    _cleanupListeners()

  openModal wiring:
    - Passes titleHtml / contentHtml / confirmText / cancelText to
      window.openModal.
    - Connects window.openModal's onCancel to state.onCancel. Every
      non-confirmed close (Cancel button, overlay click, Escape,
      close X, closeTopModal) fires state.onCancel exactly once.
    - If the caller supplies an openOptions.onMount callback, the
      modal shell invokes it synchronously after insertion into the
      DOM. That is the intended replacement for the historical
      setTimeout(0) hack in modals-char-selector.js.

  close() wiring:
    - Sets state.isOpen = false.
    - Removes every tracked listener via _cleanupListeners().
    - Calls this._modal.close() (which does NOT fire state.onCancel
      per modals-core.js's contract).
    - Clears this._modal.
    - Callers who want onCancel semantics should let the modal close
      via user action (Cancel, overlay, Escape, close X), or call
      state.onCancel themselves.

  WINDOW.SELECTORHELPERS (helper object):
    getDefaultFilterConfig, normalizeFilterConfig,
    matchGender, matchStatus, matchAge, matchLocation,
    matchExcludeIds, matchRelationship, matchesCharacter,
    isBloodRelativeBasic, isSpouseBasic,
    getCharacterDisplayName, getCharacterInitials,
    getGenderLabel, getGenderSymbol,
    version (currently 3).

  The same object is exposed under both window.SelectorHelpers and
  window._SelectorBaseHelpers for backward compatibility.

  Flat aliases (also installed on window):
    getCharacterDisplayName, getCharacterInitials,
    isBloodRelativeBasic, isSpouseBasic,
    getGenderLabel, getGenderSymbol.

  isBloodRelativeBasic semantics:
    - Fails closed: returns false when FamilyQueries is not loaded
      or throws.
    - Fails closed on missing or equal ids.

  isSpouseBasic semantics:
    - Reads window.getRelationshipBetween if it is a function, or
      window.RelationshipQueries.getRelationshipBetween.
    - Returns true only when the relationship record has
      type === 'marriage' AND status === 'ongoing'.
    - Fails closed on missing module or missing record.

  getGenderSymbol semantics:
    - Prefers window.getGenderIcon(gender) — the icons.js helper.
    - Falls back to window.Icons[name] with MALE / FEMALE /
      GENDER_NEUTRAL.
    - Final fallback: escaped text label.
    - No emojis, ever.

2.2 locationDropdown.js
--------------------------------------------------------------------------------

  window.buildLocationDropdown(selectedId, placeholder, showAllOption)
    Builds `<option>` inner HTML for a `<select>`. Sorted
    alphabetically by display name. Emits:
      - "All locations" when showAllOption is truthy
      - A placeholder option when showAllOption is falsy and
        placeholder is a non-empty string
      - An empty leading option when neither is provided and
        selectedId is missing, so the select does not auto-select
        the first place

  window.getLocationHierarchyDisplay(placeOrId)
    Accepts a place object OR a place id. Delegates to
    world.getParentChain when present; otherwise walks the local
    parent chain. Formats via window.formatLocationHierarchy when
    present; otherwise joins names with ' → '.
    Returns '' for missing or unresolvable input.

  window.getLocationCountry(placeOrId)
    Accepts a place object OR a place id.
    Delegates to world.getLocationCountry when present.
    Falls back to a local walker when absent.
    SHADOWS world.js's same-named export under the documented load
    order. The winning function is a SUPERSET (accepts place OR id;
    delegates to world's version when called with a place).
    See SHADOWING in the module header for the full contract.

  window.getLocationDistrict(placeOrId)
    Same story as getLocationCountry, for district.

  window.getLocationTypeLabel(typeId)
    Returns the display name for a location type or 'Unknown'.
    Reads window.getLocationTypeById at call time.

  SHADOWING:
    Under the documented load order (world.js before locationDropdown.js),
    locationDropdown's getLocationCountry / getLocationDistrict overwrite
    world.js's. Runtime callers should assume the SUPERSET contract.

2.3 modals-char-selector.js
--------------------------------------------------------------------------------

  window.openCharacterSelector(options)
    Options:
      title         string  default 'Select Character'
      targetId      string  target character id (used to compute
                            "peers" and "blood relative" / "spouse"
                            badges)
      onSelect      Function called with the chosen character
                            projection
      onCancel      Function called when the modal closes without
                            a pick
      excludeIds    array of ids to exclude
      preset        key into FILTER_PRESETS
      filters       object overriding the default filters

  FILTER_PRESETS:
    'partner'    status=single, ageGroup='21-30', peers=true,
                 showDeceased=false
    'father'     gender=male, ageGroup='31-40', hasChildren=true,
                 showDeceased=false
    'mother'     gender=female, ageGroup='31-40', hasChildren=true,
                 showDeceased=false
    'child'      ageGroup='0-10', showDeceased=false
    'master'     ageGroup='31-40', showDeceased=false
    'apprentice' ageGroup='11-20', showDeceased=false
    'elder'      ageGroup='61-70', showDeceased=false
    'available'  status=single, ageGroup='21-30', showDeceased=false
    'all'        (empty)

  Default filters:
    search='', gender='all', status='all', ageGroup='all',
    location='all', role='all', showDeceased=false, peers=false,
    sameLocation=false, hasChildren=false, noChildren=false,
    isHead=false, isNotHead=false, hasParents=false, orphan=false,
    sortBy='age_desc'

  Filter predicates (via SelectorHelpers and local adapters):
    - search: substring match on name + surname
    - gender: exact match against char.gender
    - status: 'partnered' via
      RelationshipQueries.getActiveCommittedPartners; 'single' is
      the negation
    - ageGroup: parsed into [min, max]; '+' for the open-ended band
    - location: exact match against char.currentLocationId
    - hasChildren / noChildren: via FamilyQueries.getChildIds
    - hasParents / orphan: via FamilyQueries.getAllParentIds
    - role: matches a name returned by CharacterCommands.getProfessions

  DOM scoping:
    - The modal element is stored on this._root.
    - Every DOM query is scoped via this._root.querySelector.
    - Every listener is registered via this._registerListener
      (from SelectorBase) so it can be removed by close()'s
      _cleanupListeners.
    - The row-click handler and the Escape/Enter keydown handler
      are scoped to the modal.

  Modal mount:
    - _render passes _cacheElements and _attachEvents through
      openOptions.onMount, not setTimeout(0). This eliminates
      the collision where two stacked selectors shared id-scoped
      DOM lookups.

  Badges:
    - "Relative" and "Spouse" badges are computed via
      SelectorHelpers.isBloodRelativeBasic / isSpouseBasic when
      targetId is supplied.
    - "Partnered" badge is computed via
      RelationshipQueries.getActiveCommittedPartners.
    - "Deceased" badge from char.isDeceased.

  Row click:
    - Calls SelectorBase.prototype.close() (state.onCancel does NOT
      fire, because close() is programmatic), then fires
      state.onSelect(character). The cleanup listener order
      ensures onSelect fires on a stable, closed modal.

  Cancel paths:
    - The modal's Cancel button, overlay click, Escape, close X,
      and any closeTopModal call from external code all fire
      state.onCancel via openModal's wiring.

  window.closeCharacterSelector:
    - Finds the topmost `.modal .selector-container[data-selector="character"]`
      and clicks its close button. If none found, no-op.

2.4 modals-household-selector.js
--------------------------------------------------------------------------------

  window.openHouseholdSelector(options)
    Options:
      title         string  default 'Select Household'
      onSelect      Function called with the household snapshot
      onCancel      Function called on every non-confirmed close
      characterId   string  optional; enables current-household
                            highlighting and relative badges
      filterConfig  object  see below

    filterConfig:
      showActive      boolean default true
      showVacant      boolean default true
      showEmpty       boolean default true
      showDeprecated  boolean default false
      showDeleted     boolean default false
      searchText      string  default ''

  Household classification:
    'active'      has living members
    'vacant'      has members but none living
    'empty'       has no members
    'deprecated'  persisted status is 'deprecated' or 'destroyed'

  Row badges:
    - Status badge per classification (Active / Vacant / Empty /
      Deprecated) with a colored chip
    - current: shown when household.id === getCharacterHousehold(
      characterId).id
    - relative: shown when SelectorHelpers.isBloodRelativeBasic
      (characterId, memberId) is true for any member

  Row click:
    - Uses _resolveHouseholdSnapshot(householdId) to tolerate
      HouseholdQueries.getHousehold returning a record object, an
      id string, or null. See HOUSEHOLDQUERIES GET-HOUSEHOLD
      CONTRACT in the module header.
    - Calls closeTopModal, then schedules onSelect(snapshot) via
      setTimeout(0). This preserves the same call shape as the
      historical implementation and lets the modal removal complete
      before the caller's onSelect runs.

  Cancel paths:
    - The modal's Cancel button, overlay click, Escape, close X, and
      closeTopModal all fire onCancel (via the modal shell's wiring).

  DOM scoping:
    - Uses modal.element (from window.openModal's return) as the
      scope. Every query is root.querySelector.
    - Delegated row-click is bound to listEl.

  Style policy:
    - This module still uses inline style attributes on rows and
      filter chips. The header acknowledges this as a deferred
      cleanup (TODO: selectors-css-migration). Do NOT claim the
      module is CSS-only in the docs; fix the code first.

2.5 What the selector subsystem does NOT do
--------------------------------------------------------------------------------

  - No mutation. Every function is a read.
  - No domain logic. Family, relationship, household, character
    semantics delegate to the owning modules.
  - No persistence. Does not call saveMasterData or markDataDirty.
  - No cross-tab sync. Does not subscribe to masterDataUpdated.
  - No icons in confirm/cancel buttons (plain text only, per
    selectors-docs.txt's icon policy).

PART 5 — DISCREPANCIES BETWEEN selectors-docs.txt AND THE CODE
================================================================================

The selectors-docs.txt reference document is OUT OF SYNC with the
code in several places. Below is the full list of divergences,
verified against the four supplied selector files.

1. **`js/core/query-helpers.js` does not exist.**
   selectors-docs.txt describes it as a core file with a large
   surface (getCharacterStatusBasic, getCharacterRoles,
   getCharacterLocationId, getCharacterParents,
   getCharacterChildren, getAgeGroupForAge, getAgeGroupLabel,
   getLocationHierarchy, getLocationHierarchyDisplay,
   getAllLocationsHierarchical, etc.). No supplied selector file
   references it. modals-char-selector.js and
   modals-household-selector.js read those concepts through
   CharacterCommands, CharacterQueries, FamilyQueries, and
   HouseholdQueries directly. Treat the "CORE QUERY HELPERS"
   section as describing a file that does not exist in the tree.

2. **`js/core/selector-base.js` does not exist.**
   The selector-base.js file is at `js/selectors/selector-base.js`.
   selectors-docs.txt's Architecture Diagram and File Structure
   place it under `js/core/`. Do not move it: the selector modals
   load-time guard window.SelectorBase, which is installed by
   js/selectors/selector-base.js. The file's own header says "LOCATION:
   js/selectors/selector-base.js".

3. **selector-base.js does not expose the helper object under
   `_SelectorBaseHelpers.escapeHtml` and friends.**
   selectors-docs.txt (section 4, "Exposed Helpers") lists
   `_SelectorBaseHelpers.escapeHtml`, `_SelectorBaseHelpers.getIcon`,
   `_SelectorBaseHelpers.getGenderSymbol`,
   `_SelectorBaseHelpers.getGenderLabel`,
   `_SelectorBaseHelpers.isBloodRelativeBasic`,
   `_SelectorBaseHelpers.isSpouseBasic`,
   `_SelectorBaseHelpers.openModal`,
   `_SelectorBaseHelpers.closeTopModal`,
   `_SelectorBaseHelpers.showToast`,
   `_SelectorBaseHelpers.debounce`.

   In the code, window._SelectorBaseHelpers is an ALIAS for
   window.SelectorHelpers, and SelectorHelpers exposes:
   getDefaultFilterConfig, normalizeFilterConfig, matchGender,
   matchStatus, matchAge, matchLocation, matchExcludeIds,
   matchRelationship, matchesCharacter, isBloodRelativeBasic,
   isSpouseBasic, getCharacterDisplayName, getCharacterInitials,
   getGenderLabel, getGenderSymbol, version.

   The helper object does NOT include escapeHtml, getIcon, openModal,
   closeTopModal, showToast, or debounce. Those are methods on the
   SelectorBase class, not on the helper object.
   modals-char-selector.js calls them via `this.escapeHtml(...)` and
   `this.debounce(...)` (class methods), not via
   `_SelectorBaseHelpers.escapeHtml(...)` (helper object method).

4. **SelectorBase.openModal signature.**
   selectors-docs.txt (section 4) lists
   `openModal(title, content, confirmText, onConfirm)`.
   The code's signature is
   `openModal(title, content, cancelText, onConfirmExtra, openOptions)`.
   The parameter names differ, and the code's openModal does NOT
   render a confirm button. It renders a cancel button only, and the
   selection is the subclass's job via row clicks. modals-char-selector.js
   calls it as `this.openModal(title, content, 'Cancel', function () {},
   { onMount: ... })`.

5. **locationDropdown.js does not export the surface described in
   selectors-docs.txt section 7.**
   The docs describe `buildHierarchicalLocationOptions`,
   `renderHierarchicalLocationOptionsHtml`,
   `getFilteredLocationOptions`, `renderSimpleLocationOptions`,
   `renderLocationOptionsByPriority`, `renderLocationOptionsByParent`,
   `createLocationSelector`, `createFilterAwareLocationSelector`,
   `refreshAllFilterAwareSelectors`, `registerLocationFilterListener`,
   `notifyLocationFiltersChanged`, `setLocationFilterFn`.
   The code exports `buildLocationDropdown`,
   `getLocationHierarchyDisplay`, `getLocationCountry`,
   `getLocationDistrict`, `getLocationTypeLabel`.
   The docs describe a different (and larger) surface. Callers should
   trust the code's surface. `window.getFilteredLocationOptions`, if
   a caller needs it, does not exist in the supplied locationDropdown.js.
   Any caller that uses it must shim it or use
   buildLocationDropdown directly.

6. **modals-char-selector.js does not export
   `window.CharacterSelectorState`.**
   selectors-docs.txt (section 5, "Exports") lists
   `window.CharacterSelectorState` as an export.
   The code exports only `window.openCharacterSelector`,
   `window.closeCharacterSelector`, `window.FILTER_PRESETS`,
   `window._openCharacterSelector`, `window.openUnifiedCharacterSelector`.
   No `CharacterSelectorState` is installed.

7. **modals-household-selector.js does not export
   `window.HouseholdSelectorState`.**
   Same story as CharacterSelectorState. The code exports only
   `window.openHouseholdSelector`.

8. **modals-household-selector.js's filterConfig differs from the
   docs.**
   The docs list `showActive`, `showVacant`, `showEmpty`,
   `locationFilter`, `searchTerm` (5 fields).
   The code's `_defaultFilterConfig()` returns `showActive`,
   `showVacant`, `showEmpty`, `showDeprecated`, `showDeleted`,
   `searchText` (6 fields).
   The docs also omit `showDeprecated` and `showDeleted`, and the
   code uses `searchText` (not `searchTerm`) and has no
   `locationFilter`.

9. **modals-household-selector.js does not have a
   `_selectHousehold(id)` method or a `_filterHouseholds()` method
   as the docs describe.**
   The code inlines filtering into a local `_render()` and
   selection into the delegated row-click handler. The docs list
   `_selectHousehold` and `_filterHouseholds` as public class methods.

10. **selector-base.js does not call `_getIcon` on modals-core.js.**
    selectors-docs.txt lists `_getIcon` (from modals-core.js) as a
    dependency of selector-base.js. Neither the code nor any other
    supplied selector file reads `_getIcon`. The icons-related read
    is via window.getIcon (from icons.js) or window.Icons.

11. **selector-base.js does not call `_escapeHtml` on modals-core.js.**
    Same story: escapeHtml comes from formatting.js via the load-time
    guard, not from modals-core.js.

12. **`_showToast` on modals-core.js.**
    selectors-docs.txt lists `_showToast` as a modals-core.js
    dependency of selector-base.js. In the code, selector-base.js's
    showToast calls window.showToast (from ui.js). `_showToast` is
    NOT called.

13. **`getCurrentYearSafe` vs `getCurrentYear`.**
    selectors-docs.txt (section 3, Core Dependencies) lists
    `getCurrentYearSafe` as the canonical accessor.
    The code's selector-base.js prefers window.getCurrentYear and
    only falls back to window.getCurrentYearSafe. modals-char-selector.js
    requires window.getCurrentYear (canonical) at load time.
    The docs' assumption of getCurrentYearSafe as canonical is
    stale; the canonical accessor is getCurrentYear.

14. **`AGE_GROUPS_MAP`.**
    selectors-docs.txt (section 3) lists `AGE_GROUPS_MAP` as a
    constants.js dependency. There is no `AGE_GROUPS_MAP` in the
    supplied constants.js (age-constants.js defines AGE_GROUPS, and
    constants.js defines LOCAL_STORAGE_KEYS and APP_CONSTANTS). No
    selector file reads AGE_GROUPS_MAP.

15. **"No inline styles" policy vs. actual code.**
    selectors-docs.txt's Key Principles say "No inline styles: All
    styling via CSS classes in external stylesheet." The
    modals-household-selector.js file still uses inline style
    attributes for the row layout, the filter chip layout, and the
    status badge colors. Its own header acknowledges this as a
    deferred cleanup (TODO: selectors-css-migration). Do not rely on
    the docs' claim that the selectors are CSS-only.

16. **"Core has NO system dependencies."**
    selectors-docs.txt asserts that all core files work without any
    system loaded, and that selectors depend only on core. The
    supplied selector files contradict this: modals-char-selector.js
    load-requires character-queries.js, character-commands.js, and
    family-queries.js; modals-household-selector.js load-requires
    household-queries.js. Those are domain files, not core. The docs'
    "Core Only" principle is aspirational but not what the code does.
    See Part 1 for the actual dependency list.

17. **Docs say `query-helpers.js` is "NO system deps".**
    As noted above, the file does not exist. If a future revision
    re-introduces a query-helpers.js, this docs entry should be
    updated; until then, the modals-char-selector.js and
    modals-household-selector.js code reads their data through the
    domain modules, not a core query-helpers layer.

18. **Docs say modals-char-selector.js depends on query-helpers.js.**
    It does not. Its dependencies are selector-base.js,
    character-queries.js, character-commands.js, family-queries.js,
    time.js, accessors.js, and (optionally) relationship-queries.js
    and age-constants.js. The same is true of
    modals-household-selector.js, which depends on selector-base.js
    and household-queries.js.

    order. Runtime callers should assume the SUPERSET contract
    (accepts place OR id). If you need world.js's original
    place-only resolver, reach for it before locationDropdown.js
    loads, or read it from a module-local capture.


================================================================================
PART 7 — KNOWN HAZARDS
================================================================================

 1. selectors-docs.txt is out of sync with the code.
    Do not trust the docs' export lists, dependency lists, or
    load-order section without checking them against the code.
    The specific divergences are enumerated in Part 5.

 2. modals-char-selector.js and modals-household-selector.js are
    NOT "core-only" despite the docs' claim. They require domain
    modules at load time (character-queries.js, character-commands.js,
    family-queries.js, and household-queries.js respectively). A
    page that loads the selectors but not those domains will fail
    at load with a clear error from the selector files' own guards.

 3. The modals-household-selector.js file still uses inline style
    attributes. The docs' "no inline styles" claim is aspirational
    for this file. Do not assume a CSS migration has landed.

 4. window.getFilteredLocationOptions does not exist in the supplied
    locationDropdown.js. If a caller needs it, either shim it or use
    window.buildLocationDropdown directly. Do not assume the
    selectors-docs.txt surface exists.

 5. modals-household-selector.js's _resolveHouseholdSnapshot
    defensively handles HouseholdQueries.getHousehold returning a
    record object, an id string, or null. Do not "simplify" this
    by removing the guard; the extra shape handling is the whole
    point of the function.

 6. SelectorBase.close() does NOT fire state.onCancel. This is
    intentional and matches modals-core.js's modal-close contract.
    Callers who need cancel semantics must let the modal close via
    user action, or call state.onCancel themselves.

 7. Every modal in the selector subsystem scopes its DOM reads via
    the modal element (root) or its descendants. Do not regress this
    to document.getElementById / document.querySelector. Two stacked
    selectors of the same type share element ids, and the document-
    scoped lookup returns the OLDER modal.

 8. window.selectors and js/core/state.js. state.js reads
    LocationUIState, not any selector. Do not add a selector
    dependency to state.js; selectors are on-demand modals, not
    runtime state modules.

 9. modals-char-selector.js inherits escapeHtml, debounce, and
    showToast from SelectorBase.prototype. If a caller reaches into
    the instance from outside (e.g. to override one of these for a
    test), it must be careful not to break the base class's contract
    for subsequent instances. The base class holds no global state;
    per-instance overrides are safe but persistent for that instance.

10. The locationDropdown.js getLocationCountry / getLocationDistrict
    shadowing is intentional. Do not "fix" it by renaming world.js's
    exports; the superset contract is what runtime callers rely on.
    If world.js ever renames its exports to avoid the collision,
    locationDropdown.js's fallbacks become the canonical resolvers
    and no caller breaks.
