================================================================================
PART 1 — FILE INVENTORY AND LAYERS
================================================================================

The apprenticeship subsystem sits ABOVE the relationship, role, and
character domains. It orchestrates their commands and queries; it does
not own them.

  CONSTANTS (leaf; depends on SkillUtils)
    js/apprenticeship/apprenticeship-constants.js

  RULES (pure policy; depends on constants + SkillUtils at load)
    js/apprenticeship/apprenticeship-rules.js

  QUERIES (read-only; composes RelationshipQueries + CharacterCommands
           + RoleState + accessors + time + rules)
    js/apprenticeship/apprenticeship-queries.js

  COMMANDS (writes; composes ProfessionalCommands + CharacterCommands
            + RoleCommands + queries + rules)
    js/apprenticeship/apprenticeship-commands.js

  KNOWLEDGE COMMANDS (parallel write path; composes CharacterCommands
                      + RoleCommands + queries + rules; no
                      ProfessionalCommands)
    js/apprenticeship/professional-knowledge-commands.js

  MODALS (DOM + commands; batch persist per successful action)
    js/apprenticeship/modals-apprenticeship.js

Note the layer ordering:
  constants -> rules -> queries -> commands -> modals
  knowledge-commands depends on CharacterCommands and RoleCommands
  directly (not on ApprenticeshipCommands).

  js/apprenticeship/apprenticeship-constants.js
    Owns: window.APPRENTICESHIP_STAGES,
          window.APPRENTICESHIP_STATUS,
          window.APPRENTICESHIP_ROLES,
          window.TEACHING_CONSTANTS.
    Load-time dependencies (HARD — throw at load if missing):
      window.SkillUtils                 [skill] via skill-utils.js;
        SkillUtils.getThresholds is a LOAD-TIME METHOD CHECK.
    Call-time dependencies:  NONE.
    Consumed by:
      [load] apprenticeship-rules.js     (APPRENTICESHIP_STAGES,
                                          APPRENTICESHIP_STATUS,
                                          TEACHING_CONSTANTS — HARD)
      [load] apprenticeship-commands.js  (TEACHING_CONSTANTS,
                                          via A.APPRENTICESHIP;
                                          reads window.TEACHING_
                                          CONSTANTS indirectly)
      [load] apprenticeship-queries.js   (TEACHING_CONSTANTS —
                                          call-time via
                                          getTeachableSkills /
                                          findPotentialMasters)
      [load] modals-apprenticeship.js    (TEACHING_CONSTANTS,
                                          APPRENTICESHIP_STAGES,
                                          APPRENTICESHIP_STATUS —
                                          HARD)
    Notes:
      - APPRENTICESHIP_STAGES is DERIVED from SkillUtils.TIERS.
        Each stage mirrors a SkillUtils tier by id, name, and
        minLevel/maxLevel. requiredYears is local to apprenticeship.
      - TEACHING_CONSTANTS.MIN_MASTER_SKILL = THRESHOLDS.JOURNEYMAN
        (51). COMPLETION_SKILL = THRESHOLDS.EXPERT (76). Both
        derived from SkillUtils so moving a tier boundary moves them.
      - The module validates its own derivation at load: every
        SkillUtils tier must have a matching stage, stage boundaries
        must equal tier boundaries, MIN_MASTER_SKILL < COMPLETION_SKILL,
        MIN_SKILL < MAX_SKILL. Violations throw.
      - SKILL_LEVELS and SKILL_TRANSFER_METHODS do NOT live here.
        They live in js/professional/skill-constants.js and
        js/professional/skill-transfer-constants.js per the module
        header.

     ("apprenticeship-rules.js requires apprenticeship-constants.js
     (APPRENTICESHIP_STAGES) first.").

 3.  skill-utils.js before apprenticeship-rules.js.
     Failure without it: apprenticeship-rules.js throws at load
     ("apprenticeship-rules.js requires skill-utils.js
     (SkillUtils) first.").

 4.  relationship-types.js before apprenticeship-queries.js and
     apprenticeship-commands.js.
     Failure without it: both throw at load
     ("requires relationship-types.js (RELATIONSHIP_ARCHETYPES)

     Failure without it: apprenticeship-queries.js throws at load
     ("requires relationship-queries.js (RelationshipQueries)

     apprenticeship-queries.js.
     Failure without it: apprenticeship-queries.js throws at load

     ("requires apprenticeship-rules.js

     apprenticeship-queries.js, apprenticeship-commands.js,
     apprenticeship-rules.js, apprenticeship-constants.js
     (TEACHING_CONSTANTS, APPRENTICESHIP_STAGES,
     APPRENTICESHIP_STATUS) before modals-apprenticeship.js.
     Failure without any: modals-apprenticeship.js throws at load
     naming the missing module.

 15. core/world.js before the first call to a modal that needs
     location resolution.
     Failure without it: no load-time throw. _getCurrentLocation
     returns null; location display shows "Unknown". This is a
     soft degradation, not a hard error. Prior revisions required
     window.getCurrentLocation which accessors.js does not export;
     that dependency has been removed.

 16. CharacterCommands methods (addProfession, updateProfession,
     getProfession, getProfessions) and
     RoleCommands.recordCharacterSkillProgress before
     professional-knowledge-commands.js's first call to
     preserveKnowledgeOnDeath or assessKnowledgeLoss.
     Failure without any: the module throws at call time
     ("ProfessionalKnowledgeCommands requires
     CharacterCommands.<name>" or "requires
     RoleCommands.recordCharacterSkillProgress").

 17. RoleState.getRole OR window.getRoleById before
     professional-knowledge-commands.js's first call to a
     role-resolving function.
     Failure without BOTH: the module throws at call time
     ("ProfessionalKnowledgeCommands: no role reader available.
     Load role-state.js (RoleState.getRole) or accessors.js
     (getRoleById) before using this module.").

 18. window.SKILL_TRANSFER_METHODS [UNVERIFIED] before the first
     call to apprenticeship-commands.js::teachSkill.
     Failure without it: every methodId is rejected as
     UNKNOWN_METHOD, even when the caller supplied a valid id.

 19. window.Random.next OR window.randomNext before the first
     call to apprenticeship-commands.js::teachSkill or any other
     command that needs a roll.
     Failure without either: _roll throws at call time.

 20. core/storage.js before apprenticeship-commands.js::persist is
     first called.
     Failure without it: persist() returns
     { success: false, reason: 'saveMasterData is not available.' }.
     The commands themselves still mutate in-memory state; only
     the flush fails.


================================================================================
PART 7 — KNOWN HAZARDS
================================================================================

 1.  apprenticeship-doc.txt is truncated.
     The supplied narrative doc ends at §1 "Ownership chain:" with
     no further content. This dependency document is derived from
     the code, not from the (missing) narrative sections. Update
     the narrative doc before citing it as authoritative.

 2.  Role skill authority.
     character.professions[].skillLevel is canonical. Education's
     character.subjectProgress['role_<id>'].level is educational
     progress and may legitimately differ. Apprenticeship reports
     progression through RoleCommands.recordCharacterSkillProgress
     (which enforces the non-decreasing invariant); it does NOT
     write character.professions directly.

 3.  Role creation vs progression.
     addProfession (creation) and
     RoleCommands.recordCharacterSkillProgress (progression) are
     distinct. The invariant does not apply to creation.
     apprenticeship-commands.js and
     professional-knowledge-commands.js both route creation
     through addProfession and progression through
     recordCharacterSkillProgress.

 4.  _getRoleById LENIENT vs STRICT in
     apprenticeship-commands.js and
     professional-knowledge-commands.js.
     - apprenticeship-commands.js::_getRoleById is LENIENT
       (display only, returns null when the role is missing).
       _requireRoleForWrite is STRICT (throws when the role is
       missing).
     - professional-knowledge-commands.js::_getRoleById THROWS
       when NEITHER RoleState.getRole NOR window.getRoleById is
       available. It returns null when one is available but the
       role is missing.
     - The behavioral difference is intentional:
       apprenticeship-commands.js is called from display paths
       that tolerate a null; professional-knowledge-commands.js is
       called from the death cascade where a load-order bug must
       surface. Do not unify without auditing both.

 5.  RoleState.getRole is the canonical runtime role reader.
     RoleState.getRole returns CLONES as of the current role
     subsystem. Apprenticeship code does not mutate the returned
     role. After role-system.js loads, window.getRoleById is
     aliased to RoleState.getRole, so the fallback in
     apprenticeship-commands.js and
     professional-knowledge-commands.js returns clones too.

 6.  MULTI-ROLE DISAMBIGUATION.
     A character may have concurrent apprenticeships with multiple
     masters for different roles.
     - getApprenticeship(masterId, apprenticeId, roleId) REQUIRES
       roleId. Omitting it throws.
     - getOngoingApprenticeship throws when the pair has more
       than one ongoing apprenticeship.
     - progressApprenticeship, teachSkill, teachSpecialization
       accept an OPTIONAL roleId and return
       { code: 'MULTIPLE_ROLES' } when omitted and ambiguous.
       They do NOT throw.
     - Modals-apprenticeship.js passes roleId whenever it is in
       scope.

 7.  PARTIAL-TRANSACTION ROLLBACK on createApprenticeship.
     The profession write to the apprentice is the preparatory
     step; the edge creation is the atomic commit point. On edge
     creation failure, the profession write is reverted via
     _revertEnsureProfession. Revert failures are logged but do
     not change the returned result — the edge failure is the
     reported outcome.

 8.  HALF-TRANSACTION RISK in
     professional-knowledge-commands.js.
     preserveKnowledgeOnDeath writes each dying profession to the
     heir INDEPENDENTLY. If a later step fails, earlier steps are
     already in memory. This command does NOT revert on partial
     failure — the caller's death cascade is the atomic boundary.
     Callers of preserveKnowledgeOnDeath must ensure a flush
     happens after the cascade completes successfully. Failures
     within the loop are logged via console.warn but do not abort
     the loop.

 9.  PERSISTENCE divergence across domains.
     - ApprenticeshipCommands.persist returns
       { success, reason? } (Pattern A + getLastSaveError).
     - ProfessionalKnowledgeCommands does NOT expose a persist()
       function; the caller's death cascade owns persistence.
     - EducationCommands.persist returns a BOOLEAN.
     - RankCommands.persist and ReligionCommands.persist and
       RoleCommands.persist and NameCommands.persist return
       { success, reason? } and read getLastSaveError
       (typeof-guarded).
     - CultureCommands.persist returns { success, reason? } but
       does NOT read getLastSaveError.
     - GovernmentCommands.persist returns { success: false } but
       does not throw and does not read getLastSaveError.
     - SettlementCommandCommit throws on persist failure.
     Do not unify without updating every caller's error-handling.

 10. _handleRoleDeleted robustness.
     Wraps each cancelApprenticeship in try/catch. Calls persist()
     ONCE after the loop. Prior revisions let a single throw abort
     the loop, orphaning the remaining apprenticeships.
     Failed cancels are counted in `failed` and logged via
     console.warn.

 11. updateApprenticeship gates its writes.
     updateEdgeMetadata runs ONLY when metaChanged. endEdge runs
     ONLY when statusChanged. Prior revisions called endEdge
     unconditionally on update, even for a same-status no-op.

 12. Randomness source.
     window.Random.next is the canonical RNG stream (also used by
     affair-commands.js, jealousy-commands.js,
     relationship-integrations.js). A legacy window.randomNext
     fallback is honoured. There is NO Math.random call and NO
     window.RNG reference (window.RNG does not exist in this
     tree).

 13. SKILL_TRANSFER_METHODS [UNVERIFIED].
     teachSkill reads window.SKILL_TRANSFER_METHODS, which lives
     in js/professional/skill-transfer-constants.js. The file is
     referenced but not in the supplied batch. Missing file ->
     every methodId is rejected as UNKNOWN_METHOD. Confirm the
     provider before relying on teachSkill.

 14. modals-apprenticeship.js location resolution.
     Uses world.js's getCurrentPlace / getCurrentLocationId
     (soft). Prior revisions required window.getCurrentLocation
     which accessors.js does not export. The REQUIRED array has
     been corrected; the modal loads without world.js and shows
     "Unknown" for location display.

 15. modals-apprenticeship.js icon lookup.
     Uses window.Icons[name] with CIRCLE fallback via the local
     _getIcon wrapper. Does NOT depend on window._getIcon (which
     does not exist). Do not reintroduce a _getIcon dependency.

 16. modals-apprenticeship.js confirm form.
     _confirm enforces the THREE-argument
     confirmDialog(message, title, onConfirm) form. The
     two-argument form sends the callback into the title slot.

 17. modals-apprenticeship.js _showToast provider.
     Tries _showToast (primary), then showToast (fallback), then
     one-shot console.warn. Do not add a hard dependency on
     window._showToast; it is a deprecated alias.

 18. modals-apprenticeship.js modal lifecycle.
     Every modal uses onMount. Element lookups are scoped to the
     modal element. Do not regress to a setTimeout or
     document.getElementById pattern.

 19. professional-knowledge-commands.js is NOT called by
     modals-apprenticeship.js.
     Knowledge preservation runs from the death cascade
     (character-lifecycle.js or its orchestrator). The modal file
     does not need ProfessionalKnowledgeCommands loaded.

 20. Apprenticeship queries read professions via
     CharacterCommands.getProfessions.
     The character projection may or may not include professions
     (it is not documented as guaranteed). getTeachableSkills
     reads through the command layer, never the projection.
     Similarly, professional-knowledge-commands.js reads the
     dying character's professions via getProfessions, not off
     the projection.

 21. getApprenticeshipsByRole complexity.
     O(apprenticeships) per call. Called from
     _handleRoleDeleted on every roleDeleted event. If the
     apprenticeship catalogue grows large, role deletion becomes
     visibly slow. The fix, if it ever matters, is a role-index in
     RelationshipQueries.

 22. getApprenticeshipDetails ended-record handling.
     By default returns the ONGOING record only. Pass
     { includeEnded: true } to include ended records;
     getApprenticeshipDetailsById returns any status. Prior
     revisions always returned null for ended records, which
     prevented the details modal from displaying them.

 23. Apprenticeship has no hydrate/init.
     Its state lives on relationship edges (owned by
     RelationshipState) and on character profession records
     (owned by CharacterCommands). There is no
     ApprenticeshipState module and no bootstrap to run.

 24. modals-apprenticeship.js includes APPRENTICESHIP_STAGES in
     the REQUIRED load guards.
     The modal does not read APPRENTICESHIP_STAGES directly in
     the supplied code (it reads TEACHING_CONSTANTS and
     APPRENTICESHIP_STATUS). The guard is present because the
     modal contract is scoped to the apprenticeship subsystem,
     whose constants module installs all three. Do not remove the
     guard without verifying no future revision reads the
     constant.

 25. getMaster throws on multiple active masters.
     A character with multiple active masters must use getMasters().
     The singular convenience deliberately throws — silently
     returning the first master would silently drop the others.

 26. findPotentialMasters entries without skillLevel pass
     through unchanged.
     SettlementQueries.getSettlementMastersByRole is permitted to
     omit skillLevel on entries; this module does not invent a
     default. Callers that need the threshold enforced must use a
     settlement query that provides skillLevel. Documented in the
     JSDoc for findPotentialMasters.

 27. professional-knowledge-commands.js's
     _requireRoleForWrite is present but unused.
     Both write paths operate on professions, not roles. It is
     present for symmetry with education-commands.js and
     apprenticeship-commands.js so any future role write has a
     consistent strict accessor. Do not remove it as dead code
     without auditing the intent.

 28. apprencticeship-doc.txt reference.
     The narrative doc is truncated in the supplied batch. Do not
     cite its §2 (load order), §3 (data model), etc., since those
     sections are not available. This dependency document plus the
     code are the source of truth until the narrative doc is
     completed.

 29. js/core/constants/relationship-constants.js vs
     js/relationships/relationship-types.js.
     Both may provide RELATIONSHIP_STATUS at different scopes.
     Apprenticeship reads window.RELATIONSHIP_STATUS, which is
     installed by js/relationships/relationship-types.js
     (per the LOAD-TIME GUARD). js/core/constants/relationship-
     constants.js is a CORE module; if it also exports
     RELATIONSHIP_STATUS, the load order determines the winner.
     Do not rely on the CORE constants' RELATIONSHIP_STATUS unless
     you verify the alias collision.

 30. Apprenticeship and education share the role skill write
     path.
     Both route progression through
     RoleCommands.recordCharacterSkillProgress. If the role
     domain's invariant ever needs adjustment (e.g. allowing a
     downward correction for a specific kind of training), the
     change must happen in RoleCommands — not here. Do not
     re-implement the invariant in apprenticeship code.

 31. Apprenticeship and professional-knowledge commands do NOT
     touch the character projection's profession fields.
     Every write is through CharacterCommands. Do not read
     character.professions off the projection for any purpose;
     use getProfession / getProfessions.

 32. Apprenticeship queries require
     SettlementQueries.getSettlementMastersByRole for
     findPotentialMasters.
     Absence is not a "no masters found" state; the function
     throws. Do not add a silent empty-result fallback.

 33. Career-stage label consistency.
     APPRENTICESHIP_STAGES is derived from SkillUtils.TIERS, so
     every stage name (Untrained, Novice, Apprentice, Journeyman,
     Expert, Master) matches SkillUtils. Modals, education-annual,
     and rank all read the SAME taxonomy. Do not add a second
     stage vocabulary.

 34. Apprenticeship modals' _persistAndWarn is REQUIRED after
     every mutating command.
     Every mutating handler in modals-apprenticeship.js calls
     _persistAndWarn(successMessage). Missing this means the
     user's action lives only in memory until the next
     markDataDirty-triggering action. Do not add a new mutating
     path that skips it.

 35. modals-apprenticeship.js's openApprenticeshipDetailsModal
     closes and re-opens the modal on progress.
     The progress action closes the current modal, mutates,
     persists, then re-opens the details modal fresh. Do not
     regress to in-place refresh; the details modal has no
     refresh contract.
