# Crime & Law System — Domain Documentation

Version: 6.1 (core-compatibility pass)
Replaces: `crime-docs.txt`
Owns: `crimes`, `vendettas` on `masterData.data`
Depends on: Character, Household, Location, Settlement, Religion, Industry

Version history:
    6.0  Post-refactor baseline.
    6.1  Core-compatibility pass. All crime modules now use canonical
         core helpers (getCurrentYear, escapeHtml, showToast, getIcon).
         Deprecated aliases (getCurrentYearSafe, _escapeHtml, _showToast,
         _getIcon) are no longer used anywhere in the crime domain.
         Cross-domain resolver in crime-law-integration.js and
         crime-bootstrap.js corrected to point at the canonical
         settlement query modules (SettlementLawQueries,
         SettlementReligionQueries) instead of methods that do not
         exist on SettlementQueries. Modals now use the core modal
         shell's accepted keys (titleHtml/contentHtml) and its return
         shape (result.element); the previous code passed title/content
         and read result.content, both of which the core ignores.

## 1. Ownership contract

The Crime domain owns exactly two canonical arrays on `masterData.data`:

| Array | Shape | Owner |
|---|---|---|
| `crimes` | `[{ id, type, perpetratorId, perpetratorName, victimId, victimName, year, reason, locationId, witnesses[], evidence[], solved, solvedAt, solution, punishment, method, severity, recordedAt, notes, metadata, civilViolation, religiousViolation, religionId, violatedLaws[] }]` | Crime |
| `vendettas` | `[{ id, householdAId, householdAName, householdBId, householdBName, characterAId, characterAName, characterBId, characterBName, cause, originCrimeId, startedYear, status, deaths[], escalatedAt, resolvedAt, resolution, notes, createdAt, updatedAt }]` | Crime |

Crime **does not** own:

| Data | Owner | Read via | Written via |
|---|---|---|---|
| Character identity, death, professions | Character | `getCharacterById`, `getCurrentLocationId` (global) | `killCharacter`, `CharacterCommands.addProfession` (for profession additions) |
| Household membership, prestige, crime history | Household | `getHouseholdById` | `HouseholdCommands.applyPerpetratorCrime` / `applyVictimCrime` / `applyExecutionToHousehold` |
| Places, leaders, government assignment | Location | `getPlaceById`, `getCurrentLocationId` | — |
| Government type, justice severity, watch, settlement wealth/debt, civil laws | Settlement | `SettlementQueries.getSettlementData`, `SettlementLawQueries.getCivilLaws`, `SettlementReligionQueries.getDominantReligion` | `SettlementGovernmentCommands.setJusticeSeverity` / `setWatch`, `SettlementLawCommands` |
| Religious laws, religion membership | Religion | `ReligionLaws.getLawsByReligion`, `ReligionQueries.getReligion` / `getAllReligions` | — |
| Enterprises and their impact on settlement income | Industry | `IndustryQueries.getIndustryTaxRevenue` / `getIndustryEnterpriseStats` | — |
| Relationships | Character | `getRelationshipsForCharacter`, `endRelationship` (globals) | those same globals |

Cross-domain **writes** go through the owning domain's commands. Cross-domain **reads** go through the owning domain's queries. Crime code never writes into another domain's canonical arrays.

### Canonical law sources

The ownership table above names the correct modules. The following
resolvers in `crime-law-integration.js` consume those modules. Each
resolver tries the canonical source first, then a documented
alternative, then throws:

    _getCivilLaws(locationId)
        SettlementLawQueries.getCivilLaws          ← canonical
        GovernmentLaws.getCivilLaws                ← alternative
        throw otherwise

    _getReligionLaws(religionId)
        ReligionLaws.getLawsByReligion             ← canonical
        ReligionState.getLawsByReligion            ← alternative
        throw otherwise

    _getDominantReligion(locationId)
        SettlementReligionQueries.getDominantReligion  ← canonical
        SettlementState.getDominantReligion            ← alternative
        throw otherwise

    _getSettlementData(locationId)
        SettlementState.getSettlementData          ← canonical
        window.getSettlementData                   ← alternative

Note: `SettlementQueries.getDominantReligion` and
`SettlementQueries.getCivilLaws` do NOT exist. Those methods belong
to `SettlementReligionQueries` and `SettlementLawQueries`
respectively. If a future contributor sees a resolver probing
`SettlementQueries` for those methods, it is a bug — the probe will
always fail. The v6.1 pass removed all such dead probes.

### File inventory

Each crime module lives at `js/crime/<file>`. The pre-refactor path
`js/core/crime/<file>` is no longer used and must not appear in any
HTML script tag.

    js/crime/crime-constants.js          vocabulary and defaults
    js/crime/crime-state.js              canonical records + indexes
    js/crime/crime-law-integration.js    applicability + evaluation
    js/crime/crime-queries.js            derived read API
    js/crime/crime-commands.js           orchestration + persist
    js/crime/crime-view-models.js        presentation shaping
    js/crime/crime-ui-stats.js           DOM rendering for stats
    js/crime/modals-crime.js             modal lifecycle
    js/crime/crime-bootstrap.js          load-time verification
    js/crime/vendetta-system.js          DEPRECATED compatibility shim

`vendetta-system.js` is retained only so pre-refactor callers that
reference `window.VendettaSystem.*` do not break during migration.
Every one of its functions forwards to the canonical implementation
in `CrimeState`, `CrimeCommands`, or `CrimeQueries` and emits a
one-time deprecation warning. New code must not use it.

## 3. Core compatibility

The crime domain relies on the canonical core helpers. The following
patterns are prohibited in crime modules. Each one was present in the
pre-v6.1 code and was removed by the compatibility pass.

### Time

    PROHIBITED:  window.getCurrentYearSafe()
    CANONICAL:   window.getCurrentYear()

`getCurrentYearSafe` is a deprecated alias in `js/core/time.js`. Every
crime module uses the canonical name. The pattern `return 1250;` as a
fallback does not exist in this domain. A missing `getCurrentYear` is
an application load failure, not a fabricated year.

Files affected by the v6.1 pass:
    crime-bootstrap.js        (verify globals)
    crime-view-models.js      (_currentYear helper)
    crime-queries.js          (_getCurrentYear helper)
    crime-state.js            (_now helper)
    crime-commands.js         (_now helper)
    modals-crime.js           (default year in three submit paths)

### UI helpers

    PROHIBITED:  window._escapeHtml(), window._showToast(), window._getIcon()
    CANONICAL:   window.escapeHtml(), window.showToast(), window.getIcon()

The underscore-prefixed names are deprecated aliases. Every crime
module uses the canonical names. Loading a crime module against a
future core where the aliases are removed must not break.

Files affected:
    modals-crime.js           (load guards, all inline escape/toast/icon calls)
    crime-ui-stats.js         (load guard, getIcon helper)

### Modal infrastructure

The core modal shell is `js/core/modals-core.js`. It exposes:

    window.openModal(options)  →  { element, close }
    window.closeTopModal()
    window.showToast(message, type)    (from ui.js)
    window.confirmDialog(message, title, onConfirm)
    window.escapeHtml(str)             (from formatting.js)
    window.getIcon(name)               (from icons.js)

The accepted keys on `openModal` are:

    titleHtml      trusted HTML for the modal title
    contentHtml    trusted HTML for the modal body
    confirmText    button label
    cancelText     button label ('' hides the cancel button)
    onMount        fn(element)   — called after DOM insertion
    onConfirm      fn(element)   — called on confirm; return false to keep open
    size           'small' | 'medium' | 'large'

The keys `title` and `content` are silently ignored. A modal that
passes those renders with the default title ("Modal") and an empty
body. The v6.1 pass corrected 7 modal call sites.

The return value is `{ element, close }`. Event delegation must
attach to `result.element`. The v6.1 pass corrected all 6 crime
modals to read `result.element` instead of `result.content`.

There is no `window.ModalsCore` namespace. Some pre-refactor files in
other domains reference one; those files are legacy and must be
migrated to the direct globals before they will work.

Files affected:
    modals-crime.js           (all 6 modal call sites)

### Cross-domain resolver naming

The settlement domain splits its read APIs across several query
modules. The following names do NOT exist:

    SettlementQueries.getDominantReligion     → SettlementReligionQueries.getDominantReligion
    SettlementQueries.getCivilLaws            → SettlementLawQueries.getCivilLaws
    SettlementState.getCivilLaws              → SettlementLawQueries.getCivilLaws
    SettlementState.getDominantReligion       → SettlementReligionQueries.getDominantReligion
                                              (SettlementState retained as alternative — see §1)

A resolver that probes these dead names will always fail. The v6.1
pass removed all such probes from `crime-law-integration.js` and
`crime-bootstrap.js`.

The crime domain's cross-domain resolvers are documented in §1
under "Canonical law sources".

### Bootstrap verification

`crime-bootstrap.js` verifies the surfaces above at load. If a
dependency is missing or wrong, the page fails at load with a clear
message naming the missing item. The bootstrap does NOT fall back to
silent degradation for any required dependency.

Optional dependencies (currently `SettlementGovernmentCommands
.recordCrimeImpact`) are warned once on first use and skipped. No
other dependency is optional.

## 4. State contract

`CrimeState` (`js/crime/crime-state.js`) is the domain authority for
canonical crime and vendetta records. It owns:

  - the canonical arrays (`masterData.data.crimes`,
    `masterData.data.vendettas`)
  - indexes over those arrays
  - lifecycle transitions (record → solve; active → escalated →
    resolved)
  - subscription notification

It does not:
  - save (`CrimeCommands.persist` owns the write)
  - decide punishments or consequences (`CrimeLawIntegration`)
  - compute statistics (`CrimeQueries`)
  - orchestrate workflows (`CrimeCommands`)

### Public reads return clones

Every public read (`getCrime`, `getAllCrimes`, `getCrimesByPerpetrator`,
`getCrimesByVictim`, `getCrimesInvolvingCharacter`, `getCrimesByType`,
`getCrimesByLocation`, `getUnsolvedCrimes`, `getCrimeCount`,
`getVendetta`, `getAllVendettas`, `getVendettasByHousehold`,
`getVendettasByCharacter`, `getActiveVendettas`,
`getActiveVendettaBetween`, `getVendettaCount`) returns deep clones.
Callers cannot mutate canonical state through a returned object.

### Canonical accessors

`_getCrimeCanonical`, `_getAllCrimesCanonical`, `_getVendettaCanonical`,
`_getAllVendettasCanonical`, and `_setVendettaStatus` return live
records and are reserved for `CrimeCommands` and `CrimeLawIntegration`
during a command. Anything else must use the public reads.

### Mutation primitives

`recordCrime`, `solveCrime`, `deleteCrime`, `createVendetta`,
`recordVendettaDeath`, `resolveVendetta`, `deleteVendetta` each:

  1. Acquire a mutation lock (single-threaded recursive-call guard)
  2. Hydrate from masterData if not yet hydrated
  3. Perform the mutation
  4. Call `window.markDataDirty()`
  5. Publish the event to subscribers
  6. Release the mutation lock
  7. Return `{ success: true, data: ... }` or
     `{ success: false, reason, code }`

They do NOT save, do NOT dispatch `CustomEvent`, and do NOT modify
indexes for other records. The commands own the commit tail.

### Lifecycle invariants

  - A crime is either solved or not. `solved === true` implies
    `solvedAt` is a year; `solved === false` implies `solvedAt` is
    null. `recordCrime` NEVER records a solved crime — the invariant
    is enforced by ignoring `data.solved`. `triggerExecution` records
    the crime unsolved, then calls `solveCrime` immediately.

  - A vendetta's status only reaches `ESCALATED` via
    `recordVendettaDeath` (automatic at the threshold) or via the
    explicit `_setVendettaStatus` primitive (called by
    `CrimeCommands.escalateVendetta`). It only reaches `RESOLVED` via
    `resolveVendetta`.

  - Historical snapshot fields (`perpetratorName`, `victimName`,
    `householdAName`, `householdBName`, `characterAName`,
    `characterBName`) are snapshots at time of recording and are
    never refreshed from live sources.

### Cache management

  - `hydrateFromMasterData(force)` — idempotent. If `force` is falsy
    and indexes are already built, no-op. If `force` is true, rebuild
    from masterData regardless. Throws on duplicate IDs, missing
    IDs, or malformed canonical shape.

  - `reload()` — clears indexes and forces a full rebuild. Publishes
    `STATE_EVENTS.CACHE_RELOADED` on success. Returns `true` on
    success, `false` on failure (which is also logged to console).

  - `invalidateCache()` — legacy alias for `reload()`.

  - `validateIntegrity()` — warn-only. Returns an array of warning
    strings and logs them via `console.warn`. Does NOT throw. Used by
    `crime-bootstrap.js` on first load.

## 5. Command contract

`CrimeCommands` (`js/crime/crime-commands.js`) is the orchestration
layer. It does NOT decide legal consequences; it executes what
`CrimeLawIntegration.evaluateAction()` returns.

### Result shape

Every command returns:

    { success: true, data: {...} }
    { success: false, reason: string, code?: string }

Codes come from `CrimeConstants.CODES`. Codes are stable strings and
may be switched on by callers. Codes are never removed once they
have appeared in a shipped result.

### The four public commands

`triggerMurder(victimId, killerId, options)`:

  1. Resolve victim and killer, validate (both exist, victim alive,
     not self)
  2. Resolve year, reason, killerGotAway, startVendetta, location
  3. Call `Law.evaluateAction(killerId, action, context)`
  4. `State.recordCrime(...)` (unsolved)
  5. If `!killerGotAway`: `State.solveCrime(...)` (solved)
  6. `window.killCharacter(victim, year, 'Murdered', {...})`
  7. Execute legal consequences (currently: only EXECUTION
     consequences are handled; other consequence types are returned
     with `applied: false, reason: 'no-handler'` and surfaced to the
     caller without being guessed at)
  8. If `startVendetta` and different households:
     `createBloodFeud(...)`
  9. Apply household side effects via
     `HouseholdCommands.applyVictimCrime` /
     `applyPerpetratorCrime`
  10. Apply settlement side effects via
      `SettlementGovernmentCommands.recordCrimeImpact` (optional)
  11. `logEvent('murder', 'Murder', ...)`
  12. `_commit(C.EVENTS.CRIME_RECORDED, {...})`

`triggerExecution(condemnedId, options)`:

  1. Resolve condemned, validate (exists, alive)
  2. Resolve year, reason, method, executionerId, location
  3. If `executionerId`: `Law.evaluateAction(...)`. Else: skip law
     evaluation (executions by "the state" have no executioner to
     evaluate).
  4. `State.recordCrime(...)` (unsolved)
  5. `State.solveCrime(...)` (solved — the outcome is legally
     determined)
  6. `window.killCharacter(...)`
  7. If `endRelationships !== false`: for each ongoing relationship,
     `window.endRelationship(...)`
  8. Apply household side effects via
     `HouseholdCommands.applyExecutionToHousehold`
  9. Apply settlement side effects via `recordCrimeImpact` (optional)
  10. `logEvent('execution', 'Execution', ...)`
  11. `_commit(C.EVENTS.CRIME_RECORDED, {...})`

`escalateVendetta(vendettaId, options)`:

  Two modes. See command body for full details.

  Without `options.force`:
     Succeeds only if the vendetta has reached
     `C.VENDETTA_ESCALATION_THRESHOLD`. This is the retry path for
     automatic escalation that somehow did not fire.

  With `options.force === true`:
     Succeeds regardless of the death count, but requires
     `options.reason` for the audit trail.

  Returns `{ success: true, data: { vendetta, escalated } }` where
  `escalated` is true if the call transitioned the vendetta to
  ESCALATED, false if it was already ESCALATED (idempotent).

`createBloodFeud(victimId, killerId, options)`:

  Called by `triggerMurder`. Derives household IDs from the two
  characters. If a vendetta already exists between those households,
  records a new death on it. Otherwise creates a new vendetta and
  records the first death.

### The commit tail

Every command that mutates calls `_commit(eventName, payload)`. That
helper performs, in order:

  1. `State.hydrateFromMasterData(true)` — force rebuild of indexes
  2. `window.markDataDirty()` — flag for next save
  3. `State.publish(eventName, payload)` — in-process subscribers
  4. `window.dispatchEvent(new CustomEvent(eventName, { detail }))` —
     cross-domain consumers

It does NOT save. Persistence is `CrimeCommands.persist()`.

### Persistence boundary

`CrimeCommands.persist()`:

  1. If `window.saveMasterData` is missing, return
     `{ success: false, reason: 'saveMasterData unavailable',
     code: C.CODES.PERSIST_FAILED }`.
  2. Call `window.saveMasterData()`.
  3. Return `{ success: true, data: null }` or
     `{ success: false, reason, code: PERSIST_FAILED }`.

The UI calls `persist()` exactly once per user action, after the
command returns success. `modals-crime.js` does this via
`_commitAndPersist()`.

### Household side effects

All household effects route through `HouseholdCommands`:

    HouseholdCommands.applyPerpetratorCrime(householdId, params)
    HouseholdCommands.applyVictimCrime(householdId, params)
    HouseholdCommands.applyExecutionToHousehold(householdId, params)

Each is a required dependency of `crime-commands.js`. If
`HouseholdCommands` is missing, the module fails at load with a
clear error naming the missing surface.

### Settlement side effects

`SettlementGovernmentCommands.recordCrimeImpact(locationId,
eventData)` is optional. If absent, crime-commands warns once on
first use and skips the settlement effect. If present but broken
(module loaded, method missing), that is a boot-order failure — the
warn-once path is only for the "whole module is absent" case.

### Legal consequence execution

`_executeConsequence(consequence, ctx)` handles:

    EXECUTION         → triggerExecution(...)
    IMPRISONMENT      → { applied: false, reason: 'no-handler' }
    EXILE             → { applied: false, reason: 'no-handler' }
    FINE              → { applied: false, reason: 'no-handler' }
    PENANCE           → { applied: false, reason: 'no-handler' }
    EXCOMMUNICATION   → { applied: false, reason: 'no-handler' }
    OTHER             → { applied: false, reason: 'unrecognised' }
    (unknown)         → { applied: false, reason: 'unrecognised' }

Unhandled consequences are returned to the caller in the result's
`consequenceResults` array. They are never silently dropped, and the
caller is never told a consequence was applied that was not.

## 6. Query contract

`CrimeQueries` (`js/crime/crime-queries.js`) is the application-facing
read API. It composes the primitive reads from `CrimeState` into
derived statistics.

### Result shape

Queries return their natural values:

  - `getCrime(id)` → crime record or null
  - `getAllCrimes()` → array (clones)
  - `getCrimesByPerpetrator(id)` → array (clones)
  - `getCrimesByVictim(id)` → array (clones)
  - `getCrimesInvolvingCharacter(id)` → array (clones, deduplicated
    across perpetrator and victim)
  - `getCrimesByCharacter(id)` → array (LEGACY alias for
    getCrimesByPerpetrator)
  - `getCrimesByType(type)` → array (clones)
  - `getCrimesByLocation(id)` → array (clones)
  - `getUnsolvedCrimes()` → array (clones)
  - `getCrimeCount()` → number

Vendetta queries have the same shape. `includeResolved` defaults to
TRUE (resolved vendettas are included). Pass
`{ includeResolved: false }` to exclude them.

### Statistics

`getLocationCrimeStats(locationId, year, windowYears)` returns a
structure whose `period` field carries `{ startYear, endYear,
windowYears }` — the exact window used for the "recent" columns. All
other statistics in the result cover the FULL history for that
location. The `year` argument selects the reference year for the
recent window; it is NOT a filter on `totalCrimes` and is NOT a
filter on the derived distributions.

`getOverallCrimeStats(year, windowYears)` has the same semantics
globally.

`getCrimeSeverityStats()`, `getCrimeClearanceRate()`, and
`getCrimeTrends(locationId, years, endYear)` are also available. See
the query reference below.

### Crime burden semantics

The metric `crimeBurden` is "historical recorded crimes per current
resident". It is NOT a rate (it is not temporal), and it does not
cover a specific window. `recentCrimeBurden` is the equivalent for
the recent window. Both are null when the population accessor
(`getLocationPopulationCount`) is unavailable.

`getNormalizedCrimeBurden(locationId, year, windowYears)` clamps the
value into [0, 1] for UI code that expects a bounded scalar. The
unclamped value remains available on the location stats result.

`getCrimeRateByLocation(locationId)` is a LEGACY alias for
`getNormalizedCrimeBurden`. Documented as lossy; prefer the
non-aliased name.

### Empty vs missing

A missing settlement/location is null.
An existing location with zero crimes is an empty array or zero
count. These are not the same, and this module never conflates them.

## 7. Law integration contract

`CrimeLawIntegration` (`js/crime/crime-law-integration.js`) is the
boundary between Crime and the two law systems (civil via Settlement,
religious via Religion).

### Applicability

`getApplicableLaws(characterId, domain)` returns all laws that apply
to the character, regardless of enforcement status. Each item is:

    {
      law:         the law record,
      source:      'civil' | 'religious',
      sourceId:    locationId (civil) or religionId (religious),
      sourceName:  resolved display name,
      applicability: 'universal' | 'follower' | 'official_religion',
      isEnforced:  boolean
    }

Applicability modes:

  `universal`         Civil laws. Apply to everyone in the location.

  `follower`          Religious laws of the character's own religion.
                      Apply only to followers.

  `official_religion` Religious laws of the settlement's dominant
                      religion in a theocracy or a settlement with
                      `useReligiousLawsAsCivil === true`. Apply to
                      everyone, always enforced.

`getEnforcedLaws(characterId, domain)` returns only the subset
whose `isEnforced === true`. This is the correct entry point for
enforcement logic.

### Action evaluation

`evaluateAction(characterId, action, context)` returns:

    {
      lawful:        boolean,
      violations:    all violations (civil + religious, post-supremacy),
      civil:         civil violations after supremacy,
      religious:     religious violations after supremacy,
      governingLaw:  highest-severity enforced violation, or null,
      consequences:  derived consequences (enforced only)
    }

`action` must include `type` and `domain`. `context` may include
`locationId` (overrides the character's current location) and any
other fields the law's violationCheck might read.

### Supremacy

In a theocracy or `useReligiousLawsAsCivil` settlement, the state
religion's law governs. If any religious violation exists, it takes
precedence and civil violations are folded into it. This is applied
INSIDE `evaluateAction`; there is no separate "apply supremacy
afterwards" step.

### Violation detection

A law only criminalises an action if it explicitly opts in.
Matching the law's `domain` against the action's `domain` is NOT
sufficient — any violence-domain law would otherwise catch any
violent action. Explicit opt-in is one of:

  - `law.crimeMapping.crimeType === action.type`
  - `law.crimeMapping.crimeTypes` contains `action.type`
  - `law.violationCheck(action, context)` returns true

Modifiers (`law.modifiers`) further constrain the match: each key
must equal the corresponding value on `action.details[key]` or
`context[key]`. Falsy values (0, false, '') are legitimate; only
undefined falls through to the secondary source.

### Consequences

Consequences are derived only from ENFORCED violations. A law that
is applicable but not enforced produces no consequence.

The consequences array is never populated with invented punishments.
If a law is enforced but declares no consequence, the result includes
`{ type: 'other', description: null, source: {...} }` so the caller
knows the law was enforced without a prescribed punishment.

Each consequence has shape:

    {
      type:        one of CONSEQUENCE_TYPES, or 'other',
      description: string | null,
      method:      string | null,   (for EXECUTION)
      authority:   string | null,
      source:      { lawId, lawName, source, sourceId, sourceName }
    }

The command layer executes what it recognises (currently: EXECUTION).
Unrecognised types are returned with `applied: false` and surfaced
to the caller.

### Search and statistics

`searchLaws(query, locationId, religionId)` searches either civil
laws of a location, religious laws of a religion, or both. Empty
arguments to both `locationId` and `religionId` search all known
locations and all known religions. If a source fails to load, it is
skipped and the search continues — search is a UI-facing best-effort
operation.

`getLawStatistics(locationId)` returns aggregate counts by source,
domain, severity, and type.

## 8. View model contract

`CrimeViewModels` (`js/crime/crime-view-models.js`) is the pure
presentation-shaping layer. No DOM, no queries, no state, no commands.
Every function takes the data it needs as an argument.

### What view models own

  - the shape every renderer consumes
  - label lookups (crime type names, vendetta status labels, severity
    labels)
  - icon NAMES (not rendered icons; the UI resolves via getIcon)
  - modal field defaults

### What view models do not own

  - HTML
  - icon resolution
  - state, query, or command access
  - severity band thresholds (delegated to CrimeConstants.classifySeverity)
  - crime type vocabulary (falls back to snake_case-to-Title for
    unknown types so the identifier is still legible)

### Primitive formatters

`formatCrimeType(type)`, `formatVendettaStatus(status)`,
`formatSeverity(severity)`, `formatSeverityBand(severity)`,
`formatYear(year)`, `formatPersonName(character)`,
`formatSnapshotName(name)`. All pure, all presentational.

### Builders

  `toCrimeListItem(crime, ctx)` — the shape crime list renderers consume
  `toCrimeListItems(crimes, ctx)` — batch
  `toCrimeDetailsViewModel(crime, ctx)` — full details modal shape
  `toVendettaListItem(vendetta)` — the shape vendetta list renderers consume
  `toVendettaListItems(vendettas)` — batch
  `toVendettaDetailsViewModel(vendetta)` — full details modal shape
  `toCrimeStatsViewModel(stats, locationName)` — stats panel shape
  `toMurderModalViewModel(options)` — default field values
  `toExecutionModalViewModel(options)` — default field values
  `toVendettaModalViewModel(options)` — default field values
  `toLawEvaluationViewModel(evaluation)` — display-ready summary of a
                                       legal evaluation

View models never fabricate domain values. Missing values are null,
not defaults. A missing crime returns null from every builder.

## 9. Modal contract

`CrimeModals` (`js/crime/modals-crime.js`) is the modal lifecycle
layer. It calls commands for mutations, queries for reads, and view
models for presentation.

### Public modals

    openMurderModal(options)
    openExecutionModal(options)
    openVendettaModal(options)
    openCrimeDetailsModal(crimeId)       (read-only)
    openVendettaDetailsModal(vendettaId) (read-only)
    openCrimeStatsModal(locationId, year) (read-only)

Each takes `options` and, in the write paths, calls
`options.onComplete(data)` after a successful command + persist.

### Persist boundary

Every write modal calls `_commitAndPersist()` after the command
returns success. That helper:

  1. Calls `CrimeCommands.persist()`
  2. If persist fails, shows a warning toast ("Saved in memory, but
     persisting failed: ...")
  3. Closes the modal and calls `options.onComplete`

The read-only modals (details, stats) do not call `persist()`.

### Presentation helpers

`CrimeModals` re-exports `formatCrimeType`, `formatVendettaStatus`,
`formatSeverity`, `formatPersonName`, and `iconForCrimeType` from
`CrimeViewModels`. These exist for backward compatibility with
callers that use `CrimeModals.formatX`. New code should use
`CrimeViewModels` directly.

`iconForCrimeType(type)` is the only helper that resolves the icon
NAME to an actual icon element. It calls `window.getIcon(name)`.

### Vendetta creation quirk

`openVendettaModal` calls `window.CrimeState.createVendetta` directly
(not through `CrimeCommands.createBloodFeud`). This is intentional:
`createBloodFeud` derives households from characters, but the
vendetta modal collects households directly. If `CrimeCommands`
gains a `createVendettaForHouseholds(householdAId, householdBId,
options)` command, this modal calls that instead. Documented so
future maintainers do not "fix" this by routing it through the wrong
command.

## 10. Stats UI contract

`CrimeStatsUI` (`js/crime/crime-ui-stats.js`) is the DOM renderer for
crime statistics panels, crime lists, vendetta lists, and simple
charts.

### Public renders

    renderStatsPanel(containerId, options)
    renderCrimeList(containerId, crimes, options)
    renderVendettaList(containerId, vendettas, options)
    renderCrimeChart(containerId, data, type)
    refreshAll()
    unmount(containerId)

### The render registry

Every render call registers its container, kind, and options in an
internal `_renderRegistry` map. `refreshAll()` iterates the registry
and re-renders each container with its original options — this
preserves `showActions`, `emptyMessage`, and any other presentation
configuration across refresh.

If a container is unmounted from the DOM, call `unmount(containerId)`
so `refreshAll()` does not attempt to render into a stale element.

### Render errors

Render errors are logged via `console.error` and return `false`.
They are never silently swallowed. The renderer does not catch and
hide errors — it surfaces them so a broken data shape is visible
in the console.

### Location vs household

Crimes have `locationId`. Vendettas do not — they have participating
households. The crime list accepts a location filter; the vendetta
list accepts a household filter. Do not conflate the two.

## 11. Legacy shim

`vendetta-system.js` (`js/crime/vendetta-system.js`) is a
DEPRECATED compatibility shim. Every function forwards to the
canonical implementation and emits a one-time deprecation warning
via `console.warn`.

The shim exists so pre-refactor callers that referenced
`window.VendettaSystem.*` continue to work during migration. Its
returns match the canonical results — structured
`{ success, data }` / `{ success, reason, code }` — NOT the old
bare-object-or-null shape. Any caller that used
`if (result === null)` must migrate to `if (!result.success)`.

The shim must NOT become:
  - a second storage layer
  - a second index set
  - a second VENDETTA_STATUS constant
  - a second createBloodFeud implementation
  - anything that writes to `masterData.data.vendettas` directly

If any of those reappear, the file has regressed.

## 15. Error contract

Silent failure is prohibited.

The patterns

    catch (error) { return []; }
    catch (error) { return null; }
    catch (error) { return false; }

are not used to hide dependency or runtime failures in domain code.

An error is either:
  - rethrown,
  - converted into a structured domain/application error,
  - handled explicitly as a documented best-effort operation.

The single documented best-effort operation is
`CrimeStatsUI` render functions, which log via `console.error` and
return `false` on failure. This is because rendering must not
interrupt other DOM work; the failure is surfaced in the console,
not swallowed.

Everything else — State mutations, Command orchestrations, Law
evaluation, Bootstrap verification — fails loudly and returns a
structured failure result, never `null` or `undefined` on the
failure path.

## 16. Recursion guard policy

Global processing guards are not used in queries, rules,
calculations, commands, or renderers.

The single exception is `CrimeState`'s `_mutatingState` boolean,
which guards against reentrant state mutations during a single
commit. It is scoped to State's mutation primitives only. It is not
consulted by queries, commands, view models, or renderers.

The following do not exist anywhere in the crime system:

    _processing
    _processingCrime
    _processingQuery
    _processingCommand
    _rendering

Composition is legal. A query may call another query. A command may
call another command (e.g. `triggerMurder` calls `createBloodFeud`).
A renderer may call another renderer.

If a genuine cycle exists, the dependency graph must be fixed, not
masked by a boolean flag.

## 18. Completion standard

The crime module is complete when:

  - State owns canonical records and indexes, and nothing else.
  - Commands own transaction boundaries and persistence.
  - Queries are observational and never mutate.
  - Law integration is the only place that decides legality.
  - View models are pure presentation shaping.
  - Modals are the only UI layer.
  - No module contains fabricated fallbacks for missing values.
  - No module silently swallows a required-dependency failure.
  - No module carries a second copy of vocabulary that lives in
    CrimeConstants.
  - No module probes for a method that does not exist on its target
    module.
  - No module uses a deprecated core alias.
  - Documentation matches the architecture actually implemented.

Mechanical requirements for the current version:

  - No crime module calls `window.getCurrentYearSafe`. The canonical
    accessor is `window.getCurrentYear`.
  - No crime module calls `window._escapeHtml`, `window._showToast`,
    or `window._getIcon`. The canonical names are `escapeHtml`,
    `showToast`, `getIcon`.
  - No crime modal call site passes `title:` or `content:` to
    `window.openModal`. The accepted keys are `titleHtml` and
    `contentHtml`.
  - No crime modal call site reads `result.content` from
    `window.openModal`. The modal element is `result.element`.
  - No crime module probes `SettlementQueries.getDominantReligion`
    or `SettlementQueries.getCivilLaws`. Those methods live on
    `SettlementReligionQueries` and `SettlementLawQueries`.
  - No crime module references `window.ModalsCore`. That namespace
    does not exist.
  - Every crime module's `LOCATION:` header names `js/crime/<file>`,
    not `js/core/crime/<file>`.

## 19. Amendment rule

This document describes the current architecture. If implementation
reveals a genuine domain contradiction, the contract is amended
explicitly before the code is changed to accommodate it.

The correct sequence is:

    discover contradiction
        ↓
    resolve domain meaning
        ↓
    amend contract
        ↓
    update affected modules

The incorrect sequence is:

    code gets awkward
        ↓
    add another fallback
        ↓
    add another State helper
        ↓
    add another global flag
        ↓
    pretend nothing happened

The crime system has had enough of those.
