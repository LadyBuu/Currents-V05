# 1. SYSTEM OVERVIEW

## Purpose

The Crime & Law System manages all criminal activities, legal
enforcement, and vendettas within the game world. It provides:

- Crime recording with full historical and legal context.
- Dynamic law enforcement drawn from Religion and Government systems.
- Dual legal systems (civil and religious) with explicit precedence.
- Explicit legal consequences derived from laws, not inferred.
- Vendetta management as a first-class domain concept.
- Statistics and trends over crime and vendettas.
- Rich crime records that preserve historical snapshots and law data.
- Cross-domain integration with household, settlement, character, and
  religion systems through their public command boundaries.

## Architecture

```
                    ┌──────────────────┐
                    │  CrimeConstants  │
                    │ vocabulary       │
                    │ defaults         │
                    └────────┬─────────┘
                             │
                             ▼
                    ┌──────────────────┐
                    │    CrimeState    │
                    │ records, indexes │
                    │ primitive writes │
                    │ persistence      │
                    └────────┬─────────┘
                             │
                ┌────────────┴────────────┐
                ▼                         ▼
       ┌─────────────────┐      ┌─────────────────────┐
       │  CrimeQueries   │      │ CrimeLawIntegration │
       │ derived reads   │      │ applicability       │
       │ statistics      │      │ violations          │
       │                 │      │ consequences        │
       └────────┬────────┘      └─────────┬───────────┘
                │                         │
                └────────────┬───────────┘
                             ▼
                    ┌──────────────────┐
                    │  CrimeCommands   │
                    │  orchestration   │
                    └───────┬──────────┘
                            │
          ┌─────────────────┼──────────────────┐
          ▼                 ▼                  ▼
 HouseholdCommands   SettlementCommands   CharacterCommands
 RelationshipCommands
                            │
                            ▼
                    ┌──────────────────┐
                    │ CrimeModals +    │
                    │ CrimeStatsUI     │
                    └──────────────────┘
```

Dependency direction is strictly downward. Commands may call queries and
state; state never calls commands. UI reads from queries and calls
commands; it never reads state directly.

## Key Design Principles

| Principle | Description |
|-----------|-------------|
| **Single mutation authority** | CrimeState owns all crime and vendetta mutations. Nothing else writes to `masterData.data.crimes` or `.vendettas`. |
| **Consequence separation** | CrimeLawIntegration decides consequences. CrimeCommands executes them. Neither invents the other. |
| **No shared module guards** | Public commands compose freely. Guards exist only where a genuine recursion boundary does. |
| **No fabricated values** | Missing required dependencies fail. There is no `1250`, no fallback crime taxonomy, no hardcoded punishment text. |
| **Persistent rollback** | Every mutation rolls back its in-memory change if persistence fails. State and disk cannot diverge. |
| **Historical snapshots** | Fields named `*Name` are snapshots at recording time. Fields named `*Id` are references. |
| **Presentation vocabulary is UI** | Crime type labels, vendetta status labels, and icons live in the modal layer, not in constants or state. |
| **No private cross-domain access** | Commands reach other domains through their public command boundary. `SettlementState._updateSettlementData` is not a public API. |

# 3. CRIME-CONSTANTS.JS

## Purpose

Pure data plus small, side-effect-free helpers. Does not read state, does
not depend on other domains, does not decide legal consequences.

## Ownership

- Crime type vocabulary (`CRIME_TYPES`).
- Canonical secular / religious categorisation arrays.
- Law classification vocabulary (`LAW_TYPES`, `LAW_CATEGORIES`,
  `LAW_DOMAINS`, `LAW_SEVERITY`).
- Default crime severity (`CRIME_SEVERITY`) — defaults only, overridden
  by laws.
- Vendetta status (`VENDETTA_STATUS`), escalation threshold
  (`VENDETTA_ESCALATION_THRESHOLD`).
- Religious punishment vocabulary (`RELIGIOUS_PUNISHMENTS`) — labels for
  consequences that laws may prescribe, not consequences themselves.
- UI/input vocabulary (`MURDER_REASONS`, `EXECUTION_METHODS`).

## What this module does not do

- It does not map crimes to law domains. That is owned by the law layer.
- It does not define punishments. Those come from laws.
- It does not invent fallbacks for unknown crime types.

## Key constants

### CRIME_TYPES

Secular: MURDER, EXECUTION, CRIME_OF_PASSION, ADULTERY, TREASON, THEFT,
ESPIONAGE, ASSAULT, VENDETTA, VIOLENCE, ROBBERY, FRAUD, FORGERY,
SMUGGLING.

Religious: HERESY, BLASPHEMY, APOSTASY, SACRILEGE, WITCHCRAFT, IDOLATRY,
SCHISM, EXCOMMUNICATION_VIOLATION, RELIGIOUS_IMPERSONATION,
FALSE_PROPHECY, DESECRATION.

### LAW_DOMAINS

MARRIAGE, BEHAVIOR, WORSHIP, FOOD, SOCIAL, ECONOMIC, POLITICAL, SEXUAL,
VIOLENCE, DEATH.

### VENDETTA_STATUS

ACTIVE, ESCALATED, RESOLVED.

### VENDETTA_ESCALATION_THRESHOLD

`3`. The single source of truth for when a vendetta escalates.

## Key functions

| Function | Returns |
|----------|---------|
| `getAllCrimeTypes()` | All crime type identifiers |
| `getSecularCrimeTypes()` | Secular crime type identifiers |
| `getReligiousCrimeTypes()` | Religious crime type identifiers |
| `isReligiousCrime(type)` | boolean |
| `isSecularCrime(type)` | boolean |
| `isKnownCrimeType(type)` | boolean |
| `getDefaultCrimeSeverity(type)` | number, or `undefined` for unknown types |

The categorization arrays (`SECULAR_CRIME_TYPES`,
`RELIGIOUS_CRIME_TYPES`) are the single source. Adding a new crime type
requires adding it to exactly one array and to `CRIME_TYPES`; no helper
needs updating.

`getDefaultCrimeSeverity` returns `undefined` for unknown crime types. It
does not silently substitute `5`.

# 4. CRIME-STATE.JS

## Purpose

Single domain authority for crime and vendetta records. Owns storage,
indexes, lifecycle transitions, and persistence. Does not decide legal
consequences, does not calculate statistics, does not orchestrate.

## Ownership

- Canonical crime and vendetta records (`masterData.data.crimes`,
  `masterData.data.vendettas`).
- Indexes over those records.
- Lifecycle transitions.
- Persistence boundary.
- Subscriber notification.

## Invariants

1. A crime is never recorded as solved. `recordCrime` rejects
   `solved: true`. Solving is a transition performed by `solveCrime`.
2. `bodyCount` is not persisted. Use `deaths.length`.
3. Records are added to the cache at most once. Re-adding the same id is
   a no-op.
4. Persistence failures are returned, never swallowed. A mutation that
   cannot be persisted is reported as failed and its in-memory change is
   rolled back.
5. Historical snapshot fields (`perpetratorName`, `victimName`,
   `householdAName`, `householdBName`, `characterAName`, `characterBName`)
   are never refreshed from live sources.

## Initialization

Initialization is transactional. The module builds a fresh set of indexes
into a local object and swaps them into place only after the entire
persisted dataset has loaded successfully. A malformed record cannot
leave the module half-initialized.

## Key functions

### Crime queries

| Function | Returns |
|----------|---------|
| `getCrime(crimeId)` | Crime record or null |
| `getAllCrimes()` | Array of crime records |
| `getCrimesByPerpetrator(characterId)` | Crimes where the character is the perpetrator |
| `getCrimesByVictim(characterId)` | Crimes where the character is the victim |
| `getCrimesInvolvingCharacter(characterId)` | Crimes where the character is either |
| `getCrimesByCharacter(characterId)` | Legacy alias for `getCrimesByPerpetrator` |
| `getCrimesByType(type)` | Crimes of the given type |
| `getCrimesByLocation(locationId)` | Crimes recorded at the given location |
| `getUnsolvedCrimes()` | Crimes with `solved: false` |
| `getCrimeCount()` | Total crime count |

### Crime commands

| Function | Returns |
|----------|---------|
| `recordCrime(data)` | `{ success, data, error }` |
| `solveCrime(crimeId, solution, solvedAtYear)` | `{ success, data, error }` |
| `deleteCrime(crimeId)` | `{ success, error }` |

### Vendetta queries

Resolved vendettas are **included by default**. Pass
`{ includeResolved: false }` to exclude.

| Function | Returns |
|----------|---------|
| `getVendetta(vendettaId)` | Vendetta or null |

| `getActiveVendettas(householdId)` | Unresolved vendettas involving the household |
| `getActiveVendettaBetween(a, b)` | Unresolved vendetta between two households, or null |

### Vendetta commands

### Subscription and cache management

# 5. CRIME-LAW-INTEGRATION.JS

## Purpose

The boundary between the Crime domain and the two law systems. Given a
character, an action, and a context, answers:

1. Which laws govern this action for this character?
2. What are the legal consequences?

It does not execute consequences. It does not record crimes.

## Concepts

| Term | Meaning |
|------|---------|
| **Applicable** | The law applies to this character at this location, regardless of enforcement status. |
| **Enforced** | The law is currently enforced as law. Applicable does not imply enforced. |
| **Violation** | The action breaches this law. |
| **Governing law** | The highest-severity enforced violation, if any. |
| **Consequence** | What the governing law prescribes. Derived from the law, never invented. |

## Precedence (theocracy)

- **Theocracy or `useReligiousLawsAsCivil`**: the settlement's dominant
  religion's law governs everyone. Religious violations are promoted to
  civil status inside `evaluateAction`. There is no separate
  "apply supremacy afterwards" step for callers to forget.
- **Secular settlement**: civil laws apply to all residents; religious
  laws apply only to followers.
- **Established church**: both systems run in parallel.

## Key functions

### Applicability

| Function | Returns |
|----------|---------|
| `getApplicableLaws(characterId, domain)` | All laws that apply, with `isEnforced` per item |
| `getEnforcedLaws(characterId, domain)` | Subset where `isEnforced` is true |
| `getReligiousLaws(characterId, domain)` | Subset from religious sources |
| `getCivilLawsForCharacter(characterId, domain)` | Subset from civil sources |

Each returned item has the shape:

```js
{
    law,
    source: 'civil' | 'religious',
    sourceId,
    sourceName,
    applicability: 'universal' | 'follower' | 'official_religion',
    isEnforced: boolean
}
```

### Evaluation

```js
CrimeLawIntegration.evaluateAction(characterId, action, context)
```

Returns:

```js
{
    lawful: boolean,
    violations: [violationItem],
    civil: [violationItem],
    religious: [violationItem],
    governingLaw: violationItem | null,
    consequences: [consequence]
}
```

Where `consequence` is:

```js
{
    type: 'execution' | 'imprisonment' | 'exile' | 'fine'
        | 'penance' | 'excommunication' | 'other',
    description: string | null,
    method: string | null,
    authority: string | null,
    source: { lawId, lawName, source, sourceId, sourceName }
}
```

A law only produces a consequence if it is enforced and declares one. If
it is enforced but declares no consequence, the consequence list contains
an `{ type: 'other', description: null }` entry so the caller knows the
law was breached and no specific penalty was defined.

### Search and statistics

| Function | Returns |
|----------|---------|
| `searchLaws(query, locationId, religionId)` | Matching laws with source info |
| `getLawStatistics(locationId)` | Counts by source, domain, severity, type |

## What laws must expose

A law is violated by an action only if it opts in explicitly:

- `law.crimeMapping.crimeType` — single identifier, exact match against
  `action.type`.
- `law.crimeMapping.crimeTypes` — array of identifiers, exact match.
- `law.violationCheck(action, context)` — custom predicate.

Domain match alone does not constitute a violation. This preserves the
distinction between "this law is about violence" and "this law criminalises
this specific action."

## Modifiers

A law may declare `law.modifiers = { key: requiredValue }`. Modifiers are
matched against `action.details[key]` first, then `context[key]`.
`undefined` falls through to the secondary source; `false`, `0`, and `""`
are treated as legitimate values.

# 6. CRIME-QUERIES.JS

## Purpose

Application-facing read API. Composes `CrimeState` primitives into
derived views: statistics, trends, distributions, clearance metrics.
Observational only.

## Time window semantics

All statistics functions that accept a `year` parameter treat it as an
**analysis reference year**, not a filter on the underlying dataset.
`totalCrimes` always means "all recorded crimes for this location (or
globally)". Functions that use a window state it explicitly and return a
`period` object:

```js
period: {
    referenceYear: number,
    windowYears: number,
    startYear: number,
    endYear: number
}
```

## Crime burden semantics

The metric formerly called `crimeRatePerCapita` was historical recorded
crimes divided by current population. That is not a rate; it has no time
denominator. The metric is exposed as:

- `crimeBurden`: historical recorded crimes per current resident.
- `recentCrimeBurden`: recorded crimes in the recent window per current
  resident.
- `getNormalizedCrimeBurden(locationId)`: the same value clamped to
  `[0, 1]` for UI code that needs a bounded scalar.

None of these is a per-year rate.

## Severity bands

Severity is numeric (1–10). Bands:

| Band | Range |
|------|-------|
| low | 1–3 |
| medium | 4–6 |
| high | 7–8 |
| critical | 9–10 |

The thresholds live in a single private helper. `SEVERITY_BANDS` is
exported for read-only use.

## Key functions

### Crime queries

Same surface as `CrimeState`, plus presentation-neutral wrappers.

### Vendetta queries

Same surface as `CrimeState`.

### Statistics

| Function | Returns |
|----------|---------|
| `getLocationCrimeStats(locationId, year, windowYears)` | Full location stats with `period` |
| `getCrimeTrends(locationId, years, endYear)` | Array of yearly buckets |
| `getCrimeTypeDistribution(locationId)` | Map of type → count |
| `getOverallCrimeStats(year, windowYears)` | Global stats with `period` |
| `getCrimeSeverityStats()` | Distribution, average, median, bands |
| `getCrimeClearanceRate()` | Overall and per-type clearance |
| `getVendettaStats(householdId)` | Vendetta statistics |

`getVendettaStats(householdId)` filters to vendettas **involving** the
household. The `byHousehold` map contains both sides of every vendetta
returned — the queried household and its opponents. This is deliberate: it
exposes the network around a household.

## Clearance semantics

"Clearance" here means the crime has been marked solved in the record.
That is the only sense in which the term is used in this simulation.

# 7. CRIME-COMMANDS.JS

## Purpose

Orchestration layer. Each command validates inputs, resolves context,
asks `CrimeLawIntegration` for a legal evaluation, records the crime
through `CrimeState`, kills characters through `killCharacter`, applies
the consequences returned by the law layer, updates households and
settlements through their public command boundaries, logs the event, and
returns a structured result.

## What this module does not do

- Does not decide consequences.
- Does not own crime or vendetta records.
- Does not compute statistics.
- Does not reach into another domain's private state.
- Does not use a module-wide recursion guard.
- Does not normalise options with `||` on values that could legitimately
  be falsy.

## Household side effects

Perpetrator-side and victim-side effects are distinct:

- **Perpetrator household**: criminal count and membership, prestige loss,
  crime history entry with `role: 'perpetrator'`.
- **Victim household**: victim count and membership, prestige loss
  (usually lower than perpetrator side), crime history entry with
  `role: 'victim'`.
- **Condemned household (execution)**: executed count, crime history
  entry with `role: 'condemned_household'`.

The victim's household is never told its murdered member was a criminal.

## Settlement side effects

Settlement effects go through `SettlementCommands.recordCrimeImpact` if it
exists. If it does not, the effect is skipped. Commands never call
`SettlementState._updateSettlementData` or any other private-looking
method on another domain.

## Consequence execution

For each consequence returned by the law layer:

| Consequence type | Behaviour |
|------------------|-----------|
| `execution` | Calls `triggerExecution` with the consequence's method and description. |
| `imprisonment`, `exile`, `fine`, `penance`, `excommunication` | Surfaced in the result but not applied. These await their domain APIs. |
| `other`, unrecognised | Surfaced in the result but not applied. |

Unknown consequences are never guessed at.

## Rollback on partial failure

If `recordCrime` succeeds but `killCharacter` fails, the crime record is
deleted so state and reality agree. This pattern is applied consistently
across `triggerMurder` and `triggerExecution`.

## Key functions

| Function | Returns |
|----------|---------|
| `triggerMurder(victimId, killerId, options)` | `{ success, data, error }` |
| `triggerExecution(condemnedId, options)` | `{ success, data, error }` |
| `createBloodFeud(victimId, killerId, options)` | `{ success, data, error }` |

### `triggerMurder` data shape

```js
{
    victim,
    killer,
    crime,
    year,
    locationId,
    killerGotAway: boolean,
    legalEvaluation: {
        lawful,
        violations,
        civil,
        religious,
        governingLaw,
        consequences
    },
    consequenceResults: [ { type, applied, ... } ],
    execution: executionResult | null,
    vendetta: vendettaRecord | null,
    householdUpdates: {
        victimHouseholdId,
        killerHouseholdId
    }
}
```

## Helpers

| Function | Returns |
|----------|---------|
| `getRandomMurderReason(category)` | A reason from `MURDER_REASONS`, or `'Unspecified'` |
| `getRandomExecutionMethod()` | A method from `EXECUTION_METHODS`, or `{ id: 'unknown', name: 'Unknown' }` |

# 8. VENDETTA-SYSTEM.JS (LEGACY SHIM)

## Status

**Deprecated compatibility shim.**

This file used to be a second, competing vendetta implementation with its
own storage, its own cache, its own `VENDETTA_STATUS`, and a
`createBloodFeud` that deadlocked itself via a module-wide guard. It has
been reduced to a thin delegation layer over `CrimeState` and
`CrimeCommands`.

Every function forwards to the canonical implementation. Return shapes are
unwrapped so existing callers do not break during migration. New code must
not use this file.

## Canonical replacements

| Legacy | Canonical |
|--------|-----------|
| `VendettaSystem.VENDETTA_STATUS` | `CrimeConstants.VENDETTA_STATUS` |
| `VendettaSystem.createVendetta(data)` | `CrimeState.createVendetta(data)` |
| `VendettaSystem.getVendettaById(id)` | `CrimeState.getVendetta(id)` |
| `VendettaSystem.getAllVendettas(options)` | `CrimeState.getAllVendettas(options)` |
| `VendettaSystem.getVendettasByHousehold(id, options)` | `CrimeState.getVendettasByHousehold(id, options)` |
| `VendettaSystem.getVendettasByCharacter(id, options)` | `CrimeState.getVendettasByCharacter(id, options)` |
| `VendettaSystem.getActiveVendettas(id)` | `CrimeState.getActiveVendettas(id)` |
| `VendettaSystem.recordVendettaDeath(id, data)` | `CrimeState.recordVendettaDeath(id, data)` |
| `VendettaSystem.resolveVendetta(id, data)` | `CrimeState.resolveVendetta(id, data)` |
| `VendettaSystem.createBloodFeud(v, k, o)` | `CrimeCommands.createBloodFeud(v, k, o)` |
| `VendettaSystem.getVendettaStats(id)` | `CrimeQueries.getVendettaStats(id)` |
| `VendettaSystem.clearVendettaCache()` | `CrimeState.reload()` |

## Deprecation behaviour

Every function calls a once-per-function `console.warn` naming the
canonical replacement on first use. Return shapes are the same bare-object
or-null shapes legacy callers expect.

## What this file must not become

A second storage layer, a second index set, a second `VENDETTA_STATUS`, a
second `createBloodFeud`, or anything that writes to
`masterData.data.vendettas` directly. If any of those reappear, the file
has regressed.

# 9. MODALS-CRIME.JS

## Purpose

Modal dialogs for crime and vendetta operations. Collects input and hands
it to `CrimeCommands`; renders data supplied by `CrimeQueries`. Does not
decide domain rules, does not mutate records directly, does not carry its
own vocabulary.

## Key functions

| Function | Purpose |
|----------|---------|
| `openMurderModal(options)` | Record a murder |
| `openExecutionModal(options)` | Record an execution |
| `openVendettaModal(options)` | Create a vendetta |
| `openCrimeDetailsModal(crimeId)` | View crime details |
| `openVendettaDetailsModal(vendettaId)` | View vendetta details |
| `openCrimeStatsModal(locationId, year)` | View crime statistics |

## Presentation formatters (shared)

These are exported from `CrimeModals` and consumed by `CrimeStatsUI`. They
are the only place in the crime UI where canonical identifiers are
translated into display strings.

| Function | Returns |
|----------|---------|
| `formatCrimeType(type)` | Human-readable crime type label |
| `formatVendettaStatus(status)` | Human-readable status label |
| `formatSeverity(severity)` | `'8/10'` or `'Unknown'` |
| `formatPersonName(character)` | `'First Surname'` or `'Unknown'` |
| `iconForCrimeType(type)` | Icon for the crime type |

## What this module does not do

- Does not carry a fallback crime taxonomy.
- Does not hardcode vendetta status identifiers.
- Does not fabricate years, causes, or punishment text.
- Does not use a module-wide `_processingModal` guard.

## Notes on the execution modal

The execution method field is a `<select>` populated from
`CrimeConstants.EXECUTION_METHODS`. Legal eligibility and permitted methods
are determined by the law layer; the modal only offers what the vocabulary
declares.

## Notes on the vendetta modal

A blank cause input is passed through as `null`. The modal does not
manufacture `'Unknown cause'`.

## Notes on the details modals

Law-derived fields (`civilViolation`, `religiousViolation`) are surfaced.
Vendetta death names are HTML-escaped.

## Purpose

## Key functions

| `renderCrimeList(containerId, crimes, options)` | Crime list |
| `renderVendettaList(containerId, vendettas, options)` | Vendetta list |
| `renderCrimeChart(containerId, data, type)` | Chart (type or yearly) |
| `refreshAll()` | Re-render all registered components with their original options |
| `unmount(containerId)` | Remove a container from the render registry |

## Render registry

Every render call registers its container, kind, data source, and options
in an internal registry. `refreshAll()` iterates the registry and
re-renders each container with its original options. This preserves
`showActions`, `emptyMessage`, location filters, and any other
presentation configuration across refresh. It also removes the dependency
on DOM discovery and `.parentElement` guessing.

## Location and household

Vendettas do not have a location. The vendetta list does not accept a
location filter. If a caller needs to filter vendettas, they filter by
household — which is what actually identifies a vendetta's participants.

## Presentation

- Crime type labels come from `CrimeModals.formatCrimeType`.
- Vendetta status labels come from `CrimeModals.formatVendettaStatus`.
- Icons come from `CrimeModals.iconForCrimeType` or `_getIcon` directly.
- No status string maps are duplicated here.

## Error handling

Every render function catches its own exceptions, logs them with
`console.error`, and returns `false`. Silent failure is not permitted.

# 12. LAW INTEGRATION FLOW

When a crime command runs:

```
1. Command normalises options and resolves context.

2. Command calls CrimeLawIntegration.evaluateAction().

3. evaluateAction:
   a. Resolves legal context (location, settlement, government type,
      dominant religion).
   b. Aggregates applicable laws (civil + religious, with theocracy
      precedence applied internally).
   c. Checks each law against the action using explicit opt-in
      (crimeMapping or violationCheck).
   d. Applies precedence: in a theocracy, religious violations govern.
   e. Selects the governing law (highest severity enforced violation).
   f. Derives consequences from governing laws only.

4. Command records the crime through CrimeState.recordCrime(). The record
   carries civilViolation, religiousViolation, religionId, and violatedLaws.

5. Command kills the victim through killCharacter.

6. Command iterates evaluation.consequences and executes each via
   _executeConsequence. Execution is applied; other types are surfaced.

7. Command updates households (perpetrator-side, victim-side,
   condemned-side as applicable) via HouseholdCommands if available.

8. Command records settlement impact through
   SettlementCommands.recordCrimeImpact if available.

9. Command logs the event.

10. Command returns a structured result containing the crime, the legal
    evaluation, the consequence results, and any vendetta.
```

## What the law layer decides

- Whether the action is lawful.
- Which laws are violated.
- Which law governs (highest severity enforced violation).
- What consequences the governing laws prescribe.

## What the command layer decides

- Which workflows to run in what order.
- How to handle partial failure (rollback).
- Which domain boundaries to notify.

## What the command layer does not decide

- That illegality implies a specific punishment.
- That an enforced violation implies execution.
- That a law which is applicable is therefore enforced.

# 13. CROSS-SYSTEM INTEGRATION

## Crime ↔ Religion

| Direction | Mechanism |
|-----------|-----------|
| Crime → religious laws | `CrimeLawIntegration.getApplicableLaws` |
| Crime → religious violations | `CrimeState.recordCrime` preserves `religiousViolation` and `religionId` |
| Character → religion | `character.religionId` used for follower-mode applicability |
| Theocracy | `SettlementState` government type + dominant religion |

## Crime ↔ Government

| Direction | Mechanism |
|-----------|-----------|
| Crime → civil laws | `CrimeLawIntegration.getApplicableLaws` |
| Crime → civil violations | `CrimeState.recordCrime` preserves `civilViolation` |
| Settlement → crime impact | `SettlementCommands.recordCrimeImpact` if available |

## Crime ↔ Household

| Direction | Mechanism |
|-----------|-----------|
| Crime → perpetrator household | `HouseholdCommands.applyPerpetratorCrime` if available; otherwise `HouseholdState.updateHousehold` |
| Crime → victim household | `HouseholdCommands.applyVictimCrime` if available; otherwise `HouseholdState.updateHousehold` |
| Crime → condemned household | `HouseholdCommands.applyExecutionToHousehold` if available; otherwise `HouseholdState.updateHousehold` |

## Crime ↔ Death

| Direction | Mechanism |
|-----------|-----------|
| Murder → death | `killCharacter` |
| Execution → death | `killCharacter` |
| Death → crime record | `CrimeState.recordCrime` |

## Crime ↔ Relationship

| Direction | Mechanism |
|-----------|-----------|
| Execution → relationship termination | `getRelationshipsForCharacter` + `endRelationship` |

# 15. RECURSION GUARD POLICY

Guards exist only where a genuine recursion boundary does.

| Module | Guard | Purpose |
|--------|-------|---------|
| `crime-state.js` | `_mutatingState` | Prevents primitive state mutation from re-entering itself. Not shared with orchestration; commands compose by calling multiple public state functions in sequence. |
| `crime-commands.js` | none | Commands compose freely. There is no module-wide guard. |
| `crime-law-integration.js` | none | Public functions compose freely. There is no module-wide guard. |
| `crime-queries.js` | none | Queries are pure reads and cannot recurse into themselves. |
| `crime-ui-stats.js` | none | Rendering is synchronous; there is no re-entrancy to protect against. |
| `modals-crime.js` | none | Modal construction is synchronous; composing modals (character selector, household selector) is normal. |
| `vendetta-system.js` | none | The legacy shim delegates to `CrimeState`; there is no state to protect. |

If a genuine cycle appears, the dependency graph must be fixed, not masked
by a boolean flag.

# 18. MIGRATION NOTES FROM V4

## Removed

- Module-wide `_processingCommand` guards in `crime-commands.js` (deadlocked nested calls).
- `_processingIntegration` in `crime-law-integration.js` (deadlocked law evaluation).
- `_processingVendetta` in `vendetta-system.js` (deadlocked blood feud creation).
- `_processingRender` in `crime-ui-stats.js` (protected nothing).
- `_processingModal` in `modals-crime.js` (protected nothing).
- Hardcoded punishment defaults in `crime-commands.js`.
- `getCrimeDomain` in `crime-constants.js` (recreated the deleted `CRIME_TO_DOMAIN` map).
- Fallback crime taxonomies in `crime-queries.js` and `modals-crime.js`.
- `|| 5` severity fallback in `getDefaultCrimeSeverity`.
- `1250` year fallbacks throughout.
- `bodyCount` as a persisted field.
- Second vendetta storage and cache in `vendetta-system.js`.
- Private access to `SettlementState._updateSettlementData` and `._addHistoryEntry` from commands.
- `getCharacterCombatStrength` from `crime-commands.js` (belongs in character/combat).

## Renamed

- `getCrimesByCharacter` → `getCrimesByPerpetrator`, with `getCrimesByVictim` and `getCrimesInvolvingCharacter` alongside. Legacy alias retained.
- `crimeRatePerCapita` → `crimeBurden`, with `getNormalizedCrimeBurden` for the bounded scalar.
- `invalidateCache` → `reload`. Legacy alias retained.
- `checkLawViolations` → `evaluateAction` (with a much richer return shape).

## Restructured

- `CrimeState.recordCrime` now preserves `civilViolation`, `religiousViolation`, `religionId`, and `violatedLaws`.
- `CrimeState._addCrimeToCache` / `_addVendettaToCache` are idempotent.
- `CrimeState._initialize` is transactional.
- `CrimeState` persistence failures propagate and roll back in-memory changes.
- `includeResolved` semantics are standardised across all vendetta queries: default is include.
- Household side effects are split into perpetrator-side, victim-side, and condemned-side.
- Settlement side effects go through a public command boundary.
- Law evaluation produces consequences, not just violations.
- Consequence execution in commands is explicit and enumerates known types.

## Preserved

- The command/query/state/law/UI layer separation.
- The crime and vendetta record shapes (with `bodyCount` removed).
- Historical snapshot fields (`*Name`) alongside references (`*Id`).
- The `includeResolved` option.
- The `subscribe` interface.
- The `triggerMurder` / `triggerExecution` / `createBloodFeud` entry points.
- The modal and list rendering APIs.

# 19. USAGE EXAMPLES

## Example 1: Record a murder with full law evaluation

```js
var result = window.CrimeCommands.triggerMurder(victim.id, killer.id, {
    year: 1250,
    reason: 'Jealousy',
    killerGotAway: false,
    startVendetta: true,
    locationId: 'loc_blackwood'
});

if (result.success) {
    var d = result.data;
    console.log('Crime:', d.crime.id);
    console.log('Lawful:', d.legalEvaluation.lawful);
    console.log('Consequences:', d.legalEvaluation.consequences);
    console.log('Execution result:', d.execution);
    console.log('Vendetta:', d.vendetta);
}
```

## Example 2: Check what the law would do

```js
var evaluation = window.CrimeLawIntegration.evaluateAction(
    killer.id,
    {
        type: 'murder',
        domain: 'violence',
        details: { victimId: victim.id, premeditated: true }
    },
    { locationId: 'loc_blackwood', victim: victim, killer: killer }
);

if (!evaluation.lawful) {
    console.log('Governing law:', evaluation.governingLaw.law.name);
    for (var i = 0; i < evaluation.consequences.length; i++) {
        console.log('Consequence:', evaluation.consequences[i].type);
    }
}
```

# 20. AMENDMENT RULE

This document describes the current architecture. If implementation reveals
a genuine domain contradiction, the contract is amended explicitly before
the code is changed to accommodate it.

The correct sequence is:

```
discover contradiction
    ↓
resolve domain meaning
    ↓
amend contract
    ↓
update affected modules
```

The incorrect sequence is:

```
code gets awkward
    ↓
add another fallback
    ↓
add another State helper
    ↓
add another global flag
    ↓
pretend nothing happened
```

The crime system has had enough of those.
