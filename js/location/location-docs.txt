# Location Domain — Documentation

**Version 2.0 — post-refactor**

**Covers:** state, commands, queries, hierarchy, movement, view-models, UI state, UI list, presentation, modals, bootstrap.

**Status:** refactored to match rank / role / relationship / education.

**Replaces:** `location-docs.txt` (v3.0, pre-refactor — delete after this file is in place).

---

## 1. Ownership contract

The location domain owns the geographical hierarchy of the world. It does not own characters, households, governments, or any other domain that references locations.

| Concept | Owner | Readers |
|---|---|---|
| Place records | `LocationState` | `LocationQueries` (projections) |
| Location type records | `LocationState` | `LocationQueries` (projections) |
| Indexes over places / types | `LocationState` | all location modules |
| Change events | `LocationState` | subscribers via `LocationState.subscribe` |
| Hierarchy semantics | `LocationHierarchy` | `LocationQueries`, `LocationMovement`, `LocationCommands` |
| Movement rules | `LocationMovement` | UI, cross-domain callers |
| Movement records | `CharacterQueries` (character-owned) | `LocationQueries` (projections) |
| View-shaped records | `LocationViewModels` | `LocationUI` |
| Transient UI state | `LocationUIState` | `LocationUI` |
| DOM rendering | `LocationUI` | callers |
| Cross-domain notifications | `LocationCommands` | `window` via `CustomEvent` |
| Persistence flush | `LocationCommands.persist` | callers |

**One owner per concept.** Place and location type records live only in `masterData.data`. Location indexes are rebuildable. Nothing else.

**Cross-domain writes go through owning domain commands.**

| Write | Routes through |
|---|---|
| Character current location cleared on place delete | `CharacterCommands.updateCharacterFields` |
| Character move appended | `CharacterCommands.updateCharacterFields` |
| Culture validation on assign | `CultureQueries.getCulture` (read-only) |

**No direct writes into another domain's canonical arrays.** No `masterData.data.characters` reach-in from the location domain.

```html
<!-- Location domain -->
<script src="js/location/location-state.js"></script>
<script src="js/location/location-hierarchy.js"></script>

<script src="js/location/location-queries.js"></script>

<script src="js/location/modals-moves.js"></script>
<script src="js/location/location-bootstrap.js"></script>
```

**Two important ordering constraints:**

1. **`location-hierarchy.js` loads before `location-commands.js`.** Commands calls `LocationHierarchy.validateHierarchy` at load time (dependency check) and at call time (parent change validation). Hierarchy depends on `LocationState` and `LocationQueries` — but `LocationQueries` loads after commands. This is fine because hierarchy only requires `LocationQueries` at load time for its own dependency check, and commands does not require `LocationQueries` at all.

2. **`location-bootstrap.js` loads last among location scripts.** It requires every other location module to be loaded. It also requires `character-commands.js`, `character-queries.js`, `storage.js`, `ids.js`, and `time.js`.

**Existing HTML files that load the location domain:**

- `DataManager.html`
- `GENERIC.html`
- `GENERIC_sidebar.html`
- `GovernmentManager.html`
- `HouseholdManager.html`
- `ReligionManager.html`
- `RoleManager.html`
- `SettlementManager.html`

Each needs `location-bootstrap.js` added after the last location script, and the load-order adjustment above if `location-hierarchy.js` currently loads after `location-commands.js`. Verify per file.

## 3. `location-state.js`

Single source of truth for location indexes. Rebuildable from `masterData.data.places` and `masterData.data.locationTypes`.

**Owns:**
- `_placeById`, `_placesByParent`, `_placesByType`, `_typeById` indexes.
- Public reads (clones).
- Internal canonical accessors (live references).
- Mutation primitives.
- Subscription list and publish queue.
- Hydration.

**Does NOT own:**
- Canonical records. Those live in `masterData.data`.
- Persistence. Commands call `markDataDirty`; the storage layer flushes.
- Mutations. Commands mutate through primitives.
- Cross-domain reads. Queries composes those.

### Acceptance test

Delete every index. Call `hydrateFromMasterData()`. The application behaves identically.

### Public reads (return clones)

| Function | Returns |
|---|---|
| `getPlaceById(placeId)` | `Object|null` — clone |
| `getLocationTypeById(typeId)` | `Object|null` — clone |
| `getPlacesByParentId(parentId)` | `Object[]` — clones |
| `getPlacesByTypeId(typeId)` | `Object[]` — clones |
| `getAllPlaceIds()` | `string[]` |
| `getAllLocationTypeIds()` | `string[]` |

### Internal live-reference accessors

Reserved for `LocationCommands` and `LocationHierarchy` during a transaction. Do not mutate.

| Function | Returns |
|---|---|
| `_getPlaceCanonical(placeId)` | `Object|null` — live |
| `_getLocationTypeCanonical(typeId)` | `Object|null` — live |
| `_getPlacesByParentIdCanonical(parentId)` | `Object[]` — live |
| `_getPlacesByTypeIdCanonical(typeId)` | `Object[]` — live |

### Mutation primitives

Reserved for `LocationCommands`. Each calls `window.markDataDirty()` on success. Do not hydrate, persist, or publish.

| Function | Behavior |
|---|---|
| `_addPlace(place)` | Throws on duplicate id. Pushes to canonical array. |
| `_removePlace(placeId)` | Removes from canonical array. Returns boolean. |
| `_addLocationType(type)` | Throws on duplicate id. Pushes to canonical array. |
| `_removeLocationType(typeId)` | Removes from canonical array. Returns boolean. |

### Lifecycle

| Function | Behavior |
|---|---|
| `hydrateFromMasterData()` | Clears indexes, rebuilds from canonical. Throws on duplicate or missing ids. |

### Subscriptions

| Function | Returns |
|---|---|
| `subscribe(callback)` | `Function` — unsubscribe |
| `publish(eventType, data)` | void — non-reentrant queue |

Subscriber callbacks receive `{ type, data }`. Errors are logged but do not abort delivery.

### Hard dependencies

- `window.markDataDirty` — verified at load.

## 4. `location-commands.js`

The write boundary. Every place, location type, movement, government, leader, and culture mutation goes through this module.

**Result shape:** `{ success: boolean, reason?: string, ... }`.

**Single transaction tail.** Every command:

1. Validates.
2. Mutates canonical data via `LocationState` primitives.
3. Calls `_commit(eventType, data)`.
4. `_commit` calls `LocationState.hydrateFromMasterData()`, then `LocationState.publish(eventType, data)`, then `window.dispatchEvent(new CustomEvent(eventType, { detail }))`.

**Persistence boundary.** Commands do NOT call `saveMasterData` except inside `persist()`. Callers call `persist()` exactly once per batch.

### Place commands

| Function | Returns | Notes |
|---|---|---|
| `createPlace(input)` | `{ success, placeId, place }` | Validates type, parent, culture. |
| `updatePlace(placeId, updates)` | `{ success, placeId }` | Field allowlist. Domain-owned fields refused with a message. |
| `deletePlace(placeId, options)` | `{ success, ..., charactersReconciled, charactersFailed, householdReconciliation }` | `options.mode` is required: `'simple'` or `'cascade'`. |

**`deletePlace` cleanup:**
- Characters whose `currentLocationId` points at a deleted place have it cleared via `CharacterCommands.updateCharacterFields`.
- Households are not yet location-aware. `householdReconciliation` is `'deferred'` in the result envelope. See Known Deferrals.

### Location type commands

| Function | Returns | Notes |
|---|---|---|
| `createLocationType(input)` | `{ success, typeId, type }` | Priority 1..5 required. |
| `updateLocationType(typeId, updates)` | `{ success, typeId }` | Field allowlist. |
| `deleteLocationType(typeId)` | `{ success, typeId }` | Refuses if any place still uses the type. |

### Movement commands

| Function | Returns | Notes |
|---|---|---|
| `recordMove(characterId, locationId, options)` | `{ success, characterId, locationId, year }` | Appends to `character.moves`. |
| `bulkRecordMoves(moves)` | `{ success, success[], failed[], total, succeeded, failedCount }` | Single commit for the batch. |

**Movement writes route through `CharacterCommands.updateCharacterFields`** with the full `moves` array. `moves` is not in `_DOMAIN_OWNED_FIELDS`, so the gate allows it.

### Government / leader / culture

| Function | Returns | Notes |
|---|---|---|
| `assignGovernment(placeId, governmentTypeId, governmentStyle)` | `{ success, placeId }` | |
| `assignLeader(placeId, characterId, startYear, title)` | `{ success, placeId, assignment }` | Closes any open assignment. Refuses deceased. |
| `endLeaderTerm(placeId, characterId, endYear)` | `{ success, placeId, characterId, endYear }` | |
| `updatePlaceCulture(placeId, cultureId)` | `{ success, placeId, cultureId }` | Validates via `CultureQueries`. |

### Persistence

| Function | Returns | Notes |
|---|---|---|
| `persist()` | `{ success }` or `{ success: false, reason }` | The only call site of `saveMasterData`. |

### Cross-domain events

`window.dispatchEvent(new CustomEvent(eventName, { detail }))` fires for every committed mutation. Names:

- `placeCreated`, `placeUpdated`, `placeDeleted`
- `locationTypeCreated`, `locationTypeUpdated`, `locationTypeDeleted`
- `moveRecorded`, `movesRecordedBulk`
- `governmentAssigned`
- `leaderAssigned`, `leaderTermEnded`
- `cultureAssigned`

These are in addition to `LocationState.publish`. Subscribers to `LocationState` receive `{ type, data }`. Subscribers to `window` receive `CustomEvent` with `.detail`.

### Hard dependencies

- `LocationState`, `LocationHierarchy`, `CharacterCommands`, `CharacterQueries`
- `window.getCurrentYearSafe`, `window.generateId`, `window.markDataDirty`, `window.saveMasterData`
- `CharacterCommands.updateCharacterFields`
- `CharacterQueries.getAllCharacters`, `.getCharacterById`, `.getCurrentLocationId`
- Lazy: `window.CultureQueries.getCulture` (only when a culture is assigned)

## 7. `location-movement.js`

Movement rules, accessibility, travel time, move statistics.

**Does not mutate. Does not own move records.**

### Age resolution

Delegates to `window.calculateAge(birthYear, isDeceased, deathYear, year)`.

**Note:** `CharacterQueries.getAgeAt` does not exist. It was a phantom method in an earlier version that silently returned `undefined` and disabled the minimum-age guard.

### Validation

| Function | Returns | Notes |
|---|---|---|
| `canMoveTo(characterId, locationId, year)` | `{ valid, reason }` | Age, birth, deceased, later-move guards. |
| `validateMoveSequence(characterId, moves)` | `{ valid, errors[] }` | Sorts by year; detects missing year, before-birth, duplicate, unknown location. |

### Accessibility

`isLocationAccessible(characterId, locationId)`, `getTravelRestrictions(characterId)`.

`getTravelRestrictions` returns `{ hard: [], warnings: [] }`. Noble-status warning is a soft advisory; it checks `window.RankQueries` presence and skips the warning if missing.

### Travel time

`getTravelTime(fromLocationId, toLocationId)` — deterministic. Same-country: `1 + distance * 2`. Cross-country: `7 + distance * 3`. Returns `null` if disconnected.

### Constants

`MIN_TRAVEL_AGE` — exported. Default `7`.

### Statistics

`getYearsBetweenMoves`, `getAverageMoveFrequency`, `getMostFrequentDestination`.

### Hard dependencies

- `LocationState`, `LocationQueries.getPlace` / `.areInSameCountry`, `LocationHierarchy.getHierarchyDistance`
- `CharacterQueries.getCharacterById`, `.getMoveHistory`
- `window.getCurrentYearSafe`, `window.calculateAge`

## 14. `location-bootstrap.js`

Load-time verification, hydration, namespace.

### init()

Idempotent. Safe to re-invoke after a `masterDataUpdated` reload.

Verifies:
- Globals: `generateId`, `markDataDirty`, `saveMasterData`, `getCurrentYearSafe`, `calculateAge`.
- Modules: `LocationState`, `LocationCommands`, `LocationQueries`, `LocationHierarchy`, `LocationMovement`.
- Cross-domain methods: `CharacterCommands.updateCharacterFields`; `CharacterQueries.getAllCharacters`, `.getCharacterById`, `.getCurrentLocationId`, `.getMoveHistory`.
- Canonical shape: `masterData.data.places` and `.locationTypes` are arrays.
- Surface: every public method on each location module.

Then hydrates `LocationState` and installs `window.Location`.

### Namespace

```js
window.Location = {
    state: LocationState,
    commands: LocationCommands,
    queries: LocationQueries,
    hierarchy: LocationHierarchy,
    movement: LocationMovement
};
```

### Auto-init

If `window.masterData.data` is already present when the script runs, `init()` is called automatically. Errors are logged, not thrown.

## 16. Known deferrals

1. **Household reconciliation on place delete.** `deletePlace` does not clear `household.locationId` for households at a deleted place. `HouseholdCommands` has no location-aware cleanup primitive. `householdReconciliation: 'deferred'` is returned in the result envelope. To close: add `HouseholdCommands.removeAllReferencesTo(locationId)` and dispatch it from `deletePlace`.

2. **`location-view-models.js` uses `window.TimeQueries`.** Phantom module. Two lines need replacing: `window.TimeQueries ? window.TimeQueries.getCurrentYear() : null` → `window.getCurrentYearSafe()`. See Patch list.

3. **`location-docs.txt` not yet deleted.** Delete after `location-doc.md` is committed.

4. **`location-hierarchy.js` loads before `location-queries.js` in some HTML files.** The load order listed in section 2 is the correct one. Verify per HTML file.

5. **Cross-domain events have no subscribers yet.** `placeDeleted`, `moveRecorded`, etc. fire, but no household or government module listens. Add subscribers when those domains want to react.

---

## 17. Anti-patterns

Do NOT:

- Call `saveMasterData()` outside `LocationCommands.persist()`.
- Call `LocationState._addPlace` / `_removePlace` / `_addLocationType` / `_removeLocationType` outside `LocationCommands`.
- Mutate a record returned by `LocationState.getPlaceById` — it is a clone. Mutate through commands.
- Read `masterData.data.places` or `.locationTypes` directly. Use `LocationState` accessors.
- Add a dependency on `window.TimeQueries` — it does not exist. Use `window.getCurrentYearSafe` / `window.calculateAge`.
- Add a dependency on `CharacterQueries.getAgeAt` — it does not exist. Use `window.calculateAge(birthYear, isDeceased, deathYear, year)`.
- Add ASCII glyphs (`'v'`, `'>'`, `''`) as UI icons. Route through `_getIcon`.
- Write to `character.moves` directly. Route through `LocationCommands.recordMove` → `CharacterCommands.updateCharacterFields`.
- Fabricate display defaults (like `'(unnamed)'`) in the domain layer. Do it in `LocationViewModels`.
