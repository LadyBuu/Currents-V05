## 1. Ownership contract

The Government domain owns exactly three canonical arrays on `masterData.data`:

| Array | Shape | Owner |
|---|---|---|
| `governmentDepartments` | `[{ id, name, description, locationId, parentDepartmentId, positions[], assignments[], isDeprecated, createdAt, updatedAt }]` | Government |
| `governmentTypes` | `[{ id, name, description, allowedRankIds[], icon }]` | Government |
| `governmentHistory` | `[{ id, locationId, characterId?, governmentTypeId?, governmentStyle?, eventType, startYear?, endYear?, title?, recordedAt }]` | Government |

Government **does not** own:

| Data | Owner | Read via | Written via |
|---|---|---|---|
| Leader terms (`place.leaders[]`) | Location | `LocationQueries.getCurrentLeader` etc. | `LocationCommands.assignLeader` / `endLeaderTerm` |
| Place government assignment (`place.governmentTypeId`, `place.governmentStyle`) | Location | `LocationQueries.getPlaceSummary` | `LocationCommands.assignGovernment` |
| Character professions / skill levels | Character | `CharacterQueries.getCharacterFacts` | `CharacterCommands.addProfession` |
| Civil law, justice severity, watch | Settlement | `SettlementLawQueries`, `SettlementGovernmentCommands` | `SettlementLawCommands`, `SettlementGovernmentCommands.setJusticeSeverity` / `setWatch` |
| Household wealth | Household | `HouseholdQueries.getCharacterHousehold` | `HouseholdCommands.adjustWealth` / `creditWealth` |
| Industry tax rate, tax revenue, enterprise stats | Settlement / Industry | `SettlementQueries.getIndustryTaxRate`, `IndustryQueries.getIndustryTaxRevenue` / `getIndustryEnterpriseStats` | — |

Cross-domain **writes** go through the owning domain's commands. Cross-domain **reads** go through the owning domain's queries. Government code never writes into another domain's canonical arrays.

## 5. Commands — write semantics

### 5.1 Field allowlists

Every `update*` command validates its `updates` object against `C.ALLOWED_*_FIELDS`. Rejection paths:

- Unknown field → `"Field \"X\" is not updatable on <context>"` with code `VALIDATION`
- Cross-domain field → `"Field \"X\" is owned by <owner>; use <owner> instead"` with code `VALIDATION`

`C.DOMAIN_OWNED_FIELDS` maps cross-domain field names to their owning module.

### 5.2 Persistence

One `saveMasterData` call site in the domain: `GovernmentCommands.persist()`.

The commit tail does not save. Modals call `Commands.persist()` exactly once after each successful mutation. Multi-assignment batches (bulk) commit once and persist once.

If `persist()` returns `{success: false}`, the modal shows a warning toast and does not roll back — the in-memory state is consistent, only the disk write failed.

### 5.3 Cross-domain writes

Government commands delegate to the owning domain:

- `assignLeader` / `endLeaderTerm` / `assignGovernmentToPlace` → `LocationCommands.*`, wrapped by `_wrapLocationResult`
- `updateJusticeSeverity` / `updateWatch` → `SettlementGovernmentCommands.*`, wrapped by `_wrapSettlementResult`
- `assignCharacterToPosition` / `bulkAssignCharacters` → `CharacterCommands.addProfession` (only when the position requires a role the character lacks)
- `paySalaryForAssignment` → `HouseholdCommands.adjustWealth` / `creditWealth`

`_wrapLocationResult` normalises Location's `true`-or-throw contract into `{success, data}` / `{success: false, reason, code: 'LOCATION_FAILED'}`.

`_wrapSettlementResult` normalises Settlement's `{success, code, details}` into Government's contract.

### 5.4 Salary is out of the assignment transaction

`assignCharacterToPosition` and `bulkAssignCharacters` do **not** pay salary. Salary payment is a separate command, invoked explicitly by the caller:

```js
var result = Commands.assignCharacterToPosition(departmentId, positionId, characterId);
if (result.success) {
    Commands.persist();
    var salary = Commands.paySalaryForAssignment(departmentId, positionId, characterId);
    // salary = { paid: boolean, amount?, householdId?, reason? }
}
```

Rationale: salary depends on Household, which is a separate domain. Coupling the assignment transaction to Household's write path was the source of the old warn-once-skip behaviour. Splitting it makes the failure modes independent and lets the UI decide whether to show a salary toast.

### 5.5 CustomEvents

Every successful command fires one `window.CustomEvent` (from `C.EVENTS`):

| Event | Fired by |
|---|---|
| `governmentDepartmentCreated` | `createDepartment` |
| `governmentDepartmentUpdated` | `updateDepartment` |
| `governmentDepartmentDeleted` | `deleteDepartment` |
| `governmentPositionAdded` | `addPosition` |
| `governmentPositionUpdated` | `updatePosition` |
| `governmentPositionDeleted` | `deletePosition` |
| `governmentCharacterAssigned` | `assignCharacterToPosition`, `bulkAssignCharacters` |
| `governmentAssignmentEnded` | `endAssignment` |
| `governmentAssignmentRemoved` | `removeAssignment` |
| `governmentSalaryOverridden` | `updatePositionSalary` |
| `governmentTypeCreated` / `Updated` / `Deleted` | the three government type commands |
| `governmentLeaderAssigned` / `governmentLeaderTermEnded` | delegating commands |
| `governmentAssignedToPlace` | `assignGovernmentToPlace` |
| `governmentJusticeSeverityUpdated` / `governmentWatchUpdated` | delegating commands |

Cross-domain consumers subscribe to these instead of polling.

## 6. Anti-patterns

None of these appear in the refactored modules. Any reintroduction is a regression.

- `saveMasterData` inside `_commit`, inside any mutation primitive, or inside a modal
- `invalidateCache` / `invalidateAccessorCaches` calls anywhere
- `_processing*`, `_rendering`, `_openingModal`, `_processingModal` state flags
- `value || 0`, `value || 50`, `value || []`, `value || {}` for domain values
- `return 1250`, `: 1250` fallback returns
- `typeof window.X !== 'undefined' ? ... : []` for required dependencies
- `getOrCreate*` from a read path
- `if (result)` — all Command result checks are `if (!result.success)`
- Direct writes to Place, Settlement, Household, or Character canonical data from Government code
- Inline numbers for domain values (priority, skill, salary, age thresholds, gender strings)
- Inline enum strings for gender, event names, error codes — all come from `GovernmentConstants`
- Queries calling `GovernmentState._get*Canonical` (only Commands do)
- View models calling `GovernmentQueries`, `GovernmentState`, or `GovernmentCommands`
- UI renderers calling `GovernmentQueries`
- Modals calling `GovernmentState._add*` / `_update*` / `_remove*`
- `saveMasterData` in more than one function per domain

## 7. Known deferrals

1. **`LocationCommands` throw/boolean contract.** Not normalised at the source. Government normalises with `_wrapLocationResult`. If LocationCommands adopts the standard `{success, data}` contract, `_wrapLocationResult` collapses to a pass-through.

2. **`LocationQueries.getPlaceGovernmentSummary`.** `GovernmentQueries.getLocationGovernmentSummary` prefers it and falls back to a composition over `getPlaceSummary` + `getCurrentLeader` + `getDepartmentsByLocation`. Once Location exposes the summary method, the fallback branch is dead and can be removed.

3. **`IndustryQueries` is a hard dependency of `GovernmentQueries`.** Reads `getIndustryTaxRevenue` / `getIndustryEnterpriseStats` without fallback. If a build ships Government without Industry, either Industry must load first or those two reads need to move behind a flag.

4. **`SettlementQueries.getGovernmentSalaryBudget`.** Used by `getSalaryBudgetSufficiency`. If Settlement drops the method, the budget-sufficiency display in `openGovernmentSummaryModal` shows nothing (VM returns `sufficiency: null`). No crash.

5. **Legacy `openFinancialReportModal` / `openEfficiencyScoreModal`.** Both alias `openGovernmentSummaryModal`. Kept so old callers don't break. Delete once all callers migrate.

6. **`government-history` is append-only.** No update or delete command. Every leader assignment, leader end, and government assignment appends. If pruning is needed later, add a `pruneGovernmentHistory(locationId, beforeYear)` command.
