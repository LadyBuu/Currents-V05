## 1. Government → Settlement boundary (corrected)

The Government layer was built assuming some Settlement APIs whose names differed from what exists. Correction:

| What Government calls | What it actually resolves to |
|---|---|
| `SettlementGovernmentCommands.setJusticeSeverity(locationId, severity)` | `settlement-government-commands.js` — confirmed |
| `SettlementGovernmentCommands.setWatch(locationId, { hasWatch, watchSize })` | `settlement-government-commands.js` — confirmed; takes an **object**, not positional args |
| `SettlementLawCommands.addCivilLaw / updateCivilLaw / removeCivilLaw` | `settlement-law-commands.js` — confirmed |
| `SettlementLawQueries.getCivilLaws / getCivilLaw / getCivilLawCount / getCivilLawsByDomain / getCivilLawsBySeverity / getEnforcedCivilLaws / getCivilLawsByCrimeType / getEnforcedCivilLawsByCrimeType / getCivilLawStatistics` | `settlement-law-queries.js` — confirmed |
| `SettlementProsperityQueries.getProsperityValue(locationId)` | `settlement-prosperity-queries.js` — confirmed; returns **number**, not an object |
| `SettlementQueries.getGovernmentSalaryBudget(locationId)` | `settlement-queries.js` — confirmed |
| `SettlementQueries.getIndustryTaxRate(locationId)` | `settlement-queries.js` — confirmed |
| `SettlementQueries.getSettlementData(locationId)` | `settlement-queries.js` — confirmed |

**Removed assumptions (never existed):**
- `SettlementCommands.updateJusticeSeverity` — never existed; the command is `SettlementGovernmentCommands.setJusticeSeverity`
- `SettlementCommands.updateWatch` — same; `SettlementGovernmentCommands.setWatch`
- `SettlementQueries.getProsperity` — never existed; use `SettlementProsperityQueries.getProsperityValue`

## 5. Modals contract (updated)

`modals-core.js` now supports:

| Option | Signature | Notes |
|---|---|---|
| `onMount(root)` | receives modal element | called after DOM insertion; exceptions logged & contained |
| `onOpen(root)` | alias for `onMount` | kept for callers not yet migrated; `onMount` wins if both supplied |
| `onConfirm(root)` | receives modal element | return `false` to keep modal open; any other return (incl. `undefined`) closes it |
| `onCancel(root)` | same semantics as `onConfirm` | |

**Removed:** the previous `onConfirm()` (no args), which broke every refactored Government modal.

**`openPreviewModal`** continues to work — its `onConfirm` calls the option's `onConfirm` and `onUndo`. No behavioural change for existing callers.

## 6. `government-commands.js` — corrected delegations

The file now calls:

```js
// Justice (correct module + object signature)
_SettlementGovCmds.setJusticeSeverity(locationId, severity);
_SettlementGovCmds.setWatch(locationId, { hasWatch: !!hasWatch, watchSize: ... });

// Place government (correct method name)
_LocationCommands.assignGovernment(placeId, govTypeId, govStyle);

// Leader (unchanged, but wrapped)
_LocationCommands.assignLeader(placeId, characterId, startYear, title);
_LocationCommands.endLeaderTerm(placeId, characterId, endYear);
```

Two normalisation helpers were added:

- `_wrapLocationResult(result)` — turns Location's `true`/throw contract into `{success, data}` / `{success:false, reason, code:'LOCATION_FAILED'}`.
- `_wrapSettlementResult(result)` — turns Settlement's `{success, code, details}` into Government's `{success, data, reason, code}`.

## 10. Dependency direction (frozen)

```
Definitions / Constants
        ↓
Rules (pure)
        ↓
Queries (defensive projections; may compose other Queries)
        ↓
Commands (single transaction boundary; may delegate to owning Commands)
        ↓
Canonical data (masterData.data.*)
        ↓
State (indexes; rebuild + publish only)
        ↓
Persistence (saveMasterData)
```

Presentation path:
```
Canonical data → Queries → ViewModels → UI → DOM
```

Cross-domain rule (unchanged): a domain's Commands may call another domain's Commands (delegation), but a domain's State may not mutate another domain's canonical data.

## 11. Forbidden patterns (as of Session 2)

None of these appear in the refactored modules:

- `_processing*`, `_rendering`, `_openingModal`, `_processingModal`
- `return 1250`, `: 1250` in any fallback
- `value || 0`, `value || 50`, `value || []`, `value || {}` for domain values
- `|| 10` for priority where `0` is meaningful
- `getOrCreate*` from a read path
- `saveMasterData` inside a State mutation primitive
- `invalidateCache` / `invalidateAccessorCaches` inside a modal
- `document.getElementById` inside a modal for the modal's own DOM
- `setTimeout(..., 100)` in modal wiring
- `if (result)` — all Command result checks are `if (!result.success)`
- `typeof window.X !== 'undefined' ? ... : []` for required dependencies
- Direct writes to Place / Settlement / Household / Character canonical data from Government code

---

## 12. Result contract (frozen)

Every Government Command returns:

```js
// success
{ success: true, data: { ... } }

// failure
{ success: false, reason: string, code?: string }
```

No boolean/object hybrids. No `null` returns. Callers use `if (!result.success)`.

Exceptions to this contract are the *delegated* commands (`LocationCommands`, `SettlementCommands`), which are normalised by `_wrapLocationResult` / `_wrapSettlementResult` in `government-commands.js`. Where those modules decide to adopt the same contract, the wrappers can be simplified or removed.

## 13. Known remaining work (out of scope for Session 2)

1. **`CharacterQueries` → `LocationQueries` load order.** LocationQueries must load first. If your bootstrap doesn't guarantee that, CharacterQueries' fallback to `character.currentLocationId` degrades but does not throw.

2. **`LocationCommands` throw/boolean contract.** Not normalised at the source. Government handles it with `_wrapLocationResult`. If LocationCommands adopts the standard contract, drop the wrapper.

3. **`SettlementCommands` module name.** There is no `SettlementCommands` global; commands are namespaced per area (`SettlementGovernmentCommands`, `SettlementLawCommands`, `SettlementFiscalCommands`, `SettlementDebtCommands`, `SettlementRankCommands`, `SettlementFeatureCommands`, `SettlementWealthCommands`, `SettlementSpecializationCommands`). Update any code that references a monolithic `SettlementCommands`.

4. **`government-system.js` façade** still aliases `updateJusticeSeverity` / `updateWatch` — those now route to `GovernmentCommands.updateJusticeSeverity`, which delegates correctly. No change needed, but the alias names remain for legacy callers.

5. **`government-laws.js` compatibility façade** — should be deleted once callers migrate to `SettlementLawCommands` / `SettlementLawQueries` directly.

6. **`government-assignment.js`** — should be deleted once callers use `GovernmentQueries.getQualifiedCandidates` / `getSuccessionPlan` / `analyzeAssignmentHistory` and `GovernmentRules.checkPositionEligibility` directly.

7. **`GovernmentEconomy._SettlementQueries` require** — currently unused; can be removed.

## 15. What to run first

Load the app. The first error you see is the next thing to fix. Expected outcomes, in order of likelihood:

1. Missing `SettlementProsperityQueries` or another Settlement module — add to the load order.
2. `CharacterQueries: LocationQueries is required` — swap load order.
3. `CharacterQueries.getCharacterFacts is not a function` — confirm the Session 2 update to `character-queries.js` is loaded, not a cached copy.
4. No error, but Government modals render with null location names — confirms LocationQueries projections aren't being picked up. Check `getPlaceSummary` is exported.
5. `GovernmentEconomy` throws on `SettlementProsperityQueries.getProsperityValue` — either the module isn't loaded or prosperity is unavailable for the location.

Everything else is a data question, not an architecture question.
