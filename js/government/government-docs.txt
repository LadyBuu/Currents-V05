================================================================================
PART 1 — FILE INVENTORY AND LAYERS
================================================================================

The Government subsystem follows the same layer chain as Rank / Role /
Education / Relationship / Settlement. Files in a later layer may read
from an earlier layer; they may not read from a later layer. Cycles are
forbidden.

  CONSTANTS (no deps)
    js/systems/government/government-constants.js

  STATE (owns canonical indexes; reads masterData)
    js/systems/government/government-state.js

  RULES (pure policy; no state, no I/O)
    js/systems/government/government-rules.js

  QUERIES (read-only; composes canonical state + foreign-domain queries)
    js/systems/government/government-queries.js

  COMMANDS (mutates via State primitives; commit tail is explicit)
    js/systems/government/government-commands.js

  ECONOMY (pure salary calculations; reads via Queries)
    js/systems/government/government-economy.js

  BOOTSTRAP (load-time verification + namespace)
    js/systems/government/government-bootstrap.js

  VIEW MODELS (presentation shaping; consumes query projections)
    js/systems/government/government-view-models.js

  UI (DOM rendering; consumes view models)
    js/systems/government/government-ui-list.js

  MODALS (DOM + commands; batch persist per successful action)
    js/systems/government/modals-government.js
    js/systems/government/modals-government-departments.js
    js/systems/government/modals-government-positions.js
    js/systems/government/modals-government-assign.js
    js/systems/government/modals-government-economy.js

  SETTLEMENT-LAW FORMATTERS (presentation helpers for civil laws)
    js/systems/government/settlement-law-formatters.js

  DEPRECATED COMPATIBILITY FAÇADES (government-docs.txt §8 lists
  these as DELETED; the supplied batch still has them. See PART 7 §16.)
    js/systems/government/government-assignment.js
    js/systems/government/government-laws.js
    js/systems/government/government-system.js

PART 2 — DEPENDENCIES
================================================================================

Terminology:
  REQUIRED (load-time)  — a module-level guard throws if the
                          dependency is missing when this file loads.
  REQUIRED (call-time)  — a function throws or refuses if the
                          dependency is missing at call time; the
                          module loads without it.
  OPTIONAL              — the module checks and falls back when absent.

Cross-domain references are labeled with their subsystem:
  [core]        js/core/...
  [character]   js/character/...
  [location]    js/location/...
  [selectors]   js/selectors/...
  [settlement]  js/settlement/...
  [household]   js/households/...
  [industry]    js/industry/...    [UNVERIFIED]
  [roles]       js/roles/...       [UNVERIFIED]
  [religion]    js/religion/...    (consumed only by Settlement, not Government)

      window.logEvent            (via _log — typeof-guarded)

        (via _dispatch — typeof-guarded)

        atomic mode aborts if any plan fails; best-effort applies

================================================================================
PART 7 — KNOWN HAZARDS
================================================================================

 1. getCurrentYearSafe vs getCurrentYear.
    Government uses the DEPRECATED getCurrentYearSafe accessor
    throughout: government-state.js, government-commands.js,
    government-economy.js, government-queries.js,
    government-bootstrap.js, government-assignment.js (deprecated
    façade). The canonical accessor is getCurrentYear (see
    stillwaters-docs.txt, stillwaters-character-docs.txt,
    stillwaters-location-docs.txt, stillwaters-settlement-docs.txt).
    government-docs.txt §18 codifies getCurrentYearSafe for the
    Government domain specifically. Do not change Government's
    accessor without also updating §18 of the narrative doc;
    otherwise the doc and code diverge.

 2. window.PlaceQueries.
    Government reads window.LocationQueries.getPlaceSummary, not
    window.PlaceQueries. The settlement subsystem uses
    window.PlaceQueries. Both are read accessors for location
    data; both must exist. [UNVERIFIED]: the exact module that
    installs window.PlaceQueries (referenced by the settlement
    subsystem) is not in the supplied files. Government does NOT
    need window.PlaceQueries; it reads LocationQueries directly.

 3. window._getIcon, window._escapeHtml, window._showToast.
    These are helper re-exports from modals-core.js. Government
    code reads through them via typeof guards with local
    fallbacks. If modals-core.js changes its re-export shape,
    Government falls back to:
      window.Icons[name]            (icons)
      local _escapeHtml             (escapeHtml)
      window.showToast              (toast, second fallback)
      window.showToastMessage       (toast, third fallback)

 4. window.buildLocationDropdown.
    Used by modals-government.js and
    modals-government-departments.js. When absent, both modals
    fall back to a local implementation that reads
    LocationQueries.getPlaceSummaries. The local fallback appends
    an "Unknown Location" option (value "unknown"); the
    canonical helper may not. Do not remove the fallback without
    verifying the helper's option shape.

 5. window.buildIconOptions.
    Used by modals-government.js (add / edit government type).
    When absent, the modal iterates window.Icons keys directly.
    This is a UI-only helper, not a domain function.

 6. window.confirmDialog.
    Used by modals-government.js (delete government type),
    modals-government-departments.js (delete department), and
    modals-government-positions.js (delete position). The
    supplied modals require it and throw if it is missing —
    this is a hard call-time dependency of the modals, not a
    domain dependency. Load modals-core.js.

 7. government-state.js marker: markDataDirty is idempotent
    inside mutation primitives. The commit tail's
    markDataDirty call is additive, not duplicated in a way
    that matters. Do NOT add saveMasterData to the mutation
    primitives; the commit tail pattern (mark dirty in
    primitive, save in Commands.persist) is the contract.

 8. SettlementQueries load-time dependency without use.
    government-commands.js loads window.SettlementQueries and
    throws at load if it is missing, but does not actually call
    it in the supplied file. This is a dead load-time
    dependency. Removing it would tighten the load order; adding
    a use would be a functional change. Do not remove it without
    updating the load order in PART 4 G5.

 9. LocationQueries load-time dependency without use in
    government-economy.js.
    Same story as §8. government-economy.js loads
    window.LocationQueries and throws at load if it is missing,
    but does not call it in the supplied file.

10. GovernmentCommands's _SettlementQueries load-time check
    assumes the modern SettlementQueries module. If a build
    ships without Settlement, government-commands.js will not
    load. Government-docs.txt §21 lists SettlementQueries as
    required; if that changes, update the load order.

11. modals-government-positions.js delete-position message.
    The confirm message says "Deleting it will also remove all
    assignments. Continue?" but the command
    (Commands.deletePosition) refuses when active assignments
    exist. The message is misleading. The command's refusal
    comes first; the modal displays a toast on failure. This is
    a stale string, not a functional bug — either update the
    message to match the refusal, or add a cascade option to
    deletePosition (out of scope of the current refactor).
    [Follow-up item, not a blocker.]

12. government-commands.js settlement mutation methods.
    updateJusticeSeverity / updateWatch delegate to
    SettlementGovernmentCommands.setJusticeSeverity / setWatch.
    The Settlement commands write Settlement-owned fields
    (justiceSeverity / hasWatch / watchSize) via
    SettlementCommandCommit. Government does not persist
    directly after these delegations — it relies on the
    settlement commit. Do not add a second Commands.persist() in
    these two methods; the settlement commit already handles
    it.

13. government-state.js validateIntegrity is warn-only.
    It returns an array of warning strings and logs them via
    console.warn. Bootstrap calls it inside try/catch; a throw
    from validateIntegrity indicates a bug in State, not in
    the canonical data. Referential issues (dangling parent,
    assignment pointing to missing position, end-before-start)
    are warnings only.

14. government-queries.js _charFacts helper.
    The helper is declared but the supplied file does not call
    it in any of the exported query methods. It is dead code
    today. Removing it is safe; leaving it is not a functional
    bug.

15. Settlement-law-formatters.js ownership.
    The file lives under js/systems/government/ but its name
    and purpose describe settlement-law display. It has no
    Government-module dependency and no dependency on
    GovernmentConstants. Its name/label tables are its own
    copies (LAW_TYPE_NAMES / LAW_DOMAIN_NAMES /
    LAW_CATEGORY_NAMES / LAW_SEVERITY_NAMES). The canonical
    source for these enums is SettlementLawDefinitions
    (js/settlement/settlement-law-definitions.js). A future
    cleanup should either:
      (a) move this file into js/settlement/, and
      (b) derive its tables from SettlementLawDefinitions, OR
      (c) accept the duplication as intentional
          display-only fallback.
    Do not change the label tables without also updating
    settlement-law-formatters.js's header or
    SettlementLawDefinitions.

16. Deleted files still present in the tree.
    government-docs.txt §8 lists these as DELETED:
      js/systems/government/government-system.js
      js/systems/government/government-assignment.js
      js/systems/government/government-laws.js
      js/systems/government/government-docs.txt
    They were provided in this batch (except the docs file),
    but the batch is not the current tree. Remove them from
    any HTML that still references them:
      - government-system.js throws at load
        (missing State.invalidateCache /
         State.refreshFromMasterData).
      - government-laws.js throws at load
        (missing window.SettlementCommands).
      - government-assignment.js is a compatibility façade
        whose exports (isCharacterQualifiedForPosition,
        getQualifiedCandidates, getSuccessionPlan,
        analyzeAssignmentHistory) have been superseded by
        GovernmentQueries.getQualifiedCandidates /
        getSuccessionPlan / analyzeAssignmentHistory.

17. Legacy modal aliases.
    openFinancialReportModal and openEfficiencyScoreModal are
    aliases for openGovernmentSummaryModal. Both are kept in
    modals-government-economy.js so old callers do not break.
    Delete them once every caller migrates. See
    government-docs.txt §7 Known deferrals point 5.

18. IndustryQueries hard dependency.
    government-queries.js throws at load if
    window.IndustryQueries is missing. Only two of its methods
    (getIndustryTaxRevenue / getIndustryEnterpriseStats) are
    called, and both are typeof-guarded at call time. If a build
    ships Government without Industry, either load a stub with
    those two methods or hoist the IndustryQueries dependency
    out of the module guard (see government-docs.txt §7 Known
    deferrals point 3).

19. RoleQueries and IndustryQueries are not in the supplied
    batch.
    Both are hard load-time dependencies of government-queries.js.
    [UNVERIFIED]: the exact implementations and their own
    prerequisites. Confirm they are loaded before
    government-queries.js in your build.

20. LocationCommands throw/boolean contract.
    LocationCommands.assignLeader / endLeaderTerm /
    assignGovernment may return `true` on success or throw on
    failure. GovernmentCommands._wrapLocationResult normalises
    both shapes into { success, data | reason, code }. If
    LocationCommands adopts the standard { success, data } shape
    in the future, _wrapLocationResult collapses to a
    pass-through. See government-docs.txt §7 Known deferrals
    point 1.

21. Settings on Commands.persist.
    persist() inspects the boolean return from
    saveMasterData() and reports
    { success: false, reason: 'save returned false', code:
    C.CODES.SAVE_FAILED } on false. It does NOT throw. Callers
    (every modal via _commitAndPersist) log a warning toast but
    do not roll back. In-memory state is consistent; only the
    disk write failed. This matches the settlement pattern
    (stillwaters-settlement-docs.txt PART 7 §10) except that
    Government does not throw on persist failure — different
    from SettlementCommandCommit. Do not "fix" Government's
    persist to throw without also updating every caller's
    error-handling expectation.

22. CustomEvent dispatch.
    Every successful GovernmentCommands call fires one
    window.CustomEvent (from C.EVENTS). Subscribers in other
    domains read these events. Do not suppress the dispatch,
    and do not add new events without updating C.EVENTS.
    Cross-domain consumers subscribe instead of polling.

23. Type-check pattern.
    Government code uses `if (!result.success)` for command
    results. It does NOT use `if (!result)` or `if (result)`.
    The command result contract is { success: boolean, ... }.
    A truthiness check would misfire on
    { success: false, reason } which is truthy as an object.

24. No fallback fabricated values.
    The audit rule from government-docs.txt §6 anti-patterns
    applies: no `value || 0`, `value || 50`, `value || []`,
    `value || {}`, no `return 1250`, no
    `typeof window.X !== 'undefined' ? ... : []` for required
    dependencies. The supplied code respects this. Any
    reintroduction is a regression.

25. Domain-owned fields are refused.
    government-commands.js's _validateFieldAllowlist rejects
    updates containing cross-domain field names (from
    C.DOMAIN_OWNED_FIELDS) with a message that names the owning
    module. The refusal path is:

      "Field \"X\" is owned by <owner>; use <owner> instead"

    Callers that expect to set, e.g., `characterName` on an
    assignment, will receive a validation failure. Use the
    owning domain's commands.

26. Salary payment is out of the assignment transaction.
    GovernmentCommands.assignCharacterToPosition and
    bulkAssignCharacters do NOT pay salary. The caller (modal
    or a dedicated salary flow) calls
    paySalaryForAssignment explicitly after a successful
    assignment. See government-docs.txt §5.4. Do not "fix" by
    adding salary payment inside the assignment command; that
    couples Government to Household's write path and breaks
    the independent failure modes the split exists to preserve.

27. modals-government-*.js call Commands.persist() exactly once
    per successful action.
    Adding a second persist() call would produce two
    saveMasterData() calls for a single logical mutation. The
    pattern is: command → _commitAndPersist → toast → close.
    Do not add persist() inside individual command bodies; the
    only saveMasterData call site is Commands.persist.
