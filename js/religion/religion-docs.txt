================================================================================
PART 1 — FILE INVENTORY AND LAYERS
================================================================================

The religion subsystem follows the same layer chain as the reference
subsystems (Rank / Role / Education / Relationship / Settlement /
Government):

  CONSTANTS (no deps)
    js/religion/religion-constants.js

  FORMAT (display-name lookups; depends on Constants)
    js/religion/religion-format.js

  VALIDATION (pure structural validation; depends on Constants +
              canonical law enums at CALL time)
    js/religion/religion-validation.js

  STATE (owns canonical store reference + derived indexes)
    js/religion/religion-state.js

  QUERIES (read-only; composes State + cross-domain accessors)
    js/religion/religion-queries.js

  RULES (pure policy; depends on Constants + Queries at CALL time)
    js/religion/religion-rules.js

  COMMANDS (writes via State primitives; the only persist site)
    js/religion/religion-commands.js

  LAWS (query-only surface for law records; commands moved to
        Commands)
    js/religion/religion-laws.js

  INHERITANCE (thin adapter: rules → commands)
    js/religion/religion-inheritance.js

  VIEW MODELS (presentation shaping; consumes queries + format)
    js/religion/religion-view-models.js

  RENDER (pure DOM rendering; consumes view models)
    js/religion/religion-render.js

  UI STATE (session-only selection/filter state)
    js/religion/religion-ui-state.js

  BOOTSTRAP (load-time verification + namespace)
    js/religion/religion-bootstrap.js

  MODALS (DOM + commands; save ownership per success)
    js/religion/modals-religion.js

Terminology:
  REQUIRED (load-time)  — a module-level guard throws if the
                          dependency is missing when this file loads.
  REQUIRED (call-time)  — a function throws or refuses if the
                          dependency is missing at call time.
  OPTIONAL              — module checks and falls back.

Cross-domain references are labeled:
  [core]        js/core/...
  [character]   js/character/...
  [location]    js/location/...
  [selectors]   js/selectors/...
  [settlement]  js/settlement/...
  [crime]       js/crime/...       (only for law enums)
  [government]  js/systems/government/...
  [UNVERIFIED]  referenced but not in the supplied batch

================================================================================
PART 7 — KNOWN HAZARDS
================================================================================

  1. getCurrentYear vs getCurrentYearSafe.
     Religion uses getCurrentYear throughout. Government uses
     getCurrentYearSafe (deprecated). Do not substitute. Religion
     bootstrap verifies getCurrentYear explicitly and does NOT
     verify the deprecated alias. See religion-docs.txt §0.

  2. LAW ENUM SOURCE.
     religion-commands.js::_readLawEnums and
     religion-validation.js::_readLawEnums read the canonical
     namespaced source (SettlementLawDefinitions.*,
     CrimeConstants.CRIME_TYPES). They do NOT read flat window.LAW_*
     globals, which do not exist in the current tree. Prior
     revisions did, and validation silently rejected every value
     because the enum was {}. Do not reintroduce flat globals. See
     religion-docs.txt §0 LAW ENUM SOURCE.

  3. PERSIST PATTERN.
     religion-commands.js::persist() inspects the boolean return
     from saveMasterData() and reports failure via
     getLastSaveError(). No Pattern C (discard boolean, report
     success). See PERSISTENCE TRUTH in the module header.

  4. MODAL CLOSE CONTRACT.
     modals-religion.js's onConfirm handlers RETURN the boolean
     from _handleCommandResult. Do not call closeTopModal() inside
     the success path — that caused a double-close (and a latent
     spurious onCancel fire) in prior revisions. See
     ONCONFIRM / ONCANCEL CONTRACT.

  5. CALLBACK ORDERING.
     onSuccess fires BEFORE the modal closes. This lets chained
     navigation (details → edit) reopen without the modal stack
     flashing empty. Do not reorder.

  6. CHARACTER PROJECTIONS.
     religion-queries.js returns character-domain projections, not
     live records. Mutating the returned object does NOT affect
     canonical state. For live records (authorized mutation only),
     use CharacterState.getLiveCharacterForMutation — religion
     queries never do.

  7. getFollowers returns [] for unknown religion id, not null.
     Only getReligion(id) returns null for unknown id. Do not
     conflate "unknown religion" with "religion with zero
     followers."

  8. _resolveCurrentLocationId.
     religion-queries.js prefers LocationQueries.getCurrentLocationId
     (semantic, move-aware). Falls back to
     CharacterQueries.getCurrentLocationId (raw field) for bare
     harnesses. Do not call window.getCurrentLocationId directly
     from religion code — the name is overloaded.

  9. isCulturallyCompatible / isReligiouslyPermitted stubs.
     Both fail closed (false with a reason). Do not treat the
     boolean as definitive.

  10. Bootstrap warn-only.
     CharacterQueries and PlaceQueries are WARN-ONLY for
     religion-bootstrap.js. religion-commands.js uses accessors,
     not the namespace. religion-queries.js and modals-religion.js
     DO require CharacterQueries — they enforce it at their own
     load. Do not add a hard guard in the bootstrap for these
     modules; the current warn-only posture preserves the reduced-
     harness case.

  11. Government-law formatter duplication.
     js/systems/government/settlement-law-formatters.js has its own
     law label tables (LAW_TYPE_NAMES, LAW_DOMAIN_NAMES,
     LAW_SEVERITY_NAMES). ReligionFormat has its own copies
     (LAW_TYPE_NAMES, LAW_CATEGORY_NAMES, LAW_DOMAIN_NAMES,
     LAW_SEVERITY_NAMES). The canonical source for the enums is
     SettlementLawDefinitions. A future cleanup should derive both
     label tables from there.

  12. Modal navigation setTimeout(100).
     modals-religion.js uses setTimeout(100) between close and
     open for details-modal navigation buttons (edit, set leader,
     add god, add law, create place, deprecate, delete). This is a
     documented deferral for a z-index/transition race. Do not
     remove without testing the modal stack under the target
     browsers.

  13. Character religion writes.
     All religion writes to character.religionId /
     character.religionHistory route through
     CharacterCommands.setReligion. Do not write those fields
     directly from religion code. That was the silent-data-loss
     bug fixed in the previous revision (see
     character-commands.js::setReligion).

  14. Children-commands + religion-inheritance integration.
     children-commands.js calls religion inheritance via
     CharacterCommands.assignCharacterReligion, which routes
     through ReligionCommands. That chain is CALL-TIME and
     typeof-guarded. religion-inheritance.js is the sanctioned
     entry for inheritReligionForChild; children-commands may
     call it directly or via ReligionCommands, but it must NOT
     write character.religionId itself.

  15. Set religion on a deceased character.
     ReligionCommands.assignReligionToCharacter does not check
     isDeceased. ReligionRules.canAssignReligion does not check
     isDeceased either. The caller is responsible for the
     deceased check. The modals do check
     (openAssignCharacterReligionModal fetches the character
     first; if the caller wants a hard check, add it to Rules).

  16. ReligionBootstrap idempotence.
     init() is idempotent. Repeat invocation re-hydrates indexes
     but skips verification (verification is load-time only).
     Do not add runtime verification to init() without also
     documenting the cost.

  17. window.Religion.modals may be null.
     religion-bootstrap.js captures window.ReligionModals at
     init time. If modals-religion.js loads AFTER
     religion-bootstrap.js, window.Religion.modals will be null.
     Either load modals BEFORE bootstrap, or reach into
     window.ReligionModals directly (it is a separate global).

  18. renderReligionList WeakSet-bound containers.
     religion-render.js::bindReligionListEvents guards against
     double-binding with a WeakSet. Re-rendering a container does
     not require re-binding. A caller that wants to rebind must
     create a new container.

  19. refreshReligionList per-container timer.
     Uses a WeakMap of timers, with a fallback keyed by a non-
     enumerable property per container. A container that is not
     extensible falls back to a non-unique 'default' key —
     refresh will still work, just with possible collision. This
     is a pathological case (frozen DOM node) and preferable to
     throwing.

  20. lawCategory is NOT a field on the law record the religion
      module writes. The current religion-commands.js writes
      `lawCategory` on the law (openAddLawModal passes
      `lawCategory: ...`). If a downstream consumer expects a
      different field name (e.g. category), coordinate the
      change. The religion-side canonical field is
      lawCategory — religion-view-models.js and religion-laws.js
      both read `law.lawCategory`.
