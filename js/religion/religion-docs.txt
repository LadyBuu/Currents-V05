# 1. SYSTEM OVERVIEW

## Purpose

The Religion System manages all religious aspects of the game world, including:

- **Religion Management** - Create, edit, delete, and deprecate religions
- **Religious Leadership** - Appoint leaders with full term history
- **Gods & Pantheons** - Create and manage deities with domains and attributes
- **Religious Laws** - Define laws, taboos, and guidelines (ready for Crime System)
- **Places of Worship** - Manage temples, churches, shrines with clergy and tithes
- **Religious Schools** - Create religious educational institutions
- **Character Assignment** - Assign religions to characters with conversion history
- **Religious Inheritance** - Children inherit religion from parents (configurable)
- **Location Integration** - Religions can be associated with locations
- **Settlement Integration** - Places of worship affect prosperity and unity

## Key Principles

| Principle | Description |
|-----------|-------------|
| **Single Source of Truth** | `religion-state.js` holds all religion data |
| **Command-Query Separation** | Commands (writes) vs Queries (reads) separated |
| **Separation of Concerns** | State, commands, queries, laws, inheritance, UI all separate |
| **Recursion Guards** | All public functions protected from infinite loops |
| **Change Notifications** | Subscriptions for reactive updates |
| **No Emojis** | All icons from `icons.js` via `_getIcon()` |
| **Law Definition Only** | Laws are definitions - enforcement is handled by Crime System |
| **Configurable Inheritance** | Each religion defines its own inheritance rules |
| **Parallel Legal Systems** | Religious laws operate independently from civil laws |

## State Structure

```javascript
_state = {
    religions: [],              // All religion objects
    subscribers: [],            // Change listeners
    _initialized: false,
    _processingState: false
};

_cache = {
    byId: new Map(),            // religionId → religion
    byTrait: new Map(),         // trait → [religions]

# 8. RELIGION-INHERITANCE.JS

## Purpose

Child religion inheritance logic. Determines which religion a child inherits based on:

- Mother's religion
- Father's religion
- Location's dominant religion
- Religion's inheritance rules (configurable per religion)

## Dependencies

| Module | Functions Used |
|--------|----------------|
| `religion-state.js` | `ReligionState` |
| `religion-queries.js` | `ReligionQueries` |
| `accessors.js` | `getCharacterById` |

## Inheritance Flow

```
1. Get mother and father characters
2. Get their religions
3. If one parent has no religion, check location's dominant religion
4. If both parents have religions, apply inheritance rules:
   a. If both religions have same rule type, follow it
   b. If different rules, prioritize mother's rule (tiebreaker)
   c. Check for NONE rule - if either says NONE, use other or location
5. Return the inherited religion or null
```

## Key Functions

| Function | Parameters | Returns | Description |
|----------|------------|---------|-------------|
| `getInheritedReligion(childId, motherId, fatherId, locationId)` | string, string, string, string | Object\|null | Gets inherited religion |
| `inheritReligionForChild(childId, motherId, fatherId, locationId, options)` | string, string, string, string, Object | Object | Assigns inherited religion |
| `getInheritanceRuleName(ruleType)` | string | string | Gets display name |
| `getInheritanceSource(motherId, fatherId, inheritedReligionId)` | string, string, string | string | Gets inheritance source |
| `getInheritanceDescription(religionId)` | string | string | Gets description |
| `getInheritanceSummary(religionId)` | string | Object | Gets summary |
| `getInheritanceStatistics(religionId)` | string | Object | Gets stats |
| `getAllInheritanceSummaries()` | None | Array | Gets all summaries |

# 13. CRIME SYSTEM INTEGRATION (DESIGN)

## Overview

The Crime System will integrate with the Religion System by:

1. **Checking religious laws** when a crime is recorded
2. **Tracking religious violations** separately from civil violations
3. **Applying religious consequences** (excommunication, etc.)
4. **Generating statistics** for religious crimes

## Architecture

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    CRIME SYSTEM INTEGRATION                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌─────────────────────────┐    ┌─────────────────────────┐                │
│  │  RELIGION SYSTEM        │    │  GOVERNMENT SYSTEM      │                │
│  │  (Religious Laws)       │    │  (Civil Laws)           │                │
│  └─────────────────────────┘    └─────────────────────────┘                │
│           │                              │                                  │
│           └──────────────┬───────────────┘                                  │
│                          ▼                                                  │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │                    CRIME SYSTEM                                     │   │
│  │  (Enforcement Layer)                                               │   │
│  │                                                                     │   │
│  │  1. getApplicableLaws(characterId, action, domain)                │   │

│  │                                                                     │   │
│  │  3. recordCrime(data)                                            │   │
│  │     ├── Record civil violation (if any)                          │   │
│  │     ├── Record religious violation (if any)                     │   │

│  │                                                                     │   │
│  └─────────────────────────────────────────────────────────────────────┘   │

## Data Flow: When a Crime Occurs

```
1. User triggers an action (murder, theft, heresy, etc.)
   ↓
2. Crime System records the crime
   ↓
3. Crime System gets character's location
   └── Gets civil laws from settlement
   ↓
4. Crime System gets character's religion
   └── Gets religious laws from religion
   ↓
5. Crime System checks if action violates any law
   ├── Civil violation → record in crime.civilViolation
   ├── Religious violation → record in crime.religiousViolation
   └── Both violations → record both
   ↓
6. If religious violation found:
   ├── Apply religious punishment (excommunication, etc.)
   └── Record in crime statistics
   ↓
7. Update affected systems:
   ├── Character (reputation, status)
   ├── Household (prestige, criminal count)
   ├── Settlement (crime rate)
   └── Religion (follower standing)
```

```javascript
function getApplicableLaws(characterId, action, context) {
    var character = getCharacterById(characterId);
    var locationId = getCurrentLocationId(character);
    var religionId = character ? character.religionId : null;
    
    var applicableLaws = [];
    var settlement = getSettlementData(locationId);
    
    // 1. Get civil laws from settlement
    var civilLaws = getCivilLaws(locationId);
    applicableLaws = applicableLaws.concat(civilLaws);
    
    // 2. Get religious laws from character's religion
    if (religionId) {
        var religiousLaws = ReligionLaws.getLawsByReligion(religionId);
        applicableLaws = applicableLaws.concat(religiousLaws);
    }
    
    // 3. Apply supremacy rules (theocracy)
    if (settlement && settlement.governmentType === 'theocracy') {
        // For theocracies, mark religious laws as supreme
        // Crime system should prioritize religious laws
    }
    
    // 4. Filter by domain if provided
    if (action && action.domain) {
        applicableLaws = applicableLaws.filter(function(law) {
            return law.domain === action.domain;
        });
    }
    
    return applicableLaws;
}

function checkLawViolation(characterId, action, context) {
    var laws = getApplicableLaws(characterId, action, context);
    var violations = [];
    
    for (var i = 0; i < laws.length; i++) {
        var law = laws[i];
        // Check if action violates this law
        // (custom logic per law type)
        if (violatesLaw(action, law, context)) {
            violations.push(law);
        }
    }
    
    return violations;
}
```

## Parallel Legal Systems

The design supports **parallel legal systems** where:

| Scenario | Religious Law | Civil Law | Result |
|----------|---------------|-----------|--------|
| Secular settlement | Applies to followers only | Applies to all residents | Both systems parallel |
| Theocracy | Applies to all residents | Empty (not used) | Religious law only |
| Established Church | Applies to followers + state religion | Applies to all residents | Both systems, but state religion has influence |
| Independent Courts | Religious court | Civil court | One action can trigger both violations |

This creates emergent drama - a character could be **executed by religious law** (legal in that system) but the **executor committed a civil crime** (illegal in civil system).

## Creating a Religion

```javascript
var result = window.ReligionCommands.createReligion({
    name: 'The Old Gods',
    displayName: 'The Old Gods of the North',
    description: 'Ancient religion of the northern tribes',
    trait: 'polytheistic',
    isOrganized: true,
    allowsConversion: true,
    proselytizes: false,
    inheritanceRule: {
        type: 'father'
    },
    icon: '✦'
});

if (result.success) {
    console.log('Created religion:', result.data.name);
}
```
