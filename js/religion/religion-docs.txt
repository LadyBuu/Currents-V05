## 1. Ownership Contract

The religion subsystem is split into fourteen modules, each with a
single layer of responsibility. The rule is the same as the
rank/role/relationship/education reference set: **every module owns
exactly one thing, and everything else is out of scope.**

| Module | Owns | Does NOT own |
|---|---|---|
| `ReligionConstants` | Frozen vocabulary (traits, inheritance rules, worship types, conversion reasons, default templates) | Display names, validation, state |
| `ReligionFormat` | Display names for every religion enum (trait, inheritance rule, worship type, conversion reason, law type/category/domain/severity) | Colors, icons, CSS classes |
| `ReligionValidation` | Structural validation (enum membership, required fields, type checks, year integer-ness); resolves law enums from the canonical namespaced source | Domain rules (eligibility), orchestration, mutation |
| `ReligionState` | Derived indexes, mutation primitives, subscriptions; canonical array ownership via slice-and-reassign | Canonical data ownership, persistence, query semantics, mutation policy |
| `ReligionQueries` | Semantic reads, analytics, cross-domain composition; returns character-domain projections for follower reads | Mutation, rendering, presentation defaults |
| `ReligionRules` | Pure policy ("can X happen?"), inheritance algorithm | Validation, orchestration, mutation, persistence |
| `ReligionCommands` | Write boundary, validation orchestration, rule orchestration, transaction commit, truthful `persist()` | Canonical data ownership, cross-domain side effects, presentation |
| `ReligionLaws` | Law queries, crime-mapping queries, law statistics | Law mutation (moved to Commands in Phase 7) |
| `ReligionInheritance` | Thin adapter: fetch facts → call Rules → call Commands for assignment; provenance observer | The inheritance algorithm, the assignment mutation, display names |
| `ReligionViewModels` | Presentation-ready projections (row shapes, detail models, sorting) | DOM, event handlers, queries, canonical reads |
| `ReligionRender` | DOM rendering for lists, cards, tables; delegated event binding; per-container refresh scheduling | Domain logic, field resolution, icon policy for chrome icons |
| `ReligionUIState` | UI-only state (selected religion, filters, view mode, expanded cards) | Canonical data, queries, commands |
| `ReligionBootstrap` | Load-time verification, index hydration, `window.Religion` namespace | Mutation, persistence, UI wiring |
| `modals-religion.js` | Modal forms for religion CRUD + leadership + gods + laws + places; save ownership via `ReligionCommands.persist()` | Validation, defaults, field resolution, mutation |

### The cross-cutting rules

**Commands own mutation.** Nothing outside `ReligionCommands` may call
`ReligionState._addReligion`, `_updateReligion`, or `_removeReligion`.
If another subsystem needs to write religion data, it must go through
a command.

**Commands own persistence.** `ReligionCommands.persist()` is the only
call site for `window.saveMasterData` in the religion subsystem.
Nothing else saves. The modal (or the caller) calls `persist()` once
per successful command batch. `persist()` inspects the boolean return
of `saveMasterData()` and reports failure via `getLastSaveError()`
(Pattern A in `storage.js`'s DOMAIN PERSIST CONTRACT). A failed save
is a returned `{ success: false, reason }`, never a silent success.

**Queries own reads.** Every read goes through `ReligionQueries`. No
module reads `masterData.data.religions` directly except `ReligionState`
(for indexing) and `ReligionQueries` (for enumeration).
`ReligionViewModels` and `ReligionRender` never read canonical data at
all.

**Rules and validation are pure.** `ReligionRules` and
`ReligionValidation` have no side effects, no persistence, no
randomness. Given the same facts and candidate, they return the same
verdict.

**Live records are for commands only.** `ReligionState._getReligionCanonical(id)`,
`_getGodCanonical(id)`, and `_getLawCanonical(id)` return live objects.
Only `ReligionCommands` may call them. Everything else uses
`ReligionQueries.getReligion(id)`, which returns a clone.

**One exception to the clone rule: character records.**
`ReligionQueries.getFollowers*` returns **character-domain
projections** — the same defensive copy that
`window.getCharacterById` returns under the documented load order
(character-queries.js's projection-returning override). They are
NOT the live canonical records. Callers can:

  - read any projection field safely
  - mutate the returned object without affecting canonical state
    (the projection is a copy)

Callers MUST NOT:

  - expect mutations to the returned object to persist (they do not)
  - expect the projection to reflect mutations made by other code
    after the query returned (it does not; re-call the query)

Callers that genuinely need a live reference (authorized mutation
code) must use `CharacterState.getLiveCharacterForMutation(id)`
directly. The religion domain never does; it does not own character
state and must not reach into the canonical record. Character
mutations belong to `CharacterCommands.setReligion`, which the
religion commands route through.

**No fallbacks.** Missing dependencies throw at load time (bootstrap)
or at call time (individual module `_require*` helpers). No module
silently substitutes a default for a missing capability. A missing
enum source is reported as an error naming the source, not coerced
into `{}` (which would make every value look invalid).

**One exception to the "no fallbacks" rule: UI fallbacks for
optional chrome.** `selector-base.js::getGenderSymbol` (used by the
character selector modal) falls back to a plain-text label when
`icons.js` is not loaded. The fallback produces a functional UI, not
a domain decision. Documented where it exists; no other module uses
this pattern.

### Core-compatibility rules

The religion subsystem relies on the canonical core helpers. The
following patterns are prohibited. Each was present in a pre-3.1
revision and was removed by a compatibility pass.

**Time:**

    PROHIBITED:  window.getCurrentYearSafe()
    CANONICAL:   window.getCurrentYear()

Files affected by prior passes:
    religion-bootstrap.js   (REQUIRED_GLOBALS verification)
    religion-queries.js     (_getCurrentYear helper)
    religion-commands.js    (_getCurrentYear helper)
    modals-religion.js      (_getCurrentYear helper)

**UI helpers:**

    PROHIBITED:  window._escapeHtml(), window._showToast(), window._getIcon()
    CANONICAL:   window.escapeHtml(), window.showToast(), window.getIcon()

Files affected:
    religion-render.js      (helper fallback removed)
    modals-religion.js      (helper guards + inline calls)

**Modal infrastructure:**

`js/core/modals-core.js` exposes `window.openModal`,
`window.closeTopModal`, and reads the option keys `titleHtml` /
`contentHtml`. It calls `onMount(root)` after DOM insertion and
`onConfirm(root)` on confirm. `window.openModal` returns
`{ element, close }`.

    PROHIBITED:  passing `title:` or `content:` to openModal
    PROHIBITED:  reading `result.content` from openModal
    PROHIBITED:  using `onOpen:` as the mount hook
    PROHIBITED:  inspecting `document.querySelector('.modal-body')`
                 to find the modal's own content
    PROHIBITED:  calling closeTopModal() from within onConfirm and
                 also returning truthy (double close)
    CANONICAL:   titleHtml:, contentHtml:, onMount:, onConfirm:
    CANONICAL:   result.element
    CANONICAL:   onMount(root) — root is the modal element
    CANONICAL:   return true/false from onConfirm; let modals-core
                 handle the close

The keys `title` and `content` are silently ignored by the core. A
modal that passes those renders with the default title ("Modal") and
an empty body.

Files affected:
    modals-religion.js      (all 11 modal call sites; onConfirm
                             return values)

**Law enum source:**

    PROHIBITED:  reading window.LAW_TYPES / window.LAW_CATEGORIES /
                 window.LAW_DOMAINS / window.LAW_SEVERITY /
                 window.CRIME_TYPES (flat globals — do not exist)
    CANONICAL:   window.SettlementLawDefinitions.LAW_TYPES /
                 .LAW_CATEGORIES / .LAW_DOMAINS / .LAW_SEVERITIES
    CANONICAL:   window.CrimeConstants.CRIME_TYPES

Files affected:
    religion-commands.js    (_readLawEnums helper)
    religion-validation.js  (validateLawInput; accepts options.enums)
    modals-religion.js      (openAddLawModal; reads via
                             ReligionCommands.getLawEnums)

**Canonical array ownership:**

    PROHIBITED:  masterData.data.religions.push(...) / .splice(...)
                 (mutating the live array in place)
    CANONICAL:   assign masterData.data.religions to a new array
                 (slice of the current array, then mutate the copy)

Files affected:
    religion-state.js       (_addReligion / _updateReligion /
                             _removeReligion build a working copy,
                             then reassign)

**File location:**

    PROHIBITED:  js/core/religion/<file>
    CANONICAL:   js/religion/<file>
