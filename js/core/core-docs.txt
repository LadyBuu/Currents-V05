# PART 1 — DOCUMENTATION

## 1. Overview

Still Waters is a browser-based simulation application. It is organized as a set of ES5-style IIFE modules that attach functions/objects to `window`. There is no bundler and no module system in the provided files; every module is a plain script that mutates `window` on load.

Architectural conventions that hold across the codebase:

- **Single Source of Truth (SSOT)** headers. Every non-trivial file declares SCOPE, OUT OF SCOPE, SEMANTIC RULES, DEPENDENCIES, and ICON POLICY.
- **Explicit missing vs. invalid.** `undefined`/`null` means "missing" → documented default. Wrong type / out-of-domain means "invalid" → throw or return `null`/`false`, never silently normalized.
- **No emojis, no icons in logic files.** Icons are SVG strings in `icons.js` only.
- **Required dependencies fail loudly.** Missing `window.X` throws at call time (or load time for some modules).
- **Missing data is not a dependency failure.** A missing collection returns `[]`; a missing entity returns `null`.
- **Mutation boundaries invalidate caches.** `accessors.js` builds ID maps; mutation modules call `invalidateAccessorCaches()`.
- **Persistence is debounced and truthful.** `markDataDirty()` schedules a save; `saveMasterData()` returns a boolean that reflects whether the write actually succeeded.

### 2.1 Core — storage and schema

#### `storage-schema.js`
- **Location:** `js/core/storage-schema.js`
- **Scope:** canonical shape of the persisted `masterData` envelope; current-schema normalization; default factory.
- **Exports:** `createDefaultMasterDataOverride`, `normalizeMasterData`, `STORAGE_SCHEMA_VERSION` (currently `3`).
- **Dependencies (required):** `time.js` — `TIME_CONSTANTS.DEFAULT_YEAR`, `.MIN_YEAR`, `.MAX_YEAR`.
- **Contracts:**
  - Normalization **mutates** the supplied envelope's `data` in place; does not deep-clone.
  - `SCHEMA_VERSION` identifies the **envelope** shape; migration is `database.js`'s job.
  - Top-level arrays declared: `characters, places, ranks, roles, locationTypes, governmentTypes, governments, households, householdPositions, householdAssignments, enterprises, enterpriseTypes, residences, disasters, eventLog, educationalInstitutions, parentChildEdges, pregnancyRecords, surrogacyArrangements, adoptionRecords`.
  - Top-level objects declared: `nameLists, cityNameParts, rankInheritanceRules, educationalSubjects, subjectProgress, settlementData`.
  - Scalar: `currentYear`.
  - Opt-in markers `_legacyEnvelopeLess`, `_yearCoerced`, `_preservedUnknownTopLevel` are preserved if set by the caller, never added.
  - Rank records have **no** `locationId`. Parentage fields (`motherId`, `fatherId`, `children`, `adoptedParents`, `adoptedChildren`) are **not** normalized.

#### `storage.js`
- **Location:** `js/core/storage.js`
- **Scope:** localStorage read/write, cross-tab sync, load/save/reload/reset, import, debounced save.
- **Exports:** `STORAGE_CONFIG`, `createDefaultMasterData`, `loadMasterData`, `reloadMasterData`, `forceReloadData` (deprecated), `saveMasterData`, `saveMasterDataOrThrow`, `scheduleSave`, `flushPendingSave`, `markDataDirty`, `hasUnsavedChanges`, `getLastSaveError`, `importData`, `resetMasterData`, `initializeStorage`.
- **Dependencies (required):** `time.js` (`TIME_CONSTANTS.DEFAULT_YEAR`), `storage-schema.js` (`createDefaultMasterDataOverride`, `normalizeMasterData`, `STORAGE_SCHEMA_VERSION`).
- **Optional:** `accessors.js` (`invalidateAccessorCaches`, used at cross-tab reload/import/reset), `validation.js` (`validateImportData`, required for import).
- **Contracts:**
  - `loadMasterData()` returns `{ ok, source?, error?, warnings? }`. Failure leaves `window.masterData` untouched.
  - `saveMasterData()` returns `true` **only** on a real write.
  - `markDataDirty()` is the single persistence trigger.
  - Cross-tab reload invalidates accessor caches **before** dispatching `masterDataUpdated`.
  - Envelope markers are stripped from the serialized form.
  - **Domain persist contract:** Pattern A (`saveMasterData() === true`) or Pattern B (`saveMasterDataOrThrow()`); Pattern C (discard return value) is broken and must not be reintroduced.

- **Contracts:**

- **Location:** `js/modules/simulation/simulation-generators.js`

- **Contract:** `'other'` is **not** canonical gender (removed; it was silently collapsed to `'unknown'`).

#### `character-traits.js`
- **Location:** `js/core/constants/character-traits.js`
- **Exports:** `CHARACTER_TRAITS` (frozen map), `CHARACTER_TRAIT_VALUES` (ordered id list), `CHARACTER_TRAIT_LOOKUP` (frozen null-proto membership map), `isKnownTrait`, `getTraitDefinition`, `getTraitIds`. CommonJS export for tests.

- **Location:** `js/core/constants/location-constants.js`
- **Exports:** `LOCATION_LEVELS` (1:country, 2:region/district, 3:county/duchy, 4:town/village, 5:locality/compound).

- **Location:** `js/core/constants/relationship-constants.js`

### 2.10 Core — world queries

#### `world.js`
- **Location:** `js/core/world.js`
- **Scope:** pure read-only location queries.
- **Exports:** `getLocationTypePriority`, `getPlacePriority`, `getLocationTypeScope`, `getPlaceScope`, `getChildPlaces`, `getTopLevelPlaces`, `getPlacesByPriority`, `getPlacesByScope`, `getParentChain`, `isAncestorOf`, `getLocationCountry`, `getLocationDistrict`, `getCountryPlaces`, `getCountryIdForPlace`, `getCharacterCountryId`, `getCharacterCountry`, `getCurrentLocationId`, `getCurrentPlace`, `getCharacterLocationPath`, `getCharactersGroupedByLocation`, `getLocationPopulationCount`.
- **Dependencies (required):** `accessors.js` (`getPlaces`, `getPlaceById`, `getLocationTypeById`, `getCharacters`), `time.js` (`isValidYear`).
- **Contracts:**
  - `getCurrentLocationId` may return a dangling ID; `getCurrentPlace` returns `null` in that case.

### 2.11 Core — naming

#### `names.js`
- **Location:** `js/core/names.js`
- **Scope:** character/city/region/landmark names, dynasty names, regnal numbering, epithets.
- **Exports:** `getRandomNameFromCountry`, `getRandomSurnameFromCountry`, `generateRandomFullName`, `getCharacterSurnameRules`, `getCharacterEpithet`, `getCharacterSurnameSource`, `generateDynastyName`, `formatDynastyName`, `generateCityName`, `generateRegionName`, `generateLandmarkName`, `formatTitleName`, `generateEpithet`, `formatRegnalName`, `getNextRegnalNumber`.
- **Dependencies (required):** `randomness.js` (`pickRandom`, `random`, `randomBoolean`), `accessors.js` (`getNameLists`, `getCityNameParts`), and **a** provider of `getCharacterById` — `character-queries.js` **or** `accessors.js` **or** the `character-system.js` shim (whichever loads last; all three return the fields read: `surnameRules`, `epithet`, `surnameSource`).
- **Contracts:**
  - Missing `countryId` → `null` for character-name lookups; place generators fall back to a generic name.
  - `formatTitleName` produces ordinal for 1 ("King Henry I"); `formatRegnalName` does **not** (first ruler is plain "Henry").
  - `window.normalizeName` was removed (storage-boundary concern).

## 3. Cross-cutting contracts (consolidated)

### 3.1 Persistence
- Only `storage.js` writes `localStorage['stillwaters_master']`.
- Domain mutations call `markDataDirty()` → debounced save.
- Domain `persist()` returns `{ success, reason? }` using `saveMasterData() === true` or `saveMasterDataOrThrow()`.
- `masterDataUpdated` CustomEvent fires on cross-tab reload **after** `invalidateAccessorCaches()`.

### 3.2 Accessor cache lifecycle
- Cache built lazily on first `getXById`.
- Self-heals on size mismatch with a one-shot warning per invalidation cycle.
- Mutation boundaries call `invalidateAccessorCaches()`.
- `settlementData` is not cached here; no invalidation needed for settlement writes.

### 3.3 Character projection vs. live entity
- `accessors.js::getCharacterById` returns the **live** cached entity.
- Under documented load order, `character-queries.js` (or the `character-system.js` shim) overwrites `window.getCharacterById` with a **projection**.
- Live entity access for mutation is `CharacterState.getLiveCharacterForMutation`.
- Projection consumers are enumerated in `accessors.js` header.

### 3.4 Validation vs. existence
- `validation.js` checks syntax/shape and semantics.
- `accessors.js::*Exists` and `getXById(...) !== null` check existence.
- `integrity.js` checks cross-entity references and repairs them (in memory).

### 3.5 Error-handling conventions
- Missing dependency → throw.
- Missing data → `null` / `[]` / `false` / documented default.
- Invalid explicit argument → throw or `null`/`false` per function contract (never silently normalized).
- Load-order mistakes throw; they are not a legitimate runtime state.

### 3.6 Time and years
- `TIME_CONSTANTS` owns year bounds and default year (1250).
- `getCurrentYear()` is the only current-year resolver; all else calls it.
- `isValidYear` in `time.js` and `validation.js` share the same bounds.

# PART 2 — LOAD ORDER

The order below is derived from: (a) explicit `DEPENDENCIES (REQUIRED)` sections, (b) runtime `window.X` lookups in code, and (c) the `state.js` `REQUIRED_MODULES` list. Where a file's header documents a *documented load order* (e.g. `character-queries.js` after `accessors.js`, `locationDropdown.js` after `world.js`), that is preserved. > **Reading the order:** each group may be loaded in the order shown. Within a group, order is significant unless explicitly noted. Files in a later group depend on files in earlier groups.

## 5. Load-order invariants (must-hold rules)

1. `time.js` before `storage-schema.js`, `storage.js`, `validation.js`, `world.js`, `simulation-generators.js`.
2. `storage-schema.js` before `storage.js`.
3. `storage.js` before any `accessors.js` use at runtime (accessors throws if `window.masterData` is absent).
4. `accessors.js` before `integrity.js`, `world.js`, `names.js`.
5. `collections.js` before `responsive.js` (debounce).
6. `ui.js` before `responsive.js` and `collapsible.js` (scroll-lock + `RESPONSIVE_BREAKPOINTS`).
7. `responsive.js` before `collapsible.js`.
8. All nine feature state modules before `state.js`.
9. `world.js` before `js/selectors/locationDropdown.js` (intentional shadowing).
10. Whichever of `character-queries.js` / `character-system.js` should win the `window.getCharacterById` race must load **last** among those two; `accessors.js` must load before either (it provides the underlying cache the projection reads).
11. `initializeStorage()` is called after `accessors.js` + `validation.js` are loaded, so cross-tab reload, import, and reset can invalidate caches and validate payloads.
12. `integrity.js` before `maintenance.js` at the time an audit is due (the "not due" path is dependency-free).

## 6. Known hazards

- **`LocationState` vs. `LocationUIState`.** `state.js` requires `LocationUIState` at `js/core/state/location-ui-state.js`. `js/location/location-state.js` is the **domain** module and is **not** a UI-state module. `state.js`'s error message distinguishes them explicitly.
- **`getCharacterById` race.** `accessors.js` exports the live-entity version; `character-queries.js` / the `character-system.js` shim overwrite it with the projection version. Do not "fix" this by removing the override; live access is opt-in via `CharacterState.getLiveCharacterForMutation`.
- **`getLocationCountry` / `getLocationDistrict` shadowing.** `locationDropdown.js` overwrites `world.js`'s exports with a superset. Runtime callers should assume the superset contract (place **or** id).
- **`DEATH_CAUSES` duplication.** `age-constants.js::DEATH_CAUSES` is a legacy flat list with no current consumers; `mortality-rules.js::DEFAULT_DEATH_CAUSES` is canonical. Do not conflate.
- **`FILTER_AGE_GROUPS` vs. `AGE_GROUPS`.** Intentionally different partitions; do not unify.
- **Envelope markers.** `_legacyEnvelopeLess`, `_yearCoerced`, `_preservedUnknownTopLevel` exist only in memory until the next save; `storage.js` strips them from the serialized form.
- **Persistence Pattern C.** `saveMasterData(); return { success: true };` is broken (discards return value). Use Pattern A or B.
- **`ui-state.js` fallback.** When localStorage throws, the store is in-memory only; `isPersistent()` reports this.
- **`state.js` deprecated globals.** `householdCurrentYear` throws if `time.js` is absent; `loadingOverlay` always returns `null`. Both warn once per process.
