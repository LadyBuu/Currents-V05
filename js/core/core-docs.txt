1. OVERVIEW
--------------------------------------------------------------------------------

Still Waters is a browser-based simulation application. It is organized as a
set of ES5-style IIFE modules that attach functions and objects to `window`.
There is no bundler and no module system. Every module is a plain <script>
that mutates `window` on load.

Architectural conventions that hold across the codebase:

  - Single Source of Truth (SSOT) headers. Every non-trivial file declares
    SCOPE, OUT OF SCOPE, SEMANTIC RULES, DEPENDENCIES, and ICON POLICY.

  - Explicit missing vs. invalid. undefined/null means "missing" and takes
    the documented default. Wrong type or out-of-domain means "invalid" and
    throws or returns null/false. Values are never silently normalized
    unless the function's contract says so.

  - No emojis and no icons in logic files. Icons are SVG strings in
    icons.js only.

  - Required dependencies fail loudly. Missing `window.X` throws at call
    time (or load time for some modules with guard blocks).

  - Missing data is not a dependency failure. A missing collection returns
    []; a missing entity returns null.

  - Mutation boundaries invalidate caches. accessors.js builds ID maps;
    mutation modules call invalidateAccessorCaches() after writing.

  - Persistence is debounced and truthful. markDataDirty() schedules a save;
    saveMasterData() returns a boolean that reflects whether the write
    actually succeeded. Never discard that return value.

  - Year resolution is centralized. time.js owns getCurrentYear(). No other
    module reimplements the fallback.

  - Parentage lives in parentChildEdges. The character record does NOT carry
    motherId, fatherId, children, adoptedParents, or adoptedChildren. These
    are removed fields. integrity.js and validation.js no longer audit or
    validate them.

  - Settlement data is keyed by locationId and is not an accessor cache. It
    is read directly from masterData.data.settlementData by SettlementQueries.
    Settlement writes do not require invalidateAccessorCaches().

  - The cached vs. projection accessor distinction. accessors.js's
    getCharacterById returns the LIVE cached entity. Under the documented
    load order, character-queries.js (or the character-system.js shim,
    whichever loads last) OVERWRITES window.getCharacterById with a
    projection-returning version. Callers reaching window.getCharacterById
    at runtime get a projection. Live entity access for mutation goes
    through CharacterState.getLiveCharacterForMutation.

storage-schema.js
  Location: js/core/storage-schema.js
  Scope: canonical shape of the persisted masterData envelope; current-schema
         normalization; default factory.
  Exports: createDefaultMasterDataOverride, normalizeMasterData,
           STORAGE_SCHEMA_VERSION (= 3).
  Dependencies (required): time.js — TIME_CONSTANTS.DEFAULT_YEAR, MIN_YEAR,
           MAX_YEAR.
  Contracts:
    - Normalization MUTATES the supplied envelope's data in place. No
      deep-clone.
    - SCHEMA_VERSION identifies the envelope shape; migration between schema
      versions is the migration layer's job.
    - Top-level arrays declared: characters, places, ranks, roles,
      locationTypes, governmentTypes, governments, households,
      householdPositions, householdAssignments, enterprises, enterpriseTypes,
      residences, disasters, eventLog, educationalInstitutions,
      parentChildEdges, pregnancyRecords, surrogacyArrangements,
      adoptionRecords.
    - Top-level objects declared: nameLists, cityNameParts,
      rankInheritanceRules, educationalSubjects, subjectProgress,
      settlementData.
    - Scalar: currentYear.
    - Opt-in markers (_legacyEnvelopeLess, _yearCoerced,
      _preservedUnknownTopLevel) are PRESERVED if set by the caller and NOT
      added on their own.
    - Rank records have NO locationId field. locationTypeId is the scope
      qualifier.
    - The character record carries a domain-owned traits array. Old saves
      without it receive `traits: []` on load via _ensureArrayField.
    - No automatic consistency check ties arrayKeys/objectKeys to the factory;
      keeping them in sync is the caller's responsibility until a declarative
      schema descriptor is introduced.

storage.js
  Location: js/core/storage.js
  Scope: localStorage read/write, cross-tab sync, load/save/reload/reset,
         import, debounced save.
  Exports: STORAGE_CONFIG, createDefaultMasterData, loadMasterData,
           reloadMasterData, forceReloadData (deprecated), saveMasterData,
           saveMasterDataOrThrow, scheduleSave, flushPendingSave,
           markDataDirty, hasUnsavedChanges, getLastSaveError, importData,
           resetMasterData, initializeStorage.
  Dependencies (required): time.js (TIME_CONSTANTS.DEFAULT_YEAR),
           storage-schema.js (createDefaultMasterDataOverride,
           normalizeMasterData, STORAGE_SCHEMA_VERSION).
  Dependencies (optional): accessors.js (invalidateAccessorCaches, used at
           cross-tab reload/import/reset), validation.js (validateImportData,
           required for import).
  Contracts:
    - loadMasterData() returns { ok, source?, error?, warnings? }. Failure
      leaves window.masterData untouched.
    - saveMasterData() returns true ONLY on a real write. It cancels any
      pending debounced save.
    - markDataDirty() is the single persistence trigger.
    - Cross-tab reload invalidates accessor caches BEFORE dispatching the
      masterDataUpdated CustomEvent.
    - Envelope markers are stripped from the serialized form by _performSave.
      The in-memory window.masterData keeps them so post-load inspection sees
      the load-time state.
    - Domain persist contract: Pattern A (saveMasterData() === true) or
      Pattern B (saveMasterDataOrThrow()). Pattern C (discard return value)
      is broken and must not be reintroduced.
    - Import requires validation.js to be loaded. If validateImportData is
      absent, import rejects the file rather than installing unvalidated data.

accessors.js
  Location: js/core/accessors.js
  Scope: raw collection accessors, ID-map caching, cache invalidation.
  Exports:
    Raw: getCharacters, getPlaces, getRanks, getRoles, getLocationTypes,
         getGovernmentTypes, getHouseholds, getResidences, getInheritanceRules,
         getNameLists, getCityNameParts, getDisasters, getEventLog.
    Cached lookups: getCharacterById, getPlaceById, getRankById, getRoleById,
         getLocationTypeById, getGovernmentTypeById, getHouseholdById.
    Existence: characterExists, placeExists, roleExists, rankExists,
         householdExists.
    Cache management: invalidateAccessorCaches, refreshCaches.
  Dependencies: storage.js (must have initialized window.masterData).
  Contracts:
    - ID maps index only non-empty string IDs; later duplicate wins.
    - getXById returns null for missing entity.
    - Cache self-heals via _ensureCacheInSync: size check vs. canonical
      array; warn once per invalidation cycle (throttled); rebuild on
      mismatch.
    - _ensureCacheInSync does NOT swallow rebuildFn throws. A missing
      masterData is a dependency failure, not a stale-cache case.
    - Cached accessors return LIVE entities. Under documented load order,
      character-queries.js (or the character-system.js shim) overwrites
      window.getCharacterById with a PROJECTION-returning version.
    - Concrete projection consumers listed in the header:
        names.js, education-queries.js, education-learning.js,
        education-commands.js, education-annual.js, apprenticeship-queries.js,
        apprenticeship-commands.js, professional-knowledge-cmds.js,
        modals-roles.js, modals-education.js, modals-apprenticeship.js,
        settlement-prosperity-queries.js (traits only).
    - settlementData is NOT indexed by any accessor cache. SettlementQueries
      reads it directly from masterData.
    - Rename-then-rename-back hazard: a mutation that renames an id A→B then
      back to A (net zero adds/removes) between two reads is size-equal and
      will not trigger a rebuild. The size check is a backstop, not a general
      staleness detector.
    - Only string IDs are indexed. Non-string/empty IDs are skipped by the
      cache builder, matching the public lookup contract exactly.

3. CROSS-CUTTING CONTRACTS (CONSOLIDATED)
--------------------------------------------------------------------------------

3.1 Persistence
  - Only storage.js writes localStorage['stillwaters_master'].
  - Domain mutations call markDataDirty() → debounced save.
  - Domain persist() returns { success, reason? } using
    saveMasterData() === true or saveMasterDataOrThrow().
  - masterDataUpdated CustomEvent fires on cross-tab reload AFTER
    invalidateAccessorCaches().

3.2 Accessor cache lifecycle
  - Cache built lazily on first getXById.
  - Self-heals on size mismatch with a one-shot warning per invalidation
    cycle.
  - Mutation boundaries call invalidateAccessorCaches().
  - settlementData is not cached here; no invalidation needed for settlement
    writes.
  - Rename-then-rename-back without invalidation is a mutation-boundary bug,
    not an accessors.js bug.

3.3 Character projection vs. live entity
  - accessors.js::getCharacterById returns the LIVE cached entity.
  - Under documented load order, character-queries.js (or the
    character-system.js shim) overwrites window.getCharacterById with a
    PROJECTION.
  - Live entity access for mutation is
    CharacterState.getLiveCharacterForMutation.
  - Projection consumers are enumerated in accessors.js header.

3.4 Validation vs. existence
  - validation.js checks syntax/shape and semantics.
  - accessors.js::*Exists and getXById(...) !== null check existence.
  - integrity.js checks cross-entity references and repairs them (in memory).

3.5 Error-handling conventions
  - Missing dependency → throw.
  - Missing data → null / [] / false / documented default.
  - Invalid explicit argument → throw or null/false per function contract
    (never silently normalized).
  - Load-order mistakes throw; they are not a legitimate runtime state.

3.6 Time and years
  - TIME_CONSTANTS owns year bounds and default year (1250).
  - getCurrentYear() is the only current-year resolver; all else calls it.
  - isValidYear in time.js and validation.js share the same bounds.

3.7 Parentage
  - Parentage lives in parentChildEdges (FamilyState).
  - The character record no longer carries motherId, fatherId, children,
    adoptedParents, or adoptedChildren.
  - integrity.js does not audit parent references on the character record.
  - validation.js does not validate them.
  - Imported records carrying them fail schema validation as "Unknown field".

3.8 Settlement data
  - masterData.data.settlementData is a top-level object keyed by locationId.
  - It is NOT indexed by any accessor cache in accessors.js.
  - No getSettlementData* accessor exists there. SettlementQueries reads it
    directly from masterData.
  - No cache invalidation is required after settlement writes.
  - The standard _buildIdMap contract (index by item.id) does NOT apply.

PART 5 — KNOWN HAZARDS
================================================================================

  - state.js module scope. The supplied state.js requires six modules and
    explicitly does not reference LocationUIState, MatchmakerState, or
    CensusState. If a deployed state.js differs, verify its REQUIRED_MODULES
    list against the modules actually loaded.

  - LocationState vs. LocationUIState. window.LocationState
    (js/location/location-state.js) is the domain module. It is NOT a UI
    state module and is NOT read by state.js. Older state.js revisions
    required LocationUIState at js/core/state/location-ui-state.js. The
    supplied state.js requires neither.

  - getCharacterById race. accessors.js exports the live-entity version;
    character-queries.js / the character-system.js shim overwrite it with the
    projection version. Do not "fix" this by removing the override; live
    access is opt-in via CharacterState.getLiveCharacterForMutation.

  - getLocationCountry / getLocationDistrict shadowing. locationDropdown.js
    overwrites world.js's exports with a superset. Runtime callers should
    assume the superset contract (place OR id).

  - DEATH_CAUSES duplication. age-constants.js::DEATH_CAUSES is a legacy
    flat list with no current consumers; mortality-rules.js::
    DEFAULT_DEATH_CAUSES is canonical. Do not conflate.

  - FILTER_AGE_GROUPS vs. AGE_GROUPS. Intentionally different partitions;
    do not unify.

  - Envelope markers. _legacyEnvelopeLess, _yearCoerced,
    _preservedUnknownTopLevel exist only in memory until the next save;
    storage.js strips them from the serialized form.

  - Persistence Pattern C. saveMasterData(); return { success: true }; is
    broken (discards return value). Use Pattern A or B.

  - ui-state.js fallback. When localStorage throws, the store is in-memory
    only; isPersistent() reports this.

  - state.js deprecated globals. householdCurrentYear throws if time.js is
    absent; loadingOverlay always returns null. Both warn once per process.

  - accessors.js size-based staleness check. Rename-then-rename-back without
    invalidating is size-equal and will not trigger a rebuild. That is a
    mutation-boundary bug, not an accessors.js bug.

  - parentChildEdges migration. Old saves and imports that still carry
    motherId/fatherId/children/adoptedParents/adoptedChildren on character
    records are not audited or validated by the supplied modules. Imported
    records fail validateEntitySchema as "Unknown field". Migration must move
    them to parentChildEdges before validation passes.

  - Missing modules. character-queries.js, character-state.js,
    character-system.js, household-state.js, role-state.js, rank-state.js,
    names-state.js, location-ui-state.js, and locationDropdown.js are
    referenced but not supplied. Their placement is dictated by the
    dependencies stated in the supplied headers and by state.js's
    REQUIRED_MODULES list.
